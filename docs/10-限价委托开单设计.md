# 10 - 限价委托开单设计

> **状态**：2026-09-14 方案稿（待拍板、待实施）
>
> **背景**：现行开仓唯一通道是"AI 分析落库 → 即时**市价**开仓"（[trade_engine.py:211](../backend/app/services/trade_engine.py)），AI 建议价只作闸门参考——现价偏离 AI 入场 >1% 直接作废（:139）。因此 AI 给出"回踩挂单入场"类建议时（如 VETUSDT 建议回踩 0.1629 企稳再进），系统不会真的挂单等待，交易直接流失。本方案引入**限价委托**：偏离带内的建议下限价单等待成交，成交后接入既有止损/止盈/结算状态机。
>
> **设计原则**：市价路径零改动（回归风险最小）；限价是**并列的新分支**，只复用既有闸门与成交后序列；DB 只加列不迁移；默认关闭，页面开关控制。

---

## 0. 拍板决策点（推荐值，可改）

| # | 决策 | 推荐 | 备选 |
|---|---|---|---|
| 1 | 分流规则 | 程序按偏离带自动分流：≤1% 市价、1%~3% 限价、>3% 作废 | AI 决策 schema 加 `order_type` 字段自主选择（P2） |
| 2 | 挂单时效 TTL | 24 小时 | 12h / 按K线根数 |
| 3 | 部分成交处理 | 撤单/过期时**市价平掉已成交部分**（保守，避免碎片仓位） | 保留为小仓位继续管理 |
| 4 | 默认开关 | 关（`limit_order_enabled`，策略配置页开启） | 默认开 |
| 5 | 裸仓窗口 | 巡检轮询 5 分钟（成交→发现→挂 SL 之间无止损） | user data stream 秒级感知（P2） |

## 1. 分流规则（`_attempt_open` 内新增分支）

现价复核（方向-价格一致性、≤1% 偏离、RR 复算）改造为三分支：

```
dev = |现价 − AI入场价| / AI入场价
patient_side = (direction == long  and 入场价 < 现价×(1−0.001))    # 多单挂在现价下方等回踩
             or (direction == short and 入场价 > 现价×(1+0.001))   # 空单挂在现价上方等反抽

dev ≤ 1%                       → 市价路径（现状不变，按现价复算 RR）
1% < dev ≤ 3% 且 patient_side  → 限价委托路径（按委托价复算 RR ≥1.5）
其余（反向侧 或 dev > 3%）      → 作废（现状）
```

- **patient_side 约束**：限价买入价高于现价会被交易所立即吃掉（等效市价+更差滑点），必须严格挂在"等待回踩/反抽"的一侧；breakout 类建议入场贴近现价，天然落市价路径。
- **RR 复核口径**：限价路径按**委托价**复算（委托价 = AI 入场价，分析时 risk_guard 已验过，此处等价复验）；市价路径维持按现价复算。

## 2. 限价委托路径（下单序列）

1. **前置闸门全部复用**：max_open_trades（含 PENDING 计数，见 §5）、可用余额 ≥70%（委托锁定保证金）、资金分层、同币唯一、trade_type 开关、强平闸门、交易所精度。
2. **下单**：GTC 限价单，`qty` 同现有固定亏损法；价格经 `round_price`（tickSize，[binance_trader.py:134](../backend/app/services/binance_trader.py) 已有）；新 trader 方法 `limit_order(symbol, side, qty, price)`（`type: "LIMIT"`, `timeInForce: "GTC"`）。
3. **落库**：`status='PENDING'`，`entry_price`=委托价（=AI 入场价）、`order_type='limit'`、`expires_at=now+LIMIT_ORDER_TTL_HOURS`、`raw.entry_order_id`=限价单 id（复用既有字段）、`ai_snapshot` 照常。
4. **事件**：`LIMIT_PLACED`。**不挂 SL/TP**——未成交无仓位可保护；Binance USDT-M 经典 API 无原生 bracket/OTO，SL 只能在成交后挂（§4）。

## 3. 挂单巡检任务 `manage_limit_orders`

- **调度**：beat 每 5 分钟（`crontab(minute="*/5")`），Redis 锁 `lock:limit_manage`（与结算锁 `lock:trade_open` 独立——两者操作对象不重叠）。
- **输入**：全部 `status='PENDING'` 的 trade_records（testnet/正式网按各自 client）。
- **逐单处理**（顺序：先查单，再决策）：

| 情形 | 判定 | 动作 |
|---|---|---|
| 已过期 | `now > expires_at` | 撤单 → CANCELLED（`exit_reason='limit_expired'`） |
| 完全成交 | order status `FILLED` | 成交后处理（§4）→ OPENED |
| 部分成交 | `PARTIALLY_FILLED` | 继续等待，`raw.qty_filled` 记录；仅在撤单/过期时平掉已成交部分 → CLOSED（`exit_reason='limit_partial'`） |
| 前提失效 | 未成交，多单现价 ≤ SL（止损区已到，入场前提死）/ 现价 ≥ TP1（已错过，不追）；空单对称 | 撤单 → CANCELLED（`exit_reason='limit_premise'`） |
| 外部撤销 | status `CANCELED`/`EXPIRED` | 对账 → CANCELLED |
| 继续等待 | 其余 | 不动作 |

- **撤单-成交竞态**：撤单返回 -2011（可能已成交）或撤后复查 FILLED → 一律按成交处理（§4），宁可开成不可开漏。
- **前提失效检查的开销**：每单一次 `price()` + 一次 `order()`，挂单数量级 ≤ max_open_trades(10)，5 分钟一轮完全可承受。

## 4. 成交后处理（复用市价路径的挂单序列）

1. 查实际成交均价/量（`order(symbol, order_id)` 的 `avgPrice`/`executedQty`，与市价路径的 fill 查询同源）。
2. **极端插针保护**：成交价已越过 SL（限价单在暴跌/暴涨中被动成交）→ 不挂 SL 直接市价平仓 → CLOSED（`exit_reason='sl'`）。规避 STOP_MARKET -2021 "would immediately trigger" 拒单。
3. 正常路径：挂 SL（STOP_MARKET closePosition）→ TP1 → TP2——**与 `_attempt_open` 现有保护块完全同一段代码**（抽成 `_attach_exit_orders(rec, fill_price, qty)` 共用），失败回滚 `cancel_all_algo` + reduceOnly 平仓同现状。
4. 更新：`entry_price`=实际成交均价、`qty`=实际成交量、状态 OPENED、事件 `LIMIT_FILLED`。此后既有状态机（TP1_HIT 保本、移动止损、结算）零改动接管。

## 5. 闸门与计数调整

| 闸门 | 调整 |
|---|---|
| max_open_trades | 计数 = OPENED/TP1_HIT/TP2_HIT + **PENDING**（委托锁定保证金，必须占名额） |
| 同币唯一 | **PENDING 也算**——挂单期间该币新分析不再开第二单（一个币一个计划） |
| TRADING_MIN_FREE_PCT | 不变（下委托前检查，交易所锁定保证金后自然反映在可用余额） |
| 开仓快筛（评分 ≥60、1h 内生成） | 不变（限价委托仍在分析落库瞬间放置） |

## 6. 与既有机制的交互

- **摘钩不删除**（重分析摘 `scan_result_id`）：PENDING 持有 `ai_snapshot` 快照，独立存活，不受摘钩影响。
- **结算巡检**（每小时 :10 `settle_trades`）：只处理 OPENED+，**不碰 PENDING**——职责分离，挂单生命周期完全归 §3 巡检。
- **复盘**（trade_reviews）：AI 建议回放与实际订单无关，不受影响。
- **A2 教训（SL 挂单巡检）**：PENDING → OPENED 转换后自动纳入既有 `_rehang_lost_sl` 巡检，无额外工作。

## 7. DB 变更（只加列，惯例不 DROP）

```sql
ALTER TABLE trade_records ADD COLUMN IF NOT EXISTS order_type VARCHAR(16) DEFAULT 'market';
ALTER TABLE trade_records ADD COLUMN IF NOT EXISTS expires_at TIMESTAMPTZ;
-- status 列为 VARCHAR(16) 无约束，新值 'PENDING' / 'CANCELLED' 直接可用，无迁移
-- 限价单 id 复用 raw.entry_order_id（该字段存的就是"入场委托单"的 id）
```

模型（`models/trade.py`）：加 `order_type`、`expires_at` 两列映射；`raw` 注释补充 `qty_filled`。

## 9. 前端变更

- `types/index.ts`：`TradeRecord.status` 加 `'PENDING' | 'CANCELLED'`；加 `order_type`、`expires_at` 字段。
- 交易记录页：状态标签（挂单中=processing 蓝 / 已撤销=default 灰）；PENDING 行展示委托价与到期时间；`exit_reason` 新值标签（limit_expired / limit_premise / limit_partial）。
- 事件流（trade_events）新类型：`LIMIT_PLACED / LIMIT_FILLED / LIMIT_CANCELLED / LIMIT_PARTIAL`——事件表已由 detail JSON 承载，后端写入即可，前端事件渲染按 type 文案映射。

## 10. 行为变化（须知）

| 变化 | 后果 |
|---|---|
| "回踩挂单"类建议真的挂出去了 | 建议落地率上升；此前 >1% 偏离直接流失的交易现在进入等待队列 |
| 在跑名额被挂单占用 | 挂单期间同币不再重复开仓、名额 -1；若市场单边不回踩，名额到期才释放（TTL 内资金效率下降） |
| 成交→发现→挂 SL 之间（≤5min）无止损 | 极端插针在窗口内穿越入场价时会先成交后触发插针保护（§4 第 2 步兜底）；P2 user stream 消除 |
| RR 复核口径分路径 | 限价按委托价（与分析一致）、市价按现价（更严）——同一建议两条路径的准入结果可能不同，属设计意图 |
| 委托锁定保证金 | 挂单期间可用余额下降，后续其他币开仓的 70% 余额闸门自然感知 |

## 11. 验证清单

1. **/tmp mock 套件**（monkeypatch trader，沿用 test_sl_anchor 风格）：
   - 分流：dev=0.9% 市价 / dev=2% 限价 / dev=4% 作废 / 反向侧限价→作废；
   - 放置：PENDING 落库字段（expires_at、raw.entry_order_id）、LIMIT_PLACED 事件、SL/TP 确未挂；
   - 成交：FILLED → SL/TP1/TP2 序列、entry_price=成交均价、OPENED；
   - 插针保护：成交价已越 SL → 直接平仓 CLOSED；
   - 撤销三路：TTL 过期 / 触 SL 前提失效 / 触 TP1 前提失效；
   - 部分成交：过期时平掉已成交部分 → CLOSED(limit_partial)；
   - 竞态：撤单 -2011 → 按成交处理；
   - 计数：PENDING 占 max_open_trades、同币 PENDING 挡新开仓；
   - 回归：市价路径既有套件（test_sl_anchor / test_tp_nearest / test_breakeven）全过。
2. **testnet 线上验收**：开启开关 → 找一个偏离 1%~3% 的建议挂单 → 确认交易所侧 GTC 单、状态 PENDING → 手动把价格打到位（或等回踩）→ 巡检轮内转 OPENED、SL/TP 挂出 → 之后结算状态机正常推进；另测 TTL 过期撤销路径。
3. **观察项**：挂单成交率、平均等待时长、前提失效撤销占比——为 TTL 与偏离带参数调优提供数据。

## 12. P2 展望（本期不做）

- **user data stream**（listenKey WebSocket，ORDER_TRADE_UPDATE）：成交秒级感知、SL 即挂，消除 5 分钟裸仓窗口；repo 已有 kline_hub 的 WebSocket 基建可复用。
- **AI 自主选择委托方式**：决策 schema 加 `order_type: market|limit` + `ttl_hours`，AI 按形态性格（追突破 vs 等回踩）自选，程序只校验边界。
- **追价改单**：挂单跟踪现价（如始终挂在现价回踩 0.5% 处），到期或成交止。
