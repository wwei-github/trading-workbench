>
> **背景**：现行开仓唯一通道是"AI 分析落库 → 即时**市价**开仓"（[trade_engine.py:211](../backend/app/services/trade_engine.py)），AI 建议价只作闸门参考——现价偏离 AI 入场 >1% 直接作废（:139）。因此 AI 给出"回踩挂单入场"类建议时（如 VETUSDT 建议回踩 0.1629 企稳再进），系统不会真的挂单等待，交易直接流失。本方案引入**限价委托**：偏离带内的建议下限价单等待成交，成交后接入既有止损/止盈/结算状态机。
>
> **设计原则**：市价路径零改动（回归风险最小）；限价是**并列的新分支**，只复用既有闸门与成交后序列；DB 只加列不迁移；默认开启，页面开关可关。

## 1. 委托方式路由（AI 返回即指令）

AI 决策 schema 新增 `order_type` 字段（`market` / `limit`，缺省 `market`——旧结论兼容）。`_attempt_open` 按其分流，**限价路径不做程序侧方向/偏离校验**：

```
order_type=market → 市价路径（现状不变，含现行 dev ≤1% 偏离闸门）
order_type=limit  → 直接挂 OTOCO（§2）；通用闸门（名额/余额/同币/精度）照常
```

- **为什么不需要程序校验**——限价单有三道天然保障：
  1. **价格保护**：限价买单成交价 ≤ 委托价、卖单 ≥ 委托价——成交永远不会比 AI 计划更差，SL/TP 固定 → 实际 RR 只会比计划更好（买单成交价越低 RR 越高）；
  2. **交易所几何校验**：SL/TP 触发价在现价错误一侧（会立即触发）→ 挂单被 -2021 "would immediately trigger" 拒收 → 作废记 skip 原因，几何荒谬的 AI 决策挂不出来；
  3. **TTL + 前提失效**兜住不成交的悬挂单（§3）。
- **AI 侧引导**（system prompt）：突破追入/动量延续类 → `market`；回踩企稳、反抽确认类（如 VETUSDT 回踩 0.1629 企稳再进）→ `limit`，挂单价 = entry。
- **RR 复核口径**：市价路径维持按现价复算（现行）；限价路径无开仓时 RR 复核（成交价 ≤ 委托价 = AI 入场价，分析时已验）。

## 2. 限价委托路径（下单序列）

1. **前置闸门全部复用**：max_open_trades（含 PENDING 计数，见 §5）、可用余额 ≥70%（委托锁定保证金）、资金分层、同币唯一、trade_type 开关、强平闸门、交易所精度、TP1 数量 min_qty 下单前预检（A1 教训：50% 数量 < min_qty 整单放弃）。
2. **下单 = OTOCO 一体单**（新 trader 方法 `limit_order_otoco`）：`POST /fapi/v1/algoOrder`，`algoType=OTOCO`——
   - **working 单**：LIMIT GTC，side=入场方向，price=委托价（=AI 入场价，经 `round_price` 取整），quantity=qty（固定亏损法，按委托价折算）；
   - **pending TP1**：TAKE_PROFIT_MARKET reduceOnly，triggerPrice=AI TP1，quantity=**working 的 50%**（AI 未给 TP2 时 75%）；
   - **pending SL**：STOP_MARKET，triggerPrice=AI 止损价，closePosition（不支持时全量 reduceOnly，testnet 确认）；
   - **入场单满额成交的瞬间交易所自动激活 TP1+SL**，无需等巡检；
   - 返回 OTOCO 父单 `algoId`。挂单被拒（-2021 = SL/TP 触发价在现价错误一侧，AI 几何与市况不符；-4120 精度）→ 与闸门失败同口径作废记 skip 原因。
3. **落库**：`status='PENDING'`，`entry_price`=委托价、`stop_loss`/`tp1`/`tp2`=AI 三价、`order_type='limit'`、`expires_at=now+12h`、`raw.entry_order_id`=OTOCO 父单 algoId（复用既有字段）、`ai_snapshot` 照常。
4. **事件**：`LIMIT_PLACED`。**TP2 此时不挂**（OTOCO 两个 pending 位已占满）——TP1 成交后由巡检补挂（§4）。

## 3. 限价单巡检（并入每小时 :10 结算任务，不新增定时任务）

- **位置**：`settle_trades`（`run_auto_trade_task`，每小时 :10）**开头新增 PENDING 处理块**——先处理挂单（查单/撤单/成交转 OPENED），再走既有 OPENED+ 结算循环；共用既有 Redis 锁 `lock:trade_open` 与"交易所为真相"口径。
- **输入**：全部 `status='PENDING'` 的 trade_records（testnet/正式网按各自 client）。
- **逐单处理**（顺序：先查单，再决策）：

| 情形 | 判定 | 动作 |
|---|---|---|
| 已过期 | `now > expires_at`（12h；小时粒度巡检 → 实际寿命 12~13h） | 撤 OTOCO 父单（`DELETE /fapi/v1/algoOrder`，[binance_trader.py:187](../backend/app/services/binance_trader.py) `cancel_order` 已有）→ CANCELLED（`exit_reason='limit_expired'`） |
| 完全成交 | OTOCO 状态 `FINISHED` 且仓位存在 | 成交后处理（§4）：把已激活的 TP1/SL 子单 algoId 写入 raw → OPENED（TP1/SL 已由交易所自动激活在场）→ 后续按原仓位管理逻辑 |
| 部分成交 | working 单部分成交 | **立即撤父单 + 市价平掉已成交部分** → CLOSED（`exit_reason='limit_partial'`）——SL 激活前部分仓位无止损，风险必须有界（发现延迟 ≤1h 为残余窗口） |
| 前提失效 | 未成交且现价已触及 TP1（多 ≥tp1 / 空 ≤tp1）——行情已走完，不追 | 撤父单 → CANCELLED（`exit_reason='limit_premise'`） |
| 外部撤销 | OTOCO 状态 `CANCELLED`/`EXPIRED`/`REJECTED` | 对账 → CANCELLED |
| 继续等待 | 其余（WORKING 无成交） | 不动作 |

- **"触 SL 前提失效"不成立，已删除**：耐心侧挂单（多单入场在现价下方）要触及止损价必须先穿越入场价 → 必已成交，SL 区到不了"未成交"状态（插针 gap 由成交 + SL 立即触发兜底）。唯一有意义的失效是"已错过"（价格先到 TP1）。
- **撤单-成交竞态**：撤单返回 -2011（可能已成交）或撤后复查已成交 → 一律按成交处理（§4），宁可开成不可开漏。
- **查单口径**：working 单在 `GET /fapi/v1/openAlgoOrders`（trader `open_algo_orders` 已有）；最终状态/成交明细查 `GET /fapi/v1/algoOrders?algoId=`。PENDING 期间 OTOCO 各部分在交易所侧的可见形态与子单 algoId 获取方式以 testnet 验证为准。
- **巡检粒度影响**：成交 → OPENED 转换延迟 ≤1h（期间 TP1/SL 已由交易所激活，无裸仓）；前提失效/过期撤销延迟 ≤1h。

## 4. 成交后处理（TP1/SL 已在场，巡检只做衔接）

1. 查实际成交均价/量（algo 单成交明细 avgPrice/executedQty，与市价路径 fill 查询同源）。
2. 把交易所自动激活的 TP1/SL 子单 algoId 写入 `raw.tp1_order_id`/`raw.sl_order_id`——此后既有结算逻辑（tp1_gone 事件推断、SL 补挂、保本移动）直接可用。
3. 更新：`entry_price`=实际成交均价、`qty`=实际成交量、状态 OPENED、事件 `LIMIT_FILLED`。
4. **TP1 成交后**（既有结算循环的 TP1_HIT 分支）：OCO 已自动撤销 SL → 保本 SL 由巡检**补挂**（`_replace_sl` 对不存在的旧单天然退化为直接挂新单，-4130 清理兜底）+ 设置 TP2（25%）→ 后续原移动止损逻辑（TP2_HIT 收紧、无 TP2 时跟进止损）零改动接管。
5. **极端插针兜底**：OTOCO 激活的 SL 若触发价已被越过会立即触发市价平仓（交易所自动，插针保护内建）；巡检兜底——发现成交价已越过 SL 而仓位仍存活（SL 激活异常）→ 立即市价平仓 → CLOSED（`exit_reason='sl'`）。

## 5. 闸门与计数调整

| 闸门 | 调整 |
|---|---|
| max_open_trades | 计数 = OPENED/TP1_HIT/TP2_HIT + **PENDING**（委托锁定保证金，必须占名额） |
| 同币唯一 | **PENDING 也算**——挂单期间该币新分析不再开第二单（一个币一个计划） |
| TRADING_MIN_FREE_PCT | 不变（下委托前检查，交易所锁定保证金后自然反映在可用余额） |
| 开仓快筛（评分 ≥60、1h 内生成） | 不变（限价委托仍在分析落库瞬间放置） |

## 6. 与既有机制的交互

- **摘钩不删除**（重分析摘 `scan_result_id`）：PENDING 持有 `ai_snapshot` 快照，独立存活，不受摘钩影响。
- **结算巡检**（每小时 :10 `settle_trades`）：**开头新增 PENDING 处理块**（§3），随后照常处理 OPENED+；同一任务同一锁，先挂单后持仓。
- **复盘**（trade_reviews）：AI 建议回放与实际订单无关，不受影响。
- **A2 教训（SL 挂单巡检）**：PENDING → OPENED 转换后自动纳入既有 `_rehang_lost_sl` 巡检，无额外工作。

## 12. P2 展望（本期不做）

- **user data stream**（listenKey WebSocket，ORDER_TRADE_UPDATE）：成交秒级感知 → TP1/TP2 即挂（小时巡检下 TP 延迟 ≤1h，此流将其降到秒级）；repo 已有 kline_hub 的 WebSocket 基建可复用。SL 已由 OTOCO 交易所侧解决，不依赖此流保命。
- **AI 自主选择委托方式**：决策 schema 加 `order_type: market|limit` + `ttl_hours`，AI 按形态性格（追突破 vs 等回踩）自选，程序只校验边界。
- **追价改单**：挂单跟踪现价（如始终挂在现价回踩 0.5% 处），到期或成交止。
