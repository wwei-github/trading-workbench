# 06 自动交易设计需求（AI 信号 → 币安实盘）

> 来源：2026-09-12 口述需求整理。状态：**待确认**（§12 列出需拍板的问题）。
> 定位：在现有「扫描 → AI 分析」链路末端增加自动下单执行层，并对每笔交易做全生命周期记录。

## 1. 目标与范围

- AI 分析给出 **suggest（可开单）且推荐度 ≥ 60** 的信号 → 自动在币安 USDT-M 合约下单（必须带止损、TP1、TP2）
- 每笔交易全程入库：开单信息（止损/止盈位、AI 分析结论、下单时间、单子状态）、操作历史、收益结果（正/负值）
- 每小时巡检在跑单子：识别止损/止盈成交、分批止盈、移动止损、结算收益
- 前端新增 **交易记录** Tab

**明确不在本期范围**：手动交易、现货、多策略并行、跟单。

## 2. 触发链路

```
每小时扫描（beat, minute=2）
  → AI 分析（前 AI_MAX_PER_SCAN 个，现有管线）
      → trade_decision == suggest 且 recommendation ≥ 60
          → 自动交易闸门（§3）
              → 币安下单（§5）→ 写 trade_records + trade_events
  → 每小时巡检任务（beat，与扫描错峰，建议 minute=42）
      → 对 RUNNING 状态的单子查币安持仓/挂单/成交
          → 更新状态、分批止盈、移动止损、结算收益
```

- 触发点在 AI 分析落库之后（复用现有 `run_ai_analysis_single` 尾部），每个 scan_result 只触发一次
- 巡检与扫描错峰：扫描 minute=2，AI 分析约 5~10 分钟完成，巡检建议 minute=42

## 3. 下单前置检查（全部通过才下单）

| # | 检查 | 不通过动作 |
|---|---|---|
| 1 | 全局开关 `TRADING_ENABLED`（环境变量）+ 币安 key/secret 已配置 | 跳过 |
| 2 | `recommendation ≥ TRADING_MIN_RECOMMENDATION`（默认 60） | 跳过 |
| 3 | 该 symbol 无在跑仓位（同币种不重复开） | 跳过 |
| 4 | 下单时重新校验方向-价格一致性：现价与 AI entry 偏移后，止损仍在正确一侧（多单止损仍在现价下方）；偏离过大（如 >1%）作废 | 作废并记录 |
| 5 | **余额风控（70% 规则）**：可用余额 ≥ 总资金 × 70%（§4.3） | 跳过 |
| 6 | 仓位计算合法（qty ≥ 交易所最小名义价值/精度步长，否则向上调整或放弃） | 调整/放弃并记录 |

## 4. 资金与仓位规则

### 4.1 风险基数分档（不把浮盈计算在内）

- 资金基数按账户余额（walletBalance，**不含未实现盈亏**）向下落到最近的档位：
  - 需求原话：「账户金额为 100 刀到 200 刀，则按 100 刀的 3%，也就是 3 刀来计算仓位」
  - 档位默认 `100 / 200 / 500 / 1000 / 2000 / 5000 / 10000`（环境变量可配，**待确认**）
  - 例：余额 150 → 基数 100；余额 730 → 基数 500

### 4.2 仓位计算（固定亏损法，与 Risk Guard 同源）

```
止损金额 = 风险基数 × 3%（TRADING_RISK_PCT，例：基数100 → 3 刀）
名义仓位 = 止损金额 ÷ 止损距离%（止损距离 = |entry - stop| / entry）
数量 qty = 名义仓位 ÷ 现价（按 symbol 的 stepSize 精度取整）
保证金 = 名义仓位 ÷ 杠杆（默认 TRADING_LEVERAGE=5，下单前对该 symbol 设杠杆）
```

- 止损越远仓位越小、触止损固定亏 3 刀（同现有 RISK_BUDGET_PCT 逻辑，只是基数从「3% 账户」改为「3% 分档基数」）

### 4.3 余额风控（70% 规则）

```
可用余额 = walletBalance（不含浮盈） − 在跑单子占用保证金
若 可用余额 < 总资金 × TRADING_MIN_FREE_PCT(0.7) → 不开单
```

- 需求原话：「刨除正在执行的单子金额，账户当前余额，不包含浮赢的金额，如果金额少于总仓位的 70%，则不开单」
- 口径按「保持 70% 资金空闲」理解：**在跑单占用不得超过账户总资金的 30%**（§12 待确认）

## 5. 订单结构（币安 USDT-M 合约，单向持仓）

| 订单 | 类型 | 数量 | 说明 |
|---|---|---|---|
| 入场 | MARKET | qty（100%） | 以现价市价进 |
| 止损 | STOP_MARKET（closePosition） | 全仓剩余 | 价格 = AI 止损价 |
| 止盈一 | TAKE_PROFIT_MARKET（reduceOnly） | **开仓仓位的 50%** | 价格 = AI TP1 |
| 止盈二 | TAKE_PROFIT_MARKET（reduceOnly） | **开仓仓位的 25%** | 价格 = AI TP2 |

- 进场后立即挂 SL/TP1/TP2 三单；任一挂单失败 → 市价平掉入场仓位并记录 ERROR（不留裸仓）
- 仓位分批：TP1 平 50%、TP2 平 25%，剩余 25% 由移动后的止损看护

## 6. 交易状态机

```
OPENED（已开仓，三单就绪）
  ├─ TP1 成交 → TP1_HIT（记录已实现盈亏 part1）
  │     ├─ TP2 成交 → TP2_HIT → **止损单改价为 TP1**（撤旧SL挂新SL，保本）
  │     │     ├─ SL(TP1价) 成交 → CLOSED（结算）
  │     │     └─ 人工/后续规则平仓 → CLOSED（结算）
  │     └─ SL 成交（未到TP2）→ CLOSED（结算）
  ├─ SL 成交（直接止损）→ CLOSED（结算）
  └─ 下单失败 / 挂单失败已平 → FAILED / CLOSED
```

每次状态迁移、撤单、改价、成交都写一条 `trade_events`（操作历史）。

## 7. 每小时巡检与结算

对每笔非终态（OPENED / TP1_HIT / TP2_HIT）交易：

1. 查 `positionRisk`（持仓）+ `openOrders`（挂单）+ 成交回报（userTrades / income REALIZED_PNL）
2. 判定本小时发生的事件：TP1/TP2/SL 成交 → 按状态机迁移、执行移动止损、写事件
3. **已止损或已止盈（仓位归零）→ 结算**：以币安 REALIZED_PNL 汇总本笔交易的收益，记**正/负值**（USDT）与相对止损金额的百分比，状态置 CLOSED，记录平仓时间
4. 交易所与本地不一致时（本地 RUNNING 但交易所无持仓无挂单）：以交易所为准补结算，写 WARN 事件

> 说明：巡检间隔 1 小时意味着事件最多延迟 1 小时入库；单子本身的风险控制（SL/TP 触发）由交易所挂单实时执行，不依赖巡检。

## 8. 数据模型

**trade_records（一单一行）**

| 字段 | 说明 |
|---|---|
| id, symbol, direction(long/short) | 基础 |
| scan_result_id, ai_analysis_id | 溯源到信号与 AI 分析 |
| entry_price, qty, notional, leverage, margin_used | 开仓 |
| stop_loss, tp1, tp2 | 三价（SL 移动后同步更新此字段，历史在 events） |
| status | OPENED / TP1_HIT / TP2_HIT / CLOSED / FAILED |
| opened_at, closed_at | 时间 |
| realized_pnl, pnl_pct | 结算收益（正/负值；pnl_pct 相对止损金额） |
| exit_reason | TP2后保本SL / SL / 人工 / 异常平仓 |
| raw | 币安订单 id、挂单 id 等原始信息 JSON |

**trade_events（操作历史，一事件一行）**：trade_record_id、event_type（OPEN / TP1_FILL / TP2_FILL / SL_MOVE / SL_FILL / CANCEL / ERROR / SETTLE）、detail JSON、created_at

## 9. 前端：交易记录 Tab

- 挂在 [ScanResult.tsx](../frontend/src/pages/ScanResult.tsx) 现有 Tabs 中（`trades`），位于「扫描结果」之后
- 表格列：币种、方向、状态（Tag：运行中/部分止盈/已止盈/已止损/失败）、开仓价、止损（现值）、TP1、TP2、数量、保证金、开仓时间、收益（正绿负红，含 USDT 值与 %）
- 展开行：操作历史时间线（trade_events）+ 对应 AI 分析结论（复用 AiExpandContent）
- 只读展示，不做手动平仓按钮（后续可加）

## 10. 配置项（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `BINANCE_TRADE_KEY` / `BINANCE_TRADE_SECRET` | 空 | 交易用 API 凭据（与行情共用域名 fapi.binance.com，签名 HMAC-SHA256） |
| `TRADING_ENABLED` | false | 自动交易总开关 |
| `TRADING_MIN_RECOMMENDATION` | 60 | 开单推荐度门槛 |
| `TRADING_RISK_PCT` | 3.0 | 止损金额占风险基数的比例（%） |
| `TRADING_CAPITAL_TIERS` | 100,200,500,1000,2000,5000,10000 | 风险基数分档 |
| `TRADING_MIN_FREE_PCT` | 0.7 | 可用余额 / 总资金 下限 |
| `TRADING_LEVERAGE` | 5 | 默认杠杆 |
| `TRADING_TESTNET` | false | 暂用 testnet 验证链路（建议首期先 true） |

## 11. 异常与边界

- **下单部分成交**：市价单全成或拒单；出现部分成交按实际成交量补挂 SL/TP，事件记录
- **同币种重复信号**：已有持仓跳过；24h 重复命中沿用 AI 结论的也不会重复下单（只对本次新建仓信号下单）
- **AI 分析通过但下单时币安报错**（精度/最小名义/保证金不足）：记 FAILED + 错误详情，不重试自动开单（避免连环市价单）
- **API 失效/网络**：下单前 balance 查询失败 → 本轮跳过；巡检失败 → 下小时重试（交易所挂单在场，风险不受影响）
- **服务重启**：以交易所为真源（持仓+挂单+成交）重建状态，本地只做展示与结算记账
- **精度**：qty 按 stepSize 向下取整、价格按 tickSize 取整；名义价值低于 symbol 最小值则放弃

## 12. 待确认问题

1. **风险基数分档**：只给了「100~200 按 100」一档，档位表（100/200/500/…）与「向下落档」规则是否符合预期？
2. **70% 规则口径**：「金额少于总仓位的 70%」——按「可用余额 < 账户总资金（不含浮盈）× 70% 则不开单」理解，即最多动用 30% 资金。是否正确？
3. **剩余 25% 仓位的退出**：TP2 成交、SL 移到 TP1 后，剩余 25% 若既不触发保本 SL 也没有后续移动规则，可能长期挂着的方案是什么？（候选：随趋势跟进止损 / 反向信号平仓 / 定时强平）
4. **杠杆与保证金模式**：默认 5×、全仓 or 逐仓？
5. **先 testnet 还是直接小额实盘**：建议 `TRADING_TESTNET=true` 跑通全链路后再切实盘。
6. **推荐度 60 门槛与现有 AI_MAX_PER_SCAN=10 的关系**：每小时最多 10 个 AI 分析，其中再筛 ≥60 分下单，是否还需同时限制「每小时最多自动开 N 单」？
