# 06 自动交易设计需求（AI 信号 → 币安实盘）

> 来源：2026-09-12 口述需求整理；同日六项待确认问题已拍板（§12）。
> 定位：在现有「扫描 → AI 分析」链路末端增加自动下单执行层，并对每笔交易做全生命周期记录。

## 1. 目标与范围

- AI 分析给出 **suggest（可开单）且推荐度 ≥ 60** 的信号 → 自动在币安 USDT-M 合约下单（必须带止损、TP1、TP2）
- 每笔交易全程入库：开单信息（止损/止盈位、AI 分析结论、下单时间、单子状态）、操作历史、收益结果（正/负值）
- 每小时任务：先结算在跑单子（识别止损/止盈、分批止盈、移动止损），再按评分优先开新单
- 前端新增 **交易记录** Tab

**明确不在本期范围**：手动交易、现货、多策略并行、跟单。

## 2. 触发链路

```
每小时扫描（beat, minute=2）
  → AI 分析（前 AI_MAX_PER_SCAN 个，现有管线，约 5~25 分钟）
      → trade_decision == suggest 且 recommendation ≥ 60 的分析结果入库（不开单）

每小时交易任务（beat, minute=42，先结算后开仓）
  ① 结算：对 OPENED/TP1_HIT/TP2_HIT 单子查币安 → 状态迁移/移动止损/结算收益
  ② 开仓：查「未交易的 suggest 且 ≥60 分且 1 小时内生成」的分析，按推荐度降序逐个尝试开仓
     直到 触发在跑单子上限（默认5，页面可改）或 余额风控拦截 或 候选耗尽
```

- **统一开单时点**（替代逐币即时下单）：AI 分析各子任务完成时间不一，批次结束后统一按评分排序开仓，天然实现「优先开分数高的单子」
- 手动单币重分析（force）产生的 ≥60 分结论同样进入开仓候选

## 3. 下单前置检查（全部通过才下单，按评分顺序逐个执行）

| # | 检查 | 不通过动作 |
|---|---|---|
| 1 | 全局开关 `TRADING_ENABLED` + 币安 key/secret 已配置 | 跳过本轮 |
| 2 | 在跑单子数 < `max_open_trades`（数据库配置，默认 5，页面可改） | 停止本轮开仓 |
| 3 | `recommendation ≥ TRADING_MIN_RECOMMENDATION`（默认 60） | 跳过该币 |
| 4 | 该 symbol 无在跑仓位（同币种不重复开） | 跳过该币 |
| 5 | 下单时重新校验方向-价格一致性：现价偏移后止损仍在正确一侧；偏离过大（>1%）作废 | 作废并记录 |
| 6 | **开单策略开关**：AI 归类的打法（顺势/结构破位回踩/区间边缘）须已启用（页面可改，默认开前两者） | 跳过该币 |
| 7 | **EMA 排列必须条件（顺势交易专属）**：多单须 EMA21>EMA55>EMA144（多头排列），空单须 EMA144>EMA55>EMA21（空头排列），开仓时按最新已收盘 K 线复核 | 跳过该币 |
| 8 | **余额风控（70% 规则，§4.3）** | 停止本轮开仓（资金不足，后续更开不了） |
| 9 | 仓位计算合法（qty ≥ 交易所最小名义价值/精度步长，否则向上调整或放弃） | 调整/放弃并记录 |

## 4. 资金与仓位规则

### 4.1 风险基数分档【已确认】

- 基数 = 账户余额（walletBalance，**不含未实现盈亏**）向下落到最近的档位：
  - 档位 `100 / 200 / 500 / 1000 / 2000 / 5000 / 10000`（`TRADING_CAPITAL_TIERS` 可配）
  - 例：余额 150 → 基数 100；余额 730 → 基数 500

### 4.2 仓位计算（固定亏损法，与 Risk Guard 同源）

```
止损金额 = 风险基数 × 3%（TRADING_RISK_PCT，例：基数100 → 3 刀）
名义仓位 = 止损金额 ÷ 止损距离%（止损距离 = |entry - stop| / entry）
数量 qty = 名义仓位 ÷ 现价（按 symbol 的 stepSize 向下取整）
保证金 = 名义仓位 ÷ 20（TRADING_LEVERAGE=20，逐仓 ISOLATED，下单前对该 symbol 设杠杆与逐仓）
```

### 4.3 余额风控（70% 规则）【已确认】

```
可用余额 = walletBalance（不含浮盈） − 在跑单子占用保证金
若 可用余额 < 总资金 × TRADING_MIN_FREE_PCT(0.7) → 本轮不再开单
（即：在跑单占用不得超过总资金的 30%）
```

## 5. 订单结构（币安 USDT-M 合约，单向持仓，**20× 杠杆、逐仓**）

| 订单 | 类型 | 数量 | 说明 |
|---|---|---|---|
| 入场 | MARKET | qty（100%） | 以现价市价进 |
| 止损 | STOP_MARKET（closePosition） | 全仓剩余 | 价格 = AI 止损价 |
| 止盈一 | TAKE_PROFIT_MARKET（reduceOnly） | **开仓仓位的 50%** | 价格 = AI TP1 |
| 止盈二 | TAKE_PROFIT_MARKET（reduceOnly） | **开仓仓位的 25%** | 价格 = AI TP2 |

- 进场后立即挂 SL/TP1/TP2 三单；任一挂单失败 → 市价平掉入场仓位并记录 ERROR（不留裸仓）
- **2025-12-09 起币安将条件单迁移到 Algo Order API**（经典 `/fapi/v1/order` 对 STOP_MARKET/TAKE_PROFIT_MARKET 返回 -4120）：
  SL/TP 走 `POST /fapi/v1/algoOrder`（`algoType=CONDITIONAL`，`triggerPrice` 替代 `stopPrice`），以 `algoId` 标识，
  撤单 `DELETE /fapi/v1/algoOrder`、挂单查询 `GET /fapi/v1/openAlgoOrders`
- 数量/价格统一 Decimal 规范化（交易所 -1111 精度校验）；紧急平仓用 reduceOnly 市价单（开仓未成交时会被拒绝，防反向开成裸仓）

## 6. 交易状态机

```
OPENED（已开仓，三单就绪）
  ├─ TP1 成交 → TP1_HIT（记录已实现盈亏 part1）
  │     ├─ TP2 成交 → TP2_HIT → 止损移至 TP1 价（保本）
  │     │     └─ 每小时巡检跟进止损（下）
  │     └─ SL 成交（未到TP2）→ CLOSED（结算）
  ├─ SL 成交（直接止损）→ CLOSED（结算）
  └─ 下单失败 / 挂单失败已平 → FAILED / CLOSED
```

**跟进止损（剩余 25% 仓位的退出规则）【已确认】**：TP2 成交后，每次巡检将止损移到
「最近 3 根已收盘 K 线（K 线周期同扫描周期）的最低价」（多单）/「最高价」（空单），
**只收紧不放松**：多单新SL = max(当前SL, 最近3根最低价)；空单 = min(当前SL, 最近3根最高价)。
每次移动写 SL_MOVE 事件。

## 7. 每小时交易任务（minute=42，先结算后开仓）

**① 结算**——对每笔非终态（OPENED / TP1_HIT / TP2_HIT）交易：

1. 查 `positionRisk`（持仓）+ `openOrders`（挂单）+ 成交回报（userTrades / income REALIZED_PNL）
2. 判定本小时事件：TP1/TP2/SL 成交 → 状态迁移、执行移动止损（含 TP2 后的跟进止损）、写事件
3. **已止损或已止盈（仓位归零）→ 结算**：以币安 income 汇总**净盈亏**（REALIZED_PNL + COMMISSION + FUNDING_FEE，费用为负值直接求和），记**正/负值**（USDT）与相对止损金额的百分比，状态置 CLOSED，记录平仓时间
4. 交易所与本地不一致（本地 RUNNING 但交易所无持仓无挂单）：以交易所为准补结算，写 WARN 事件

**② 开仓**——按 §2/§3：查未交易的 ≥60 分 suggest 分析，按推荐度降序逐个过闸门开仓。

> 单子本身的止损止盈由交易所挂单实时执行，不依赖巡检；巡检最多延迟 1 小时记账与跟进止损。

## 8. 数据模型

**trade_records（一单一行）**

| 字段 | 说明 |
|---|---|
| id, symbol, direction(long/short) | 基础 |
| scan_result_id, ai_analysis_id, recommendation | 溯源到信号与 AI 分析（含开单时的评分） |
| testnet | 测试网/正式网标识（区分环境数据） |
| ai_snapshot | 开单时 AI 分析结论快照 JSON（前端 AIAnalysisCard 直接渲染，不随 ai_analyses 清理断链） |
| entry_price, qty, notional, leverage, margin_mode, margin_used | 开仓（margin_mode=isolated） |
| stop_loss, tp1, tp2 | 三价（SL 跟进后同步更新，历史在 events） |
| status | OPENED / TP1_HIT / TP2_HIT / CLOSED / FAILED |
| opened_at, closed_at | 时间 |
| realized_pnl, pnl_pct | 结算收益（正/负值；pnl_pct 相对止损金额） |
| exit_reason | 跟进止损 / 保本SL / 直接SL / 异常平仓 |
| raw | 币安订单 id、挂单 id 等原始信息 JSON |

**trade_events（操作历史，一事件一行）**：trade_record_id、event_type（OPEN / TP1_FILL / TP2_FILL / SL_MOVE / SL_FILL / CANCEL / ERROR / SETTLE / SKIP）、detail JSON、created_at

**system_config 增列**：`max_open_trades int = 5`（同时在跑单子上限）

## 11. 异常与边界

- **下单部分成交**：市价单按实际成交量补挂 SL/TP，事件记录
- **同币种重复信号**：已有持仓跳过；24h 重复命中沿用旧 AI 结论的不会重复下单（只对未交易过的分析记录开仓）
- **AI 通过但币安报错**（精度/最小名义/保证金不足）：记 FAILED + SKIP 事件，本轮继续下一个候选（不连环重试同币）
- **API 失效/网络**：balance 查询失败 → 本轮开仓跳过（结算照跑）；巡检失败 → 下小时重试（交易所挂单在场，风险不受影响）
- **服务重启**：以交易所为真源（持仓+挂单+成交）重建状态，本地只做展示与记账
- **精度**：qty 按 stepSize 向下取整、价格按 tickSize 取整；名义价值低于 symbol 最小值则放弃
