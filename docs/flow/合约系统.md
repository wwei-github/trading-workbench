# 合约系统全流程

> 基于代码现状整理（2026-09-24）。主链路：定时扫描 → AI 分析 → 即时开仓 → 每小时结算巡检 → 复盘归因 → 通知/前端展示。
>
> 前端入口：头部 Segmented 选择「合约」业务域后，共 10 个子 Tab：扫描结果 | 关注列表 | 搜索币种 | 策略提示词 | 资金分析 | 交易记录 | 复盘（实盘归因/AI建议质量/规则补丁/币种黑名单） | 资金划转 等。

## 1. 定时扫描链路

核心文件：`app/tasks/scan_tasks.py`、`app/services/scanner.py`

1. **币种池**（scanner.py:183-240）：拉取币安 USDT 永续全列表，按 24h 成交额降序，依次过流动性、可交易性、风险档位、黑名单过滤，并发扫描。
2. **单币扫描**（scanner.py:86-153）：
   - 取 1h K 线算六大指标投票（见 §2）；预筛 `|净票| < 2` 直接淘汰（不请求 4h，省 IO）；
   - 补拉 200 根 4h K 线（剔除最后一根未收盘的）算 4h 背景作为第 7 票，`|净票| ≥ 3` 才分组（多头组/空头组）；
   - 触发确认（两段式决策矩阵，docs/19 §4.1）→ 计算质量分 → 落库 `scan_results`：
     - 优先级 T1 突破 > 回踩+金K当根确认（`trigger_pullback_confirm`）> 上根回踩+本根金K次根确认 > 纯金K（T2）> 触碰无金K 转 pending（`pullback_pendings` 表，次根金K才确认入场）；
     - T1 突破三重收紧（2026-09-25）：收盘越过 Donchian 轨 ≥ `BREAKOUT_THRESHOLD`(0.2%) + 放量（量比 ≥ `BREAKOUT_VOL_RATIO`=1.2）+ 长实体形态（实体/全长 ≥0.70、影线合计 ≤30%，2026-09-30-2 放宽），任一不满足落入金K/回踩分支；
     - pending 仅在恰好下一根已收盘K线有效（开盘时间精确比对），终态 confirmed/expired（window_expired/direction_flip）/superseded，由 scanner `_apply_pending_ops` 统一落库；
     - 关注列表手动刷新（watchlist.py）与扫描共用同一套 `detect_indicator_candidate` 判定逻辑。
3. **质量分 `compute_quality_score`**（technical.py:556-567）：
   - 基础分由票数、触发类型等构成；
   - 4h 背景修正：强同向 **+10**、弱同向 +5、弱反向 -8、强反向 **-12**；4h 震荡/纠缠（dir=0）不修正；
   - 分数决定排序与 AI 配额优先级。

## 2. 指标投票与 4h 背景

核心文件：`app/services/strategy/technical.py`

- **1h 六大指标**（technical.py:472-520）：MACD、布林带、RSI、SuperTrend、ADX、OBV，各投一张多/空/中性票。
- **4h 背景 `analyze_htf_background`**（technical.py:388-438），四档判定：
  1. **震荡**：ADX(14) < 20 → dir=0，不投票；
  2. **均线纠缠**：EMA21/55 间距 < 0.1% → dir=0；
  3. **弱多/弱空**：间距 0.1%~1% → dir=±1；
  4. **强多/强空**：间距 ≥ 1% → dir=±1。
  - detail 行带 `间距x.xx%, ADX=xx.x` 注入 prompt；ADX 计算失败静默降级为仅 EMA 判定。
- 快照落库：`votes_json.htf`（state/label/dir），前端「4h方向」列（扫描结果、交易记录两处）与「4h背景(EMA21/55)」指标块共用同源数据。

## 3. AI 分析链路

核心文件：`app/tasks/ai_tasks.py`、`app/services/ai_analyzer.py`、`app/services/ai_agent.py`

1. **批量派发**（ai_tasks.py:232-266）：扫描后取成交额前 `AI_MAX_PER_SCAN=10` 个候选，`group()` 一次性派发 Celery 子任务；
2. **并发控制**：Redis 信号量 `sem:llm` 全局 `LLM_CONCURRENCY=4`（config.py:59），队列模式完成一个补位一个；等待超时 300s 降级放行；单次 LLM 调用超时 `AI_CALL_TIMEOUT_S=240s`；实测单币 85~130s，批量拥塞时更长；
3. **管线选择**：工具栏开关 `ai_pipeline_enabled` 二选一——
   - **P0** `analyze_with_guard`：单次 LLM 调用 + 程序守卫；
   - **P1** `analyze_coin_agent`：Agent 多步工具链（结构化锚定 ref+offset_pct，绝不绝对价格）；
4. **Prompt 纪律**（ai_analyzer.py:33-106）：指标多数决方向优先（1h K 线形态与多数矛盾时以多数为准）；**4h 强背景硬约束**——强多头背景只能开多、强空头只能开空（prompt 注入 + 系统提示词最高优先级条款 + 程序兜底 `enforce_htf_constraint`，违反强制 skip 并注明原因）；
5. **结论落库**（ai_tasks.py:352-384）：写 `ai_analyses`（analysis、三价、recommendation 分）；`recommendation ≤ 30` 视为 skip；多周期矛盾时结构破位打法强制降分（≤60）；
6. **即时开仓**：suggest 且推荐分达标 → 派发 `open_trade_for_analysis`（开单唯一通道，开仓锁内执行）。

## 4. 开单执行

核心文件：`app/tasks/trade_tasks.py:215-290`、`app/services/trade_engine.py`

1. **多账号扇出**（docs/17 P1）：环境互斥（测试网/正式网二选一，`system_config.trading_testnet`）；正式网内按 `live_trading_keys` 启用集合并行开单，`account_registry.enabled_accounts(db)` 为权威清单（空回落 live-1）；
2. **开仓锁**：按账号 `lock:trade_open:{account_key}`，与结算巡检互斥；不同账号并行；LLM 调用绝不进锁内；
3. **风险预算**（trade_engine.py:46-87）：风险基数 = 钱包余额口径，首位取整，下限 100 / 上限 5000 USDT；钱包余额 ≤ 0 禁止交易；
4. **下单流程**（trade_engine.py:413-490）：市价开仓 → 挂 SL（`stop_market_close`，全仓 closePosition）→ 挂 TP1/TP2（`take_profit_reduce`，reduceOnly 分批 **50%/25%**，无 TP2 时 TP1 吃 75%）→ 创建 `TradeRecord`（status=OPENED）；
5. **防重复**：「该分析已开过仓」按账号口径查（account_key 匹配 + NULL 按 testnet 回落）。

## 5. 每小时结算巡检（:00）

核心文件：`app/tasks/trade_tasks.py:81-189`、`app/services/trade_engine.py`、`app/services/position_advisor.py`

持锁后按顺序执行：

1. **结算 `settle_trades`**：遍历 OPENED/TP1_HIT/TP2_HIT 记录——
   - TP1 成交 → SL 移至开仓价保本；
   - TP2 成交 / 无 TP2 单 TP1 部分成交后 → 跟进止损；
   - SL 单丢失自动补挂；收益结算口径：全程 `(realized_pnl + unrealized_pnl) / risk_amount`（R 倍数）；
2. **自动导入手动仓 `auto_adopt_positions`**（trade_engine.py:1514-1537）：交易所非零持仓中无在跑记录的 = App 手动单，从 `/fapi/v1/openAlgoOrders` 解析 SL/TP（**字段为 orderType**，市价/限价四类都认），撤原单按系统规则重挂后接管，成功飞书推送；裸仓（缺 SL 或 TP）不入册只记日志；前端可点「导入持仓」立即触发同逻辑（`POST /trades/adopt-now`）；
3. **孤儿条件单清扫**：无持仓且无在跑记录的 symbol 条件单撤销（不动未知 symbol）；
4. **AI 持仓诊断 `position_advisor`**（position_advisor.py:62-87）：
   - 触发：首次浮亏立即 / 3h 冷却 / 恶化 ≥0.5R 提前刷新 / **持仓 ≥24h 未触发 TP1（滞留）**，首诊后每 24h 复诊；
   - 输出四档建议：hold / tighten / reduce / exit；滞留诊断重点评估资金效率（蓄势 vs 空耗）；
   - `exit` 建议推飞书卡片（含浮盈亏、R 倍数、持仓时长等），附带「市价平仓」按钮（需配置 FEISHU_ACTION_TOKEN），**绝不自动平仓**，点击后经长连接回调执行并推送结果卡。

## 6. 复盘归因

核心文件：`app/tasks/review_tasks.py`

- **建议复盘**（:00）：处理超 24h 的 suggest 决策，用当时的计划价重放行情判定 win_tp1 / win / loss / expired（expired 不进胜率分母；同 bar 止盈止损触碰保守判亏）→ 落 `trade_reviews`；
- **AI 归因**（:14）：对已平仓交易做错误归因（LLM），产出可执行的规则补丁草稿；
- **补丁闭环**（每日 11:40/11:45）：标签热度检查 → 补丁草稿 → active 补丁三态评估；
- 前端「复盘」Tab 下四子页：实盘归因 / AI建议质量 / 规则补丁 / 币种黑名单；实盘归因接口带 scope 参数区分环境。

## 7. 环境与账号体系

- **账号注册表纯 .env 驱动**（`services/account_registry.py`）：testnet-1（BINANCE_TESTNET_*）、live-1（BINANCE_LIVE_1_*，可回落旧变量）、live-N（N≥2，可选 _NAME）；改 .env 重启生效，无新表；
- **互斥开关**：切正式网自动关总闸 `trading_enabled=false`；总闸关时 scheduled AI 分析跳过、不派新单；
- **数据口径**：同表 testnet 布尔 + `account_key`（String(20) nullable，NULL 按 testnet 回落 testnet-1/live-1）；前端 ScopeSelector：单 live 账号 = Segmented（live/testnet），多账号 = Select（live 聚合/各账号/测试网/all）；资金分析、复盘、交易记录、资金划转面板随环境切换自动刷新（请求序列号守卫防串台）；
- 每日日报按当前环境统计：测试网模式统计测试网数据，正式网统计 live 聚合。

## 8. 通知与数据流

- **飞书**：统一走自建应用机器人（`feishu_bot`，长连接 + card.action.trigger 回调；断线 30s 重连循环）；FEISHU_TARGET_ID 按前缀识别群/个人；CI 部署通知走 open API；门禁失败必须通知「代码未部署，线上仍在跑旧版本」；
- **主要表**：`scan_results`（含 votes_json.htf）、`ai_analyses`、`trade_records`（ai_analysis_id 可空——手动导入单无 AI 行）、`account_transfers`、`trade_reviews`、`system_config`、db_logs；
- **AI 进度**：`ai_progress` 事件流存 Redis（TTL 过期即失），运行轨迹经 `/api/scans/ai-trace/{id}` 查看（只记工具返回 count/hash，超 32KB 截断）。
