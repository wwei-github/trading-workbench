## 1. 问题与定位

三层防护（档位滞回 / 合计风险上限 / 当日熔断）管的是「**开多少**」（资金层面），
本篇 BCD 管的是「**开哪个**」（币种质量层面），两者正交互补：

| 层 | 管什么 | 拦截对象 | 位置 |
|---|---|---|---|
| **B** 盘口滑点实测 | 进场成本 | 薄盘小币吃单滑点撑宽止损 | 开仓前（每单） |
| **C** 交易所风险档位 | 品种资质 | 交易所标注的最大杠杆 <10× 妖币 | 扫描宇宙（每小时） |
| **D** 黑名单 | 已知坏蛋 | 手动点名 + 止损超预算自动冷却 | 扫描宇宙 + 开仓前双保险 |

### 为什么 24h 成交额门槛拦不住

[scanner.py] 原有 `MIN_VOLUME_24H = 300万` 门槛，但 GRIFFAIN（24h 成交额过千万）
照样翻车——**成交额衡量热度，不衡量盘口深度**。拉盘时成交额很高，订单簿照样薄
（GRIFFAIN 实测吃单滑点 0.637%，牛来只有 0.032%，差 20 倍）。只有按本单数量
真实走一遍订单簿才能发现。

## 2. B 盘口滑点实测闸门

**原理**：下单前先「假装买一遍」——把本单数量按订单簿挂单逐层吃下去，加权均价
对最优价的偏离即预期滑点。

### 实现

- [binance_trader.py] `market_slippage_estimate(symbol, side, qty)`：
  拉 `/fapi/v1/depth` 50 档，逐层吃单算加权均价；簿数据异常返回 `None` 不阻断开仓
- [trade_engine.py] `_attempt_open` 内、保证金校验之后执行：
  ```
  预期滑点 > max_slippage_pct → 放弃，落明示原因「盘口滑点实测 X% 超上限 Y%」
  ```

### 参数

`max_slippage_pct`（补丁参数全家桶：模型列 / 幂等迁移 / schema / API 校验 /
patch_service / 前端手改入口）：默认 **0.3%**，页面可改，**0 = 关闭闸门**。

### 成本

单次 `/fapi/v1/depth`（50 档）实测 50~150ms、权重 2/2400 每分钟——开仓是低频事件，
开销可忽略。

## 3. C 交易所风险档位过滤

**原理**：币安对每个合约标注风险等级（leverageBracket），最大允许杠杆是交易所对
流动性/风险的终极标注。

### 关键教训：首档 MMR 口径不可用

初版设计按「首档 MMR ≥1.2% 或最大杠杆 <10×」过滤，**测试阶段实测拦截 302/523
（58%）**——NEAR/AAVE/SUI/DASH 全被误拦。真相：

> 币安 2026 年已把绝大多数山寨**首档** MMR 统一调至 1.5%~2%（首档名义 5k~10k
> 区间的常规配置），BTC 0.4% 是孤例。首档 MMR 已无风险区分度。

改为**最大允许杠杆 <10× 单一判定**后：全市场拦 21 个（龙虾/哈基米/XPL/ZAMA 等
妖币），BTC 125×/NEAR 50×/SUI 50× 全过。

### 实现

- [binance_trader.py] `risk_tier_all()`：一次 `leverageBracket` 全市场拉取
  （885 币），返回 `{symbol: (首档MMR, 最大杠杆, …)}`，**进程缓存 24h**
- [scanner.py] 扫描宇宙阶段（成交额过滤之后）：`rt[1] < 10` 的币剔除；
  拉取失败（空表）放行不阻断扫描

### 注意

4USDT 最大杠杆 50×，本层不再拦截——它由 B（滑点）与强平闸门（MMR 动态取档）
负责，C 只拦「交易所都嫌弃」的极端标的。

## 4. D 黑名单（手动 + 自动）

### 数据模型

新表 `symbol_blacklist`（[models/blacklist.py]，走 `database.py` `_run_migrations`
幂等迁移纪律）：

| 列 | 说明 |
|---|---|
| `symbol` | 币种，唯一约束（自带索引） |
| `origin` | `manual` 手动（永久）/ `auto` 自动（冷却期） |
| `reason` | 人工备注 / 自动理由（含计划风险与实亏金额） |
| `expires_at` | auto 冷却到期时间；manual 恒 NULL |
| `disabled` | 停用标记（保留历史） |

### 自动口径（用户拍板）

> 「止损的金额严重超出预计的止损金额，就加入黑名单」

[blacklist_service.py] `register_settle()` 在**结算后**触发（trade_engine 结算钩子）：

- **净亏损 ≥ 计划风险 × 1.2**（超预算 20%+）→ 自动拉黑冷却 **30 天**
  - 覆盖：滑点撑爆止损距离（GRIFFAIN -121.7% R）、资金费侵蚀、强平（-126.4% R）
- **exit_reason == liquidation** → 无条件拉黑（止损彻底失效）
- 预算内正常止损、盈利单 → 不拉黑
- 重复触发只刷新理由与到期时间，不重复建行
- （初版「连亏 3 笔 + 趋势扭转解除」设计已废弃——超预算是结构性问题，靠冷却
  到期或手动移除）

### 手动管理

复盘 Tab 新增「币种黑名单」子页（[BlacklistPanel.tsx]）：

- 添加：输入币名（自动补 USDT 后缀/去空格/转大写），可带备注，**永久生效**
- 移除：任意行删除（删行，无历史保留价值）
- 列表展示：来源标签（手动=紫 / 自动=橙）、状态（生效中/已过期/已失效）、原因

### API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/scans/blacklist` | 全量列表（含 active/expired 判定） |
| POST | `/api/scans/blacklist` | 手动添加 `{symbol, reason?}` |
| DELETE | `/api/scans/blacklist/{symbol}` | 手动移除 |

### 过滤双保险

1. **扫描宇宙**（主过滤）：`active_symbols(db)` 命中的币不进指标候选 → 不 AI
   分析、不开单，省配额
2. **开仓前兜底**：`_attempt_open` 首道闸门再查一次——覆盖「扫描与开仓时间差内
   刚被拉黑」的场景
3. 自动登记失败（DB 异常）只 warning 不阻断结算

## 6. 部署与踩坑

提交 `2b7b963`（18 文件 +557）部署时 **celery_beat 启动循环崩溃**：

```
psycopg2.errors.DuplicateTable: relation "ix_symbol_blacklist_symbol" already exists
```

根因：`symbol` 列 `unique=True` 已自带唯一索引，模型里又显式 `Index(...)`、
迁移里又 `CREATE INDEX` 同名索引——三重冲突，create_all 首次启动撞索引。

修复（`fd195f0`）：移除模型层 Index，迁移改补 `origin` 索引。
**教训：unique=True 的列不要再建同名 Index**（含迁移）。

终验：6 容器 Up、beat 正常调度、blacklist API 直连/前端反代 200、表已建。

## 7. 与相关机制的关系

- **三层防护**（档位滞回/合计风险上限/当日熔断）：资金层面，本篇 BCD 管币种层面
- **强平闸门**（bracket_mmr 动态 MMR）：开仓可行性，与 C 同源 leverageBracket
  缓存（`risk_tier_all` 复用同一 API，进程缓存 24h）
- **动态杠杆**（_adaptive_leverage）：止损过宽时降杠杆，是「尽量开」；B 是「不值
  得开就不开」，先后配合
- **复盘补丁闭环**：`max_slippage_pct` 已入补丁参数体系，AI 归因产出建议值可经
  人工确认后调整
