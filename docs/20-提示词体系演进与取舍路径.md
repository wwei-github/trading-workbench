## 四、待拍板：trail 模式的 RR 铁律（2026-10-10，个案 3 后续）

**矛盾**：trail 哲学 = 不设固定目标、让利润奔跑；现行 `risk_guard` 三价复算不看 tp_mode，trail 的 TP1 仅作参考价也须 ≥1.5R。BTWUSDT 21:55 实测：入场 ≈1.585 / 止损 1.5154（4.4%）/ 前高 1.660 → RR 1.09；1.5×ATR 延伸 ≈1.68 → 1.39；须 ≈2.1×ATR（1.69）才达标——**提示行给的三个目标在强趋势+宽止损盘面全部过不了铁律**，制度性堵死。

量化观点：固定目标 RR 是 ladder 语义的代理指标，拿来卡 trail 语义错位；宽止损风险已有独立闸门（max_stop_pct 硬上限 + 固定亏损法自动缩仓），不必靠 RR 兜底。

| 选项 | 内容 | 评价 |
|---|---|---|
| A 完全豁免 | tp_mode=trail 即不复算 RR | 实现最简；弱背景/震荡里的宽止损 trail 失去最后一道量化门 |
| **B 条件豁免（推荐）** | trail ∧ 4h phase ∈ {medium,strong,extreme} ∧ momentum=same → 豁免；否则仍 1.5R。资格复用取舍提示行判定（htf_phase 已落库，momentum 可补 stash） | 与提示行资格同源，弱背景仍受控；同步改 P0 `_RULE_TP_BASE`/P1 12/12.5/提示行/回炉反馈/测试 |
| C 降门槛 | trail 参考价 RR ≥1.0 | 本笔 1.09 险过，边界摩擦仍在 |
| D 维持 | 不改，接受此类单全部 skip | 与用户意图（trail 不看盈亏比）相悖 |

**拍板结果（2026-10-10 用户拍板「全部修改」→ 采纳 B）——已实施**：

- `risk_guard.validate_decision` 新增 `htf_bg` 参数：`_trail_rr_exempt` 判定（trail ∧ phase ∈ RR_TRADEOFF_PHASES ∧ momentum=same）；豁免仅放宽 RR，价格序/近锚/战法白名单照常；RR 复算值照常落库不虚报；htf_bg=None 缺证从严不豁免；trail 被拒时的回炉反馈点明豁免资格（Reflection 可自修）
- 资格单一来源：`technical.RR_TRADEOFF_PHASES = ("medium","strong","extreme")`，提示行注入与豁免共用同一常量（risk_guard import 同对象，测试以 `is` 断言）
- 4h 背景透传：P0 `analyze_with_guard` 入口算一次 `analyze_htf_background(htf_klines)` 随校验透传；P1 `analyze_coin_agent` ctx["htf_bg"] → `_handle_submit` → validate_decision
- 提示词三处同步：P0 `_TP_MODE_FIELD`/`_RULE_TP_BASE`、P1 rule 12 括注/12.5（trail 参考价如实上报趋势目标、强背景下豁免无须凑 1.5R）；提示行措辞同步（"复算达标"→"如实上报即可（豁免）"）

> **2026-10-11 退役**：拍板 B 整链（htf_bg 参数、`_trail_rr_exempt`、RR_TRADEOFF_PHASES 单一来源、提示词豁免条款）随策略一 ladder-only 重定义全部移除。RR 铁律重新无条件适用于策略一；trail 仅存在于策略二（s2 本就豁免 RR，见 §五）。

## 五、双入场策略拆分（2026-10-10-5 拍板，独立需求）

**需求**（用户拍板，与个案无关）：将 AI 分析拆为两个入场策略，对同一信号分别评估、分条说明、合并单一决策——

| 策略 | 定义 | 出场 |
|---|---|---|
| 策略一（s1） | **trail 加入前的原版完整规则**（2026-10-11 重定义）：ladder 分批止盈（TP1/TP2 结构位落袋）+ 盈亏比铁律（RR≥1.5）+ 结构位止盈规划，无 trail | ladder（唯一，程序推导） |
| 策略二（s2） | 只判断"在 EMA21 出现的金K"质量（形态成色/量能/指标多数决/4h 硬约束），**不做 1.5 盈亏比判断、不找止盈位** | 固定 trail 纯跟踪（浮盈 1×ATR 武装保本后跟进止损），TP1=趋势目标参考价（不挂单、不做盈亏比校验，仍受方向价格序约束）、TP2=0，止损照常 |

**合并规则**：两个策略都不满足才 skip；两个都满足时**优先取策略一开单**。**tp_mode 由 entry_strategy 程序推导**（s1→ladder、s2→trail；2026-10-11 起 AI 不自选，输出值被覆盖）。

设计原则（沿用 2.3 沉淀）：合并语义不靠提示词祈愿，全部用**程序闸**兜底——

1. **资格闸**（risk_guard）：s2 仅当信号 `touch_ref=ema21`（程序事实），谎报打回重试；
2. **语义强制**（2026-10-11 升格为全链推导）：s2 提交即程序强制 `tp_mode=trail`、TP2 清零（trade_engine 侧 tp_mode_eff 同步按 entry_strategy 推导——`"trail" if s2 else "ladder"`，cfg.tp_mode 强制配置已退役）；
3. **RR 豁免**：risk_guard RR 铁律豁免条件 = `_is_s2`（s2 无条件豁免；拍板 B 的 trail 条件豁免已随 2026-10-11 退役删除，策略一 RR 复算无豁免）；
4. **优先级闸（2026-10-10-5b 拍板：打回改自动改标）**：s2 复算 RR ≥1.5 达标 → 程序直接改标 s1 落库，不打回。初版为"强制打回改报 s1"，复核发现**假等价**：s2 的 TP1 是趋势目标参考价，可能比 s1 的第一档结构位更远，"s2 复算达标 ⟹ s1 达标"并不成立——打回后 AI 如实回第一档则再次被拒（误杀仅 s2 满足的单），改报远目标则变相跳档凑 RR；且打回压力诱导低报 TP1（s2 的 TP1 无程序校验）规避闸门。改标式：同三价在 s1 全部程序闸（RR/方向价格序/近锚）均已通过，改标签即合法 s1 单，零重试损耗零误杀；改标痕迹 = `entry_strategy=s1` + `strategy2_decision=suggest`，复盘可过滤；**改标后 tp_mode 同步翻 ladder**（trail 归策略二独有，2026-10-11 起策略一无 trail）；
5. **现价 RR 复算豁免**（trade_engine `_attempt_open`）：s2 跳过开仓闸门现价 RR 复算（否则 trail 语义在开仓侧被二次堵死，同 §四矛盾）；
6. **审计一致性闸**（2026-10-10-5b 补，risk_guard）：`strategy2_decision=suggest` 须触点=ema21；`entry_strategy=s2` 须 `strategy2_decision=suggest`——矛盾组合打回防复盘分组脏数据。
