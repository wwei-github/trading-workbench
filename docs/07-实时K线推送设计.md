# 07 实时K线推送设计（KlineHub + SSE）

> 需求：图表按秒级看到最后一根未收盘 K 线的实时跳动，上游接口调用不随浏览器/图表数增长。
> 方案 C：后端对每 (symbol, interval) 维持 1 条币安 WebSocket，SSE fan-out 给所有浏览器。

## 1. 架构

```
币安 fstream WS（1 条连接，动态 SUBSCRIBE/UNSUBSCRIBE，单连接 ≤200 streams）
      │ kline 帧 250ms/次；断线指数退避×3 → REST 降级轮询(3s)；REST 期间每 30s 探测恢复
      ▼
KlineHub 单例（uvicorn API 进程内，惰性启动：首个订阅才连上游）
  订阅表 {(symbol, interval): set[asyncio.Queue(maxsize=64)]}
  背压：queue 满丢最旧（latest-wins，kline 帧是当前 bar 的完整替换，幂等）
      │ SSE（EventSource，retry: 5000，15s 心跳注释行）
      ▼
浏览器 KlineChart：bar → series.update() 原位更新最后一根（主图 + VOL），
                   不碰 candlePoints（避免指标 effect 每 tick 全量重建）；
                   x=true 收盘帧 → 20s 去抖全量刷新（同步摆动点/指标/图例）
```

## 2. 后端

| 组件 | 说明 |
|---|---|
| `app/services/kline_hub.py` | KlineHub 单例。订阅表、唯一币安 WS 上游（raw `/ws` 端点，动态 SUBSCRIBE/UNSUBSCRIBE）、状态机 `idle→connecting→ws→rest→connecting…`（断线退避 1/2/4s×3 次失败进 REST 降级；REST 期间每 30s 探测恢复）、看门狗（WS_OK 态 30s 无事件频道 REST 兜底一帧，覆盖下架符号）、`stop()` 供 lifespan shutdown |
| `app/api/kline_stream.py` | `GET /api/scans/klines/{symbol}/stream?interval=1h`。async 生成器：首帧 `retry: 5000` → snapshot（hub 缓存 → REST 双旁路快照 → null）→ 循环 `wait_for(queue, 15s)` 出 bar / 超时心跳 → `finally unsubscribe` GC |
| `ExchangePool.get_recent_klines()` | 缓存读写双旁路：不读缓存（limit=2 会命中整周期 500 根旧缓存）、不写缓存（避免 2 根覆盖全量缓存），直接走故障转移链路 |
| 配置 | `BINANCE_WS_URL`（默认 wss://fstream.binance.com）；`websockets==15.0.1` 显式 pin（uvicorn[standard] 传递依赖为开放区间，防版本漂移破坏 client API） |

状态机：

```
IDLE ──首个订阅──▶ CONNECTING ──connect成功──▶ WS_OK（SUBSCRIBE 全部 _desired）
                     │ 退避 1/2/4s 重试×3                     │ 断线
                     ▼                                        ▼
              REST_FALLBACK ◀──3 次失败──────────────── BACKOFF
                │ 每 30s 探测 WS，成功 → 回 CONNECTING
                ▼ 最后一个订阅者退出（任一状态）
              IDLE（取消任务、关连接、清缓存，空闲零上游连接）
```

## 3. SSE 协议

| event | data | 时机 |
|---|---|---|
| `snapshot` | `{symbol, interval, bar: {t,o,h,l,c,v} \| null}` | 连接首帧 |
| `bar` | `{t,o,h,l,c,v,x}` | 每次上游事件；`x=true` 表示该 bar 已收盘 |
| `degraded` | `{message}` | 上游全失败/看门狗兜底（按频道去重，消息变化才重发） |
| `: ping` | SSE 注释行 | 每 15s 无事件时保活 |

要点：业务错误命名 `degraded` 而非 `error`（与 EventSource 原生 error 事件冲突）；
interval 由前端传它已加载数据的 interval，端点无 DB 会话；
同步 IO（httpx/SQLAlchemy）一律 `asyncio.to_thread`，不阻塞事件循环（否则 15s 心跳会延迟——天然健康探针）。

## 4. 前端

- `api/klineStream.ts`：原生 EventSource 封装，`openKlineStream(symbol, interval, handlers) → close()`。
  监听 snapshot/bar/degraded；原生 error 仅 console.warn，靠服务端 retry 自动重连。
- `KlineChart.tsx`：
  - `streamInterval` 来自最近一次整包数据响应（`applyKlineData` 尾部设置）——订阅永远晚于首次数据落图，无初始化竞态
  - 订阅 effect 依赖 `[symbol, streamInterval]`；回调实时解引用 `seriesRef`/`indicatorMetaRef`，
    图表实例因 refreshKey/币种切换重建后，旧流的晚到帧安全落在新实例上（无需断流重连）
  - `applyBar`：`series.update()` 主图 + VOL 副图（颜色规则同 indicators.ts：收 ≥ 开 用涨色）；
    **不 setState candlePoints**（指标 effect 会 removeSeries 全量重建）
  - `x=true` → `scheduleFullRefresh()`：20s 去抖 + `refreshingRef` 与手动「更新」按钮互斥；
    走非强制缓存路径整包刷新，摆动点/指标/图例随之同步

## 5. 已知边界

- 运行时改 `kline_interval` 后，已开图表维持旧周期流；自愈路径 = 点「更新」（整包响应携带新 interval，自动换流）
- 下架符号订阅成功但永无数据 → 看门狗 30s 触发 REST 兜底 + degraded
- **中文合约**（牛来USDT/哈基米USDT/龙虾USDT 等非 ASCII 符号，币安确有上市）：REST 正常可用，
  但 WS 订阅 `牛来usdt@kline_1h` 会 ACK 成功却永不推帧（静默），且异常 stream name 可能触发
  1008 整连接踢出。hub 对非 ASCII 频道不进 WS 订阅，由看门狗按 3s REST 周期轮询兜底
- 页面隐藏/失焦不暂停（单用户工具，可选二期）
- 部署需容器可出站 `fstream.binance.com:443`；连不上则常驻 REST 降级（3s 轮询，实时性退化为 3s，功能可用）

## 6. 验证清单

1. `curl -N http://localhost:8082/api/scans/klines/BTCUSDT/stream?interval=1h` → 首帧 snapshot、250ms/条 bar；走 8088（nginx）验证逐条不攒批
2. 两个 curl 订阅同频道 → 后端日志仅 1 次 SUBSCRIBE、1 条上游连接；最后一人退出才 UNSUBSCRIBE/GC
3. 置无效 `BINANCE_WS_URL` → 3 次退避后 REST_FALLBACK、每 3s 出 bar + degraded；恢复后 ≤30s 回 WS
4. `interval=1m` 等整分 → x:true 帧 → 摆动点/VOL/图例自动全量刷新；连续两分验证 20s 去抖
5. x=true 刷新瞬间点「更新」→ refreshingRef 互斥，仅一次请求
6. `docker compose restart backend` → EventSource 5s 自动重连收新 snapshot
