## 0. 全链路总览

```
                    ┌──────────────────── 每小时 :02 ────────────────────┐
                    │  ① 全市场扫描 scanner.Scanner.run                    │
                    │     量能过滤 → K线 → EMA → 信号 → 落库               │
                    └──────────────┬─────────────────────────────────────┘
                                   │ scan_results
                    ┌──────────────▼─────────────────────────────────────┐
                    │  ② AI 分析分发（信号落库后即时派发）                  │
                    │     Stage-1 免 LLM 闸门（指纹沿用；程序 skip 已移除） │
                    │     事实包组装 → LLM（信号量并发3）→ risk_guard 校验  │
                    │     → ai_analyses 落库 → 即时开仓通道               │
                    └──────────────┬─────────────────────────────────────┘
                                   │
   每小时 :10 ─────────────────────▼──────────────────────────────────────
   ③ run_auto_trade_task（仅结算巡检）：Redis 锁 → settle_trades（交易所为真相）
      ——与②的即时开仓互斥串行；开仓唯一通道 = ②（2026-09-14 取消批量开仓，
      巡检时点由 :42 提前至 :10，尽早释放额度与在跑名额）
                                   │
   每 30 分钟 ─────────────────────▼──────────────────────────────────────
   ④ 复盘任务：suggest 决策 24h 后逐 K 回放 → trade_reviews（引用 ai_analysis_id）
```

**时间与时区**：全站展示统一北京时间（2026-09-13 起），数据库存 UTC。

**开仓唯一通道（2026-09-14 晚起，取消 :42 批量开仓）**：
- AI 分析落库后立即派发 `open_trade_for_analysis`，suggest 且 ≥60 分即触发；
- 闸门未过/等锁超时（45s）即放弃，无批次兜底——等该币下次信号重新分析再触发；
- 与每小时 :10 结算巡检共用 Redis 锁 `lock:trade_open` 串行（锁 TTL 900s），防同一分析被开两次、防结算与开仓竞态。

## 1. 阶段一：币种筛选与信号检测

**入口**：`backend/app/services/scanner.py`（`Scanner.run`），定时任务 `backend/app/tasks/scan_tasks.py`（每小时 :02）。

### 1.1 流程

1. **互斥**：上一轮扫描未结束时，本轮标记 `failed`（注意：语义是"跳过"，见 §8-C1）。
2. **候选池**：拉取币安 USDT-M 全部合约，按 24h 成交额降序，过滤 `MIN_VOLUME_24H`（默认 300 万 USDT）。
3. **重复抑制**：`repeat_window_hours` 内已命中过的 (币种, 信号类型) 本轮**不落库**（`_suppress_repeat_hits`，2026-09-15 由仅打标 `is_repeat` 改为直接抑制——持续趋势里 Donchian 突破每根收盘K线都在创新高，不抑制会同币同信号每轮重复命中）。
4. **槽位检查**：AI 分析满 `AI_MAX_PER_SCAN`（10）时停止新增分析。
5. **逐币种**：拉 K 线（`max(kline_window, 300)` 根，含未收盘最后一根）→
   `analyze_ema`（EMA21/55/144 形态与偏向）→ `detect_all_signals`（单币最多 1 个信号）。
6. **信号检测**（`backend/app/services/strategy/__init__.py` `_detect`）两条路径（docs/09，2026-09-14 关键位移除）：
   - **突破路径**：收盘破 N 根 Donchian 通道轨（`BREAKOUT_CHANNEL_BARS`=20，窗口取信号K线前 N 根已收盘、严格越轨）+ 量能 ≥1.2× 均量（`BREAKOUT_VOL_RATIO`）+ EMA 允许且同向；不要求形态；
   - **形态路径**：`detect_all_patterns`（最近已收盘 K 线命中 GOLDEN_12 形态）+ EMA 门控（state ∈ EMA_ALLOWED 且偏向同向）。
7. **强度**：突破 0.7（量能 ≥2× 均量 0.8）+0.1（EMA 同向）；形态 = 形态基础强度（0.5~0.9）+0.1（趋势反转）+0.1（EMA 同向），封顶 1.0。
8. **落库**：`scan_results`（signal_type / position / pattern / strength / signal_reason / breakout_pct）。
9. **分发**：落库后对每条新信号派发 AI 分析任务（`backend/app/tasks/ai_tasks.py`）。

### 1.2 关键点

- K 线最后一根**未收盘**，所有"最新 K 线"判定实际用 `klines[-2]`（已收盘）。
- 信号 position 由形态/突破方向派生（看涨形态/向上突破=resistance、看跌/向下=support，docs/09）。

## 3. 阶段三：AI 分析

**文件**：`backend/app/tasks/ai_tasks.py`（调度与 Stage-1）、`backend/app/services/ai_analyzer.py`（事实包/LLM/校验）。

### 3.1 Stage-1 免 LLM 闸门（按顺序）

> **2026-09-15 拍板**：程序侧 skip 闸门（强度 / 信号陈旧 bars_ago / 振幅熔断 / 重复沿用）**全部移除**——选中的币种必须经过真实 AI 分析，跳过与否由 AI 自己决定。重复命中的治理前移到扫描侧（同币同信号窗口内不落库，见 §2 第 3 步）。

1. **指纹缓存**：`FINGERPRINT_TTL_MIN(60)` 内同指纹（symbol|signal_type|position|pattern|价格 0.5% 对数桶，docs/09）直接沿用旧结论（沿用前校验价格区仍有效，`_conclusion_still_valid`：现价 ∈ sl~tp1）。

### 3.2 事实包组装（`_build_messages`）

- **新鲜重算**：摆动点（recent_swings n=20）、ATR、EMA——全部用**分析时刻**最新 K 线重算。
- **现价刷新**：`current_price` 取分析时刻未收盘最新价。
- **内容**：信号字段（scan 时刻快照：pattern / signal_reason / breakout_pct 等）+ EMA 状态 + recent_swings(20) + 最近 60 根已收盘 K 线摘要 + 量能比。**不预取市场环境**（BTC 联动等）。
- **技能注入**：`skill_library.render_matched(build_facts(...))` 命中策略库则注入提示词；用户自定义策略提示词叠加。

### 3.3 LLM 调用

- 网关 glm-5.3-flash（**无法关闭思考，单轮实测 85~130s**）；并发信号量 `LLM_CONCURRENCY=3`（Redis zset，陈旧 10min 清理；超时**降级放行**，见 §8-B4）。
- 超时自动重试（间隔 90s，最多 2 次）。
- **信号陈旧风险**：从扫描（:02）到分析完成可能跨 20~30 分钟，形态/触位判定仍是 scan 时刻 K 线的快照。bars_ago 陈旧闸门曾于 2026-09-14 加入（§8-A3），**2026-09-15 按拍板移除**——AI 分析时以最新 K 线与现价重算锚点，陈旧与否交 AI 判断。

### 3.4 输出与校验链（`analyze_with_guard`）

- AI 按 P0 批量单次调用（P1 Agent 模式存在但默认关）输出：direction / entry / sl / tp1 / tp2 / trade_type / confidence / rationale。
- `risk_guard.validate`（`backend/app/services/risk_guard.py`）校验链，违规打回修正（最多 3 次尝试 = 1 + 2 次违规反馈重试），仍不过 → `build_forced_skip`：
  1. 方向-价格一致性；
  2. **方向铁律**：入场必须贴近同侧结构锚（多=摆动低点/近5根最低、空=摆动高点/近5根最高）±0.3% 容差带 ±0.25×ATR 内（breakout/manual_search 例外；无锚时放行，docs/09 换锚）；
  3. 入场偏离现价 ≤2%；
  4. **止损锚定**：入场同侧最近摆动点（多=下方最近摆动低点、空=上方最近摆动高点）vs 5 根 K 线影线极值，取更远者 + 0.3% 缓冲；<0.3×ATR 改极值锚；
  5. 止损宽度 ∈ [0.3×ATR, 3×ATR]；
  6. **止盈最近优先**（程序强制；docs/09 换摆动点锚）：候选 = recent_swings(n=50) 中入场方向前方的摆动点（多=上方摆动高点、空=下方摆动低点），最近优先；TP1 锚第一档近轨外 0.2%（AI 越档/越过结构位直接钳回）；**近位例外**：距现价 ≤1×ATR 的摆动位不作止盈目标；**近距合并**：与上一接受候选价距 ≤0.5% 并为一档；TP2 = 下一档；前方无摆动点（创新高/新低突破）→ 固定 RR 兜底（TP1 = entry ± 1.5×止损距×1.001，TP2=0）；钳制后 tp2≤tp1 → tp2=0；
  7. **RR 铁律**：修正后复算 RR ≥ `AI_RR_MIN(1.5)`，不足 → skip。
- **双评委辩论**（P2 实验开关，默认关）：对 suggest 决策多空辩论复核。
- 仓位**不由 AI 自报**：程序按固定亏损法计算（§4.3）。
- 落库 `ai_analyses`（决策/入场/止损/止盈/依据）。分析被交易/复盘引用后，重分析采用**摘钩不删除**（`scan_result_id` 置 NULL，2026-09-14 修复 FK 500）。

## 4. 阶段四：开单

**文件**：`backend/app/services/trade_engine.py`（`_attempt_open` / `try_open_for_analysis`）、`backend/app/services/binance_trader.py`（下单）。

### 4.1 触发口径（唯一通道 = 即时开仓）

- AI 分析落库（`_finish` → `_dispatch_immediate_open`，含沿用结论与 force 重分析）即派发
  `open_trade_for_analysis`；suggest 且 ≥60 分进入 `try_open_for_analysis`；
- 快速过滤：suggest / 方向 / 三价齐全 / 评分 ≥60 / 1 小时内生成 / 该分析未开过仓；
- 闸门未过即放弃（无 :42 批量兜底，2026-09-14 晚取消——评分排序随之废弃）。

### 4.2 闸门顺序（`_attempt_open`，全部通过才下单）

1. 在跑仓位 < `max_open_trades`（默认 5）；
2. 可用余额 ≥ 70%（`TRADING_MIN_FREE_PCT`）；
3. 资金分层 > 0（`_capital_base` = 钱包余额向下取整到 `TRADING_CAPITAL_TIERS` 档位）；
4. 同币种无在跑仓位；
5. `trade_type` 开关（trend_follow / structure_break / range_edge，系统配置）；
6. 方向-价格复核：long 需 sl < price < tp1（short 反之）；
7. 现价偏离 AI 入场 ≤1%；
8. **RR 复算**：以现价复算 RR ≥ 1.5（SCRUSDT 案例：入场漂移 +0.55% 后 RR 1.33 → 拒开，设计行为）；
9. trend_follow 要求 EMA 三线严格排列（多：21>55>144，空反之）；
10. **强平闸门**：止损距离 < 1/杠杆 − 维持保证金率 = 4.5%（20×），止损过宽直接跳过；
11. 交易所最小名义额/精度规则；
12. 保证金可用性。

### 4.3 仓位与下单序列

- **固定亏损法**：`notional = 资金档位 × TRADING_RISK_PCT(3%) ÷ 止损百分比`，qty 四舍五入；杠杆固定 20× 逐仓。
- **下单序列**：市价开仓（记录实际成交均价与滑点）→ 挂 SL（STOP_MARKET，closePosition）→ 挂 TP1（数量 50%；无 TP2 时 75%）→ 挂 TP2（25%，需 ≥ 交易所 min_qty）。
- **失败回滚**：任一挂单异常 → `cancel_all_algo` + reduceOnly 紧急平仓；-1121（不可交易）→ 落 `FAILED` 记录将该币排除出候选。
- **滑点**：实际成交偏离告警；实际风险 > 1.15× 预算仅 WARNING（见 §8-B3）。

## 5. 阶段五：结算与持仓管理

**文件**：`trade_engine.settle_trades`（每小时 :10 巡检，与即时开仓互斥串行）。

- **交易所为真相**：以交易所当前持仓 + 挂单 algo order ids 比对本地状态。
- **孤儿条件单清扫（2026-09-15）**：每轮结算收尾 `_sweep_orphan_algo_orders`——交易所在挂 algo 委托但**既无持仓也无在跑记录**的 symbol 一律撤销。巡检按 DB 记录驱动，清不到"无记录的遗留单"（DB 重置前的历史单等）；清扫只动本系统符号语境内的孤儿单，不做全账户无差别撤销。
- **事件推断**：止盈单消失（tp1_gone/tp2_gone）→ 推断 TP 事件；结算金额取 income 明细（REALIZED_PNL + COMMISSION + FUNDING_FEE）；`INSURANCE_CLEAR` → 判定强平（LIQUIDATION 事件）。
- **状态机**：OPENED →（TP1 成交）TP1_HIT：止损上移保本（幂等）；无 TP2 → 转移动止损；→（TP2 成交）TP2_HIT：每次巡检移动止损（收紧不放松，TP2_HIT 阶段钳制在 TP1 之上）。
- **移动止损**：最近 3 根已收盘 K 线极值锚定；巡检间隔 1h = 1 根 K 线。
- **裸仓风险**：OPENED 状态下**不检测止损挂单是否还存活**（见 §8-A2）。

## 6. 阶段六：复盘（AI 建议回放，与实际交易无关）

**文件**：`backend/app/tasks/review_tasks.py`（beat 每 30 分钟）。

- **对象与口径**：所有 `suggest` 决策（不论是否开了单），分析落库 24h 后（`OBSERVATION_HOURS`）用 1h K 线**逐根回放** AI 原始计划（entry/sl/tp1/tp2）——纯程序判定，不调 LLM。
- **结论四态**：`loss`（先触止损）/ `win_tp1`（触 TP1 后又触止损仍算）/ `win_tp2` / `expired`（24h 未触任何价位）；同一根 K 线同触 SL 与 TP 保守计 loss；`bars_to_exit` 记出场速度。
- **落库**：`trade_reviews` 一比一引用 `ai_analysis_id`（FK unique），附分析时点快照维度（signal_type/position/ema_state/recommendation）供分组统计。
- **统计**：`GET /api/scans/review/stats?days=N` 整体胜率 + 按三维度分组胜率（`ReviewStatsPanel` 展示；扫描结果表有复盘列，任务记录可展开逐条结论）。
- **区别于交易记录**：本阶段评的是**建议质量**（假想按 AI 计划进出）；实际成交的盈亏/滑点/手续费在 `trade_records` + `trade_events`（交易记录 Tab）。复盘输入自带 `ai_snapshot`，不依赖 ai_analyses 存活——摘钩方案能成立的前提。
- **规划未做**（docs/04 P2）：复盘摘要注入 Agent 系统提示词（自我校准闭环）、技能库按胜率优胜劣汰。

## 8. 漏洞与风险清单

> 梳理过程中发现的问题，按"已确认漏洞（建议修复）→ 设计张力（已知取舍）→ 观察项"分级。

### A. 已确认漏洞（✅ A1~A4 已于 2026-09-14 修复，commit 4393f22）

#### A1. TP1 挂单无最小数量预检 → 整单开仓回滚，且每轮重试 ✅ 已修复

- **位置**：`trade_engine._tp_quantities` / `_attempt_open`。
- **现象**：TP2 挂单前有 `qty_tp2 >= f["min_qty"]` 预检，**TP1 没有**。小仓位时 `qty_tp1 = 0.5×总量` 可能低于交易所 min_qty，TP1 挂单被交易所拒绝。
- **后果**：异常 → `cancel_all_algo` + reduceOnly 紧急平仓 → **整单开仓失败**；且该币不落 FAILED 记录（只有 -1121 才落），仍留在候选池 → **每小时 :42 重复"开仓→挂单→回滚→平仓"循环**，反复消耗手续费与 API 频率，实盘下是真金白银损失。
- **修复（2026-09-14）**：TP1 数量预检移到**下单前**——低于 min_qty 时整单放弃（分批止盈挂不上，主止盈档缺失无意义）。未下任何单，重试只剩两次 API 调用的零成本，无需 FAILED 记录。

#### A2. OPENED 状态止损挂单丢失无检测、无补挂 → 裸仓 ✅ 已修复

- **位置**：`trade_engine.settle_trades`（状态推进只由 tp1_gone/tp2_gone 事件驱动）。
- **现象**：巡检只推断止盈事件，**从不校验 SL algo 单（sl_order_id）是否仍在挂单列表**。手动撤单或交易所异常导致 SL 消失时，仓位在 OPENED/TP1_HIT 状态下无任何止损保护，直到强平或人工介入。
- **后果**：低概率、重后果（20× 逐仓裸仓）。
- **修复（2026-09-14）**：结算巡检新增 `_rehang_lost_sl`——仓位存活而 SL 单不在挂单列表时按当前止损价补挂（复用 `_replace_sl` 的 -4130 残留清理）；现价已越过止损价视为疑似刚触发，跳过留待结算路径确认。
- **附带发现并修复**：`_replace_sl` 以同一 dict 对象赋回 `rec.raw`，SQLAlchemy 判定无变化不写库——**历史单 raw.sl_order_id 全部停留在开仓旧值**（活库 4 条 SL_MOVE 记录实锤）。改为 `{**raw, ...}` 新对象赋值。

#### A3. 信号陈旧无闸门：形态判定距开仓可能跨多根 K 线 ✅ 已修复 → 🗑 2026-09-15 移除

- **位置**：`ai_tasks.py` Stage-1 / `ai_analyzer.py`。
- **现象**：形态/触位基于 **scan 时刻** K 线判定；分析阶段虽重算关键位/现价，但不检查"信号 K 线距今 N 根"。LLM 单轮 85~130s + 超时重试 90s，最坏链路（扫描排队 → LLM 重试）可跨 1~2 根 1h K 线，形态可能已失效甚至反向。
- **后果**：低质量/过时信号消耗 LLM 成本并可能开出逆势单。
- **修复（2026-09-14）**：Stage-1 第 2 道闸门 `_signal_bars_ago`——落库后超过 `AI_SIGNAL_MAX_BARS_AGO`（默认 2）根 K 线未分析直接程序 skip（落库 skip 结论 + 指纹，不调 LLM）；手动单币重分析（force）不受限。
- **移除（2026-09-15）**：按拍板移除程序 skip 闸门（含强度/振幅熔断），陈旧与否由 AI 以最新 K 线现算判断。

#### A4. 止损宽度上限（3×ATR）与强平闸门（4.5%）冲突 → 必死单每轮空转 ✅ 已修复

- **位置**：`risk_guard`（止损宽度 ≤3×ATR）vs `_attempt_open`（止损 <4.5% 强平闸门）。
- **现象**：高波动币 ATR% 大时，risk_guard 允许的止损宽度可能超过 4.5%——分析通过、LLM 成本已花，开仓闸门必跳过；且不落 FAILED，候选每轮重来。
- **后果**：这类币每轮重复白跑（拉 K 线 + 全闸门），LLM 花费无法产出任何开仓。
- **修复（2026-09-14）**：`risk_guard.liquidation_gate_pct()`（1/杠杆 − 维持保证金率）作为两处共用口径；风控侧以 ×0.9（20× 即 4.05%）作为安全上限直接打回 AI（开仓时现价对入场可漂移 1%，留余量），AI 收不紧就 skip；trade_engine 开仓闸门改用同一函数。测试套件 `/tmp/test_sl_anchor.py` 同步将杠杆补丁为 5×（锚距 5~7% 的夹具在 20× 下如今本就该被拦）。

#### B2. 止盈最近优先 + RR≥1.5 的联合副作用

程序强制 TP1 取第一结构位外沿后，若第一摆动位很近，RR 复算不足 1.5 → 大量信号在开仓闸门处死亡（SCRUSDT 本身 RR 仅 0.49）。这是规则的内含结果（宁缺毋滥），但会显著降低开单率——观察期统计 skip 原因分布再决定是否调节。

#### B3. 滑点仅告警不拦截

实际成交价导致 actual_risk > 1.15× 预算时只打 WARNING。testnet 盘口薄、20× 杠杆放大滑点；**正式网部署前需重新评估是否硬拦截**（超出预算 → 减量重下或放弃）。

#### B4. LLM 信号量超时降级放行

`_sem_acquire` 等待超时后放行 → 短时并发可超 3，给网关带来限流/排队压力；陈旧 10min 清理是兜底而非根治。网关 glm-5.3-flash 单轮已 85~130s，放大该风险。

#### B5. 重复沿用旧结论可能带旧结构锚

`_find_recent_suggest` 沿用 3h 内结论（2026-09-14 由 24h 收窄，脱节风险随之下降），价格区校验（现价 ∈ sl~tp1）兜底一部分，但旧结论的止盈锚可能仍与最新结构脱节。
