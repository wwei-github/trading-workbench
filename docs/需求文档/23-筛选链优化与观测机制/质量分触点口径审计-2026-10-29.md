## 1. 触点降格：深回踩在均线收敛期拿不到豁免（P1，实测）

### 1.1 现象

`trigger.py` 用"命中触点中优先级最高的一个"作为标注：

```python
# trigger.py:85-87
TOUCH_ORDER = (
    TOUCH_RETEST, TOUCH_SWING, TOUCH_EMA21, TOUCH_EMA21_4H, TOUCH_EMA55, TOUCH_EMA144,
)

# trigger.py:1070
touch_ref = next((r for r in TOUCH_ORDER if r in touches), None)
```

ema21 排在 ema55 / ema144 之前。`_probe_touches` 会记录**所有**命中的触点，但标注只取第一个；而质量分的豁免条件是 `touch_ref ∈ DEEP_PULLBACK_REFS`（`technical.py:1061`），于是降格后豁免不生效。

### 1.2 触发条件（**不是必然**）

多头深回踩命中 ema144 的几何条件是 `low ≤ EMA144 ≤ close`（`trigger.py:603`），同时命中 ema21 还需 `low ≤ EMA21 ≤ close`。两式联立：

```
close − low ≥ EMA21 − EMA144
```

即**单根 K 线（low→close）的振幅必须大于两条均线的间距**。

- 趋势健康时 ema21 与 ema144 间距常远大于单根振幅 → 不会降格；
- 深回撤后期 / 震荡收敛时两线贴近 → 高发；
- 而均线收敛恰恰是 `range_score` 命中的场景，因此影响仍显著，但属于**条件性高发，不是必然**。

### 1.3 实测复现

构造 300 根缓涨（+0.02/根，人为让均线收敛）+ 一根长下影插针（`low=94.0`、`close=96.0`），跑真实 `_probe_touches`：

```
EMA21 / EMA55 / EMA144 = [95.8, 95.46, 94.57]
插针根 low / close = 94.0 96.0
启用触点 = ('retest', 'swing', 'ema21', 'ema21_4h', 'ema55', 'ema144')
命中触点 = {'ema21': 95.8, 'ema55': 95.46, 'ema144': 94.57}
实际标注 touch_ref = ema21
是否命中深回踩均线 = ['ema55', 'ema144']
→ 豁免生效 = False
```

该样本三条均线间距 0.3~0.9（高度收敛）。换成斜率 0.2/根（间距约 3~6），单根振幅不足以覆盖两条线，降格不会发生。

### 1.4 后果

降格后该根：

1. 拿不到 `risk_vote`(−6) 与 `r2_low`(−5) 的豁免；
2. 还要额外过**仅 ema21 专属的 1H 结构门**，不过门再 −15（`trigger.py:1084-1086`）。

同类降格还发生在两处：`retest` 优先级第 1（深回踩点常与前低破位价重合）、`ema21_4h` 排在 1h `ema21` 之后（1h ema21 不在豁免集合）。

### 1.5 关键缺口：降格不可观测

被标成 ema21 后：

- `scan_results.touch_ref` 只有 `ema21`；
- `quality_parts` 只有分项，**不记录"本根还命中了哪些触点"**。

因此现在无法量化降格比例，修复前后也无法对比。**先落观测、再改判定**：

| 方案 | 成本 | 说明 |
|---|---|---|
| `quality_parts["deep_hit"] = bool` | 低（仅分项 dict） | 推荐：布尔键可直接 `jsonb_exists` 统计；如需细分再附 `touches` 数组（数组不能用 `jsonb_exists`，要用 `@>`） |
| 新增 `pending.deep_touch` 列 | 中（`database.py` ALTER + 三处返回点） | 仅在直接做修复时需要 |

观测 7 天后判读：

```sql
SELECT touch_ref AS ref,                       -- 独立列（models/scan.py:49），不在 quality_parts 里
       jsonb_exists(quality_parts, 'deep_hit') AS deep_hit,
       count(*) AS n
FROM scan_results
WHERE created_at >= now() - interval '7 days'
GROUP BY 1, 2 ORDER BY 1, 2;
```

### 1.6 若最终要修

豁免判定与展示分离（`TOUCH_ORDER` 不动，前端标签/`position_ref` 依赖它）：

- `_probe_touches` 已有 `touches`，在 `detect_trigger` 的三个返回点（当根确认 `trigger.py:1130+`、次根确认 `1225+`、upsert `1257+`）各加一个 `deep_touch` 布尔；
- `compute_quality_score` 判定改为 `deep_touch or touch_ref in DEEP_PULLBACK_REFS`（保持向后兼容）；
- pending 侧 `PendingEntry`（`models/scan.py:319-327`）现只有 `touch_ref / ema21 / quality_score / votes_json`，无独立布尔列——需加列或塞入 `votes_json`（后者语义不符，不建议）。

副作用需明示：用 `deep_touch` 判定会把"结构位 + 深均线重合"（retest/swing 同根触及 ema144）的样本一并纳入豁免，范围大于当前只按标注判定的口径。

## 2. 基础分对深回踩偏低（P1，反推）

```python
# technical.py:1516-1517
same_n = (votes["bull_n"] if direction == 1 else votes["bear_n"]) if votes else 0
score = 50 + same_n * 10  # 0/1/2/3 → 50/60/70/80，与原刻度一致
```

### 2.1 不要用"票必转向"论证（初版错误）

初版写"深回撤时 1h 方向票大多已转向 → same_n 低"，与项目自身文档矛盾：

> `trigger.py:585-589`：价格深跌到中期/长期均线通常已打翻 1h 方向票……故「慢速深回撤」实际几乎不产生信号，仅「插针式触及」（单根影线插到均线、收盘仍强、**1h 票未转向**）可穿过。

即**能出信号的深回踩恰恰是票未转向的那批**，`same_n` 未必低。当前论证改为从均分反推。

### 2.2 反推

ema144 候选 14 天均分 58.7。把已知命中项加回：

```
58.7 + risk_vote 6×0.8 + range 8×0.8 ≈ 72.7  =  base + htf + volume + 其它
```

若 `htf` 取 +5~+10、`volume` +5（深回踩常缩量，也可能 0），则 **base 中位约 58~63**，即 `same_n` 多为 1（base 60）而非 0。

结论仍成立但程度减弱：**base 60 的样本，豁免 −6/−5 再叠 −4 震荡后约 61，只是勉强过线**；真正危险的是 base 50 的少数（`same_n=0`），它们豁免后仍不足 60。

### 2.3 分数示意（**未计入** htf / shadow / zone 加分）

| 情形 | 计算 | 结果 | 过 60 |
|---|---|---|---|
| base 50 + 放量 5 − 震荡 4 | 51 | 51 | 否 |
| base 50 + 放量 5 − 震荡 4 + 企稳 7 | 58 | 58 | 否 |
| base 60 + 放量 5 − 震荡 4 | 61 | 61 | 勉强 |
| base 60 + htf 10 + 放量 5 − 震荡 4 | 71 | 71 | 是 |

上表只用于说明 base 的影响量级，不代表实际分布（真实候选还会带 htf / zone / stabilize 项）。

## 3. 单一绝对 `quality_floor` 与触点分布不等价（P1）

| 触点 | 均分（14 天线上） | 60 分线含义 |
|---|---|---|
| retest | 90.7 | 几乎无约束 |
| swing | 80.9 | 宽松 |
| ema21 | 76.4 | 正常 |
| ema144 | 58.7 | 生死线 |

**豁免后 ema144 的预期均分**（初版写死 66.7，本版改为区间）：

```
58.7 + 6×0.8 (risk_vote) + 4×0.8 (range 半额) = 66.7   ← 未计 r2_low
58.7 + 6×0.8 + 4×0.8 + 5×0.8 (r2_low 假设同为 80%) = 71.5
```

即 **66.7 ~ 71.5**。注释只给了 risk_vote 与 range 各 80% 的命中率，`r2_low` 命中率未记录，故取区间而非点值。

两点佐证：

1. `config.QUALITY_FLOOR`（`config.py:486`）的依据写的是「分水岭在 80」（<70 段 −0.056R/笔、70-79 段 −0.050R/笔 vs 80-89 段 +0.260R/笔），线上实际值却是 60（docs/23 §6 T0 实测）——按依据，60-79 段落本就是负期望，设 60 会放行这批。
2. `scanner.py:1158-1161` 自述：「回踩与突破在同一配额里竞争，回踩因质量分基数低被结构性挤出（spec F4）」；`quota_pool/quota_rank` 目前**只记录不改变分发**，实际分配仍是质量分全局前 N。

**建议**：短期给 ema55/ema144/ema21_4h 单独的 floor（如 55）；中期改池内分位排名。

## 4. `box −15` 与 `range`/`r2_low` 同源重复计罚（P1，纯口径）

```python
# technical.py:1640
_add("box", PULLBACK_BOX_PENALTY)   # -15
```

三条判据都是"横盘 / 无推进"的几何代理：

| 项 | 判据 | 分值 |
|---|---|---|
| `range` | 1h 三线收敛 / 55-144 分离史过近 / ADX<18 / 波动扩张 | −4（本次半额） |
| `r2_low` | 24 根收盘线性度 R²<0.4 | −5（本次对深回踩豁免） |
| `box` | 20 根箱宽 <3×ATR 且实体平均重叠 ≥0.6 | −15（未动） |

本次只处理了 `range`（半额）与 `r2_low`（豁免），`box` 仍满额。**对深回踩后横盘的样本，扣分结构从（−5 −15 −8）变成（0 −15 −4）——是净改善，不是恶化**（初版曾推断"可能更差"，属错误，已纠正），但同一事实被计罚两次的结构性问题依旧存在。

**建议**：先按触点统计 `jsonb_exists(quality_parts,'box')` 的比例与该组的已平仓 PnL；若深回踩 + 箱体组的期望不差，对深回踩同样半额或豁免。这是唯一**不需要 schema 变更**的结构性改善项。

## 5. `stabilize` 的 MACD 零轴项 −4 同样是"形态必然"（P1，新发现）

```python
# technical.py:1327-1329
else:
    mod -= 4
    items.append("MACD动量不确认-4")
```

`stabilize` 在三条路径下都会被调用（当根确认 `trigger.py:1137`、次根确认 `trigger.py:1215`、upsert `scanner.py:687`），其 MACD 项判定为：

- 同向 +5（`pullback_hold` 回踩零轴不破）/ +4（零轴同侧）；
- **不同向 −4**。

深回踩到 ema55/ema144 做多时，价格必然已跌至零轴下方（DIF<0 → `below`，dir=−1），与 direction=+1 不同向 → **−4**。这与 `risk_vote`(−6)、`r2_low`(−5) 是同一类：滞后动量指标在深回撤时必然逆向。

线上方向票关已关闭（docs/23 §6 T0：`direction_vote_gate_enabled=false`），MACD 逆向不会被前置门拦下，因此这 −4 **确实会作用到深回踩候选**。

**建议**：与 risk_vote/r2_low 一并纳入深回踩豁免（改动一行），或先按触点统计 `quality_parts->>'stabilize'` 分布与分档 PnL 再决定。

## 6. 放量阈值硬编码，不跟随筛选配置（P2）

```python
# technical.py:1545
if volume_ratio(klines) >= 1.2:
    _add("volume", 5)
```

筛选页可改 `flt.breakout_vol_ratio`（默认 1.2），质量分恒用 1.2。用户调到 1.5 后，trigger 用的 1.5、质量分给 +5 用的 1.2 → 同一概念两套口径，+5 变成不可解释项。

docs/23 §1.5 T11 已列「顺手把 volume 阈值接回 `flt.breakout_vol_ratio`」，至今未做。

**建议**：`compute_quality_score` 增加 `vol_ratio_min: float = 1.2`，`scanner` 两处调用传 `flt.breakout_vol_ratio`（默认值保证旧调用方零改动）。

## 7. 放量/缩量阈值边界不统一（P2，观察项，**不是重复计罚**）

初版曾把这项定为"比 range 更典型的重复计罚"，复核后不成立：

- `volume` 项（`technical.py:1545`）用的是**信号根**（确认根）量比，≥1.2 加 +5；
- `stabilize` 的量能项（`technical.py:1302-1307`）用的是**触碰根（Stage-1）**量比，>1.5 **−5**、<0.8 **+3**；
- 且当根确认与 upsert 路径显式传 `volume_semantics=False`，该项根本不执行。

两者评估的是不同根，语义也不同（Stage-1 放量下跌是抛压，确认根放量上涨是承接），设计上成立。

遗留问题只有一点：**1.2 / 1.5 / 0.8 三个阈值彼此独立、且 1.2~1.5 区间"只加不罚"缺少依据**。建议在代码注释里记录该区间的取舍理由，暂不改行为。

## 8. `swing` / `retest` 是否同属"形态性惩罚"（待数据）

逻辑上与 ema55/ema144 同源：回踩摆动防守位（做多=前低 HL）或突破回测位时，SuperTrend 同样逆向、24 根线性度同样可能被打断。

数据上 swing 均分 80.9，说明多数样本没被打到——可能因为结构位回撤较浅，R² 未破 0.4、SuperTrend 未翻转。

判读（用 `jsonb_exists` 而非 `?`，后者在 SQLAlchemy/psycopg 参数化下会与占位符冲突）：

```sql
SELECT touch_ref,
       count(*) AS n,
       avg((quality_parts->>'total')::numeric) AS avg_total,
       sum(jsonb_exists(quality_parts, 'risk_vote')::int) AS with_risk_vote,
       sum(jsonb_exists(quality_parts, 'r2_low')::int)    AS with_r2_low,
       sum(jsonb_exists(quality_parts, 'range')::int)     AS with_range,
       sum(jsonb_exists(quality_parts, 'box')::int)       AS with_box
FROM scan_results
WHERE created_at >= now() - interval '14 days'
  AND touch_ref IS NOT NULL
GROUP BY touch_ref ORDER BY n DESC;
```

若 swing 的 `risk_vote`/`r2_low` 命中率显著大于 0，且这两组已平仓 PnL 不比同触点其它样本差，才值得一并豁免。

## 9. pending 快照与最终候选的分数漂移（P2，可观测性）

| 阶段 | 调用 | 口径 | 缺失项 |
|---|---|---|---|
| 触碰当根 → upsert | `scanner.py:687-694` | `PULLBACK_CONFIRM` + `klines` | 无 `pattern` → `zone`（+3/点）与 `shadow` 不加分 |
| 次根确认 | `scanner.py:722+` | `PULLBACK_CONFIRM` + `pattern` | 完整 |

后果：

- 待确认池展示的 `quality_score` 系统性低于同一候选的最终分；
- pending 分数不进 `quality_floor`（`apply_quality_floor` 只作用于 hits，`scanner.py:818/1145`）；
- 复盘若混用两批分数会低估 pending 阶段。

建议：`quality_parts` 增加 `stage` 键（`pending` / `confirm`），避免统计时混算。属观测项，不改排序。

## 10. 注释与实现矛盾（P3）

`technical.py:813` 写：

> - bull_dip / bear_rally：宏观逆侧过渡态恒放行（质量分兜底）

但 `htf_context` 的 `block_both` 实际把过渡态拦在 scanner 前置门（见 `technical.py:578-583` 与 `923`：放行白名单只有 `aligned_*` 与 `*_recover`）。因此质量分里 `STATE_QUALITY` 的 `bull_dip/bear_rally = (5, −6)` 与 `htf_macro −4` 线上不可达，只对旧口径回放脚本生效。

危害：读代码会误以为深回踩做多（牛内回调）还要额外 −6/−10，从而误判豁免幅度是否够。

## 11. 复现方法（§1 实测脚本）

```python
import sys; sys.path.insert(0, "backend")
from app.services.scan_filters import ALL_TOUCH_REFS, ScanFilters
```
