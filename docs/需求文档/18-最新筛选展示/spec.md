# 最新筛选展示（待确认池 · 最新筛选 Tab）

> 2026-10-28。需求方：用户。代码：`frontend/src/components/LatestFunnelPanel.tsx`、`backend/app/api/scan.py::scan_funnels`。
> 背景文档：[16-筛选链路审计与优化](../16-筛选链路审计与优化/spec.md)（漏斗 19 关口径与实测数据）。

---

## 0. 摘要

在「待确认池」新增「最新筛选」页签，回答三个问题：

| 问题 | 呈现 |
|---|---|
| 这一轮各关卡各拦了多少币 | 吸顶条 100% 堆叠条 + 关卡卡片（含占比环） |
| 每个关卡卡的是**哪个条件**、具体哪些币 | 点关卡开抽屉，**按卡住原因分组**，组内列币种 |
| 0 命中是常态还是恶化 | 底部 24 轮时序（按 8 组堆叠 + 每轮命中数） |

三个明确删掉的：**「固定展开」开关**（吸顶条随滚动自动收起）、**顶部「展开原因榜」**（与卡片 5 项内容 100% 重复，占 280px 最贵空间）、**逐币列表**（已有「筛选漏斗」「无触发」两个页签负责）。

## 2. 方案选型（A–E）

| 方案 | 形态 | 判定 |
|---|---|---|
| A 关卡瀑布表 | 行=关卡，列=拦截数/占比/累计/示例币 | 信息密度最高，但「一眼」能力弱；作为抽屉内形态被吸收 |
| B 阶梯漏斗 | 19 关合并 6 组，层宽∝剩余 | 出候选为 0 时形状塌陷，观感误导 |
| **C 卡片矩阵** | 每关一卡：占比环+拦截数+子原因+示例币 | **采用**（主视图） |
| **D 堆叠条+原因榜** | 100% 堆叠条 + 原因表格 | 堆叠条与 KPI **采用**（吸顶常驻）；原因表格**删除**（§3.2） |
| **E 24 轮时序** | 逐轮堆叠柱 + 命中数 | **采用**（趋势区） |

## 3. 最终布局

### 3.1 三段式

```
┌─ 吸顶条（sticky，滚动自动收起）────────────────────────────┐
│ ● 10-28 10:00 最近一轮扫描        518 币池 │290 进管线│0 出候选│14 待确认│0 命中 │
│ ███████ 228 ████ 126 ██ 82 ▂28 ▁19 ▁19 ▏2        共 504 次拦截 │
│ 主要卡点 池过滤 228（成交额218·黑名单8）｜ 其次 4h背景门 126（缠绕83·走平28） │
└───────────────────────────────────────────────────────────┘
┌─ 卡片矩阵（按拦截数降序）──────────────────────────────────┐
│ 池过滤 228  4h背景门 126  拐头锁 82  触发层 40 …             │
└───────────────────────────────────────────────────────────┘
┌─ 最近 24 轮（堆叠柱 + 命中数，点柱回看）─────────────────────┐
└───────────────────────────────────────────────────────────┘
```

- **吸顶条折叠**：`IntersectionObserver` 监哨兵，滚出视口即 `compact` —— 堆叠条 24px→6px、隐藏 KPI 标签与「主要卡点」行、数字 19px→15px，高度 46px。**不提供"固定展开"按钮**：常驻区只该在需要时占位。
- **栈段 ↔ 卡片联动**：`hover` 一个，其余置灰（`opacity .5`/`.32`），同一组键 `hot`。
- **点栈段或卡片** → 抽屉；**点时序柱** → 该轮（`activeIdx`），吸顶条出现琥珀色 banner「正在回看 … · 命中 N · 4h门 N · 拐头锁 N」+「回到最新一轮」。

### 3.2 为什么删掉「展开原因榜」

1. **内容 5/5 重复**：关卡名、拦截数、占拦截%、构成（"缠绕 83 · 走平 28"）、示例币 —— 与卡片逐项相同，排序同为"拦截数降序"，不是"摘要→详情"而是同一数据的第二种排版。
2. **占最贵的空间**：展开 280px，在 768px 视口占 36%，正好挤掉它本该保护的时序区。
3. **差异化价值已被承担**：「5 行横向比较」卡片 3 列约 200px 本就同时可见；「整体比例」由堆叠条承担。
4. **制造双份真相**：改分组/排序忘了同步表格，会出现两个不一致数字。

保留「主要卡点 … 其次 …」一行 —— 它是**结论句**，不是可替换的表。

## 4. 抽屉：按原因分组 + 币种 K 线

```
4h 背景门 · 126 个币   按卡住原因分组
────────────────────────────────────
[搜索币种…]
┌──────────────────────────────────┐
│ 4h 状态缠绕（tangle）：ADX 14.2、  │
│ 21/55 均线间距 0.03%、价格与       │
│ EMA144 缠绕 1 次 → 不做方向       │
│ ×83   ETH  SOL  BTC  …           │
├──────────────────────────────────┤
│ 4h EMA144 斜率走平（flat）        │
│ ×28   DOGE  XRP  …               │
└──────────────────────────────────┘
```

- **原因来源**：优先 `funnel_json.details[symbol]`（逐币判定文本，`；` 分段逐行显示）；缺失时回落到关卡口径说明（`STAGE_META[stage].hint`），并在标题上标注该组计数只为该关卡的子集。
- **为什么按原因分组而不是按币列**：用户的原话是"原因要展示清楚，具体是哪个条件被卡死不过"——同一关卡下的 83 个币往往**共享同一条判定语句**（如 tangle 的证据三元组），按原因聚合才不会把同一句话重复 83 遍；差异只在币名上。
- **币种点击** → `Modal` + `KlineChart symbol limit=500`（高 640px），看完 ESCC/关闭回抽屉。

## 5. 数据接口

| 接口 | 用途 | 回什么 |
|---|---|---|
| `GET /api/scans/funnels?hours=24`（**新**） | 时序区一次画 24 柱 | `{hours,count,items[]}`，每项 `scan_id/created_at/hit_count/universe/scanned/errors/candidates/pending_pool/stages/htf_states/gate_4h_reasons`；**不含 rejects/details**（体积大） |
| `GET /api/scans/{id}/funnel` | 当前轮明细 | `{funnel: FunnelData|null}`，含 `rejects`（symbol→关卡）与 `details`（symbol→文本） |

`hit_count` 用 `scan_results` 按 `scan_record_id` 聚合（不依赖 `scan_records.hit_count` 列）。`created_at` 回 naive UTC ISO（无 `Z`），前端补 `Z` 再转本地，避免被当成本地时间少 8 小时。

## 6. 口径与边界

1. **历史轮次无币种清单**：`/funnels` 不回 `rejects/details`，回看历史轮时卡片只显示计数（点击提示"历史轮次未保存币种清单"）。
2. **`details` 覆盖不全**：实测一轮 504 条被拒明细中 `details` 只有 129 条（池过滤阶段在指标管线之前被剔除，没有判定文本），这些币回落为关卡口径说明。
3. **分组是"语义分组"不是"数量分组"**：`GROUPS` 顺序固定（池过滤→4h背景→拐头锁→触发层→待确认→震荡→方向白名单→质量分），卡片与堆叠条**按数量降序**渲染，图例保持固定序，避免跨轮对比时颜色跳位。
4. **19 个关卡代码 → 8 组**：`liquidity/untradable/new_coin/risk_tier/blacklist` 合为"池过滤"（都在指标管线之前发生，追问"哪一关"意义有限）；`no_trigger/no_touch/leg_gate/golden_no_context/no_golden/insufficient_bars` 合为"触发层"。
5. **一轮 0 命中是常态**：近 7 天按小时命中 07:00=30 / 10:00=21 / 14:00=59，而 19:00–02:00 常为 0–1。时序区的"·"就是为这个认知服务的（0 显示「·」而非空白，避免读成数据缺失）。

## 9. 明确不做

1. **不把「原因榜」做成表格**（§3.2）。
2. **不做"固定展开/自动收起"开关**：自动收起已够，多一个按钮多一处状态。
3. **不做逐币列表**：已有「筛选漏斗」（全量逐币 + 关卡筛选 + 搜索）与「无触发」两个页签。
4. **不在 `/funnels` 里回 `rejects/details`**：24 轮 × 500 币 × 判定文本会让响应达到 MB 级；历史轮不需要下钻。
5. **不按 `stages` 里的 19 个代码平铺**：图例 19 项无法扫读。
