## 1. 背景与目标

当前合约系统是**单策略硬编码**：4H 趋势定方向 → 1H K 线入场。用户提出三个诉求：

1. 以当前系统为蓝本，新增「日K定方向 → 4H 开单」的策略变体，单笔止损金额按风险基数的 **10%** 计算（现行为 3%）。
2. 当前版本要能完整保存、随时回退。
3. 两套策略能否**同时在线**，各自独立开关。

目标：

- v1 用 git tag 永久冻结，可独立构建与回退。
- v2 作为大版本，参数与 v1 隔离。
- 两套策略可在同一套后端内并行运行，各自可开关、可分别限额。

## 2. 术语

| 术语 | 含义 |

| 策略版本 | `v1_4h_1h`（4H 趋势 / 1H 入场 / 风险 3%）、`v2_1d_4h`（日K 趋势 / 4H 入场 / 风险 10%） |
| 风险基数 | 钱包余额首位数取整，上限 5000，不超过本金 |

| 策略内单数 | 单个策略允许的最大在跑单数 |
| 账户级合并 | 两策略共同消耗同一份账户资源（保证金、熔断账本、热度） |

## 5. 方案设计

### 5.1 版本模型

**git tag 是唯一版本号**，不做多层版本抽象。

| 层 | 载体 | v1 | v2 |
|---|---|---|---|
| 版本号 | git tag | `v1.0.0` | `v2.0.0` |
| 镜像 | `IMAGE_TAG` | `v1.0.0` | `v2.0.0` |
| 策略标识 | 代码常量 `STRATEGY_VERSION` | `v1_4h_1h` | `v2_1d_4h` |

规则：

- `STRATEGY_VERSION` **写在代码里**，不从环境变量读，使「v1 镜像跑 v2 参数」物理上不可能。
- 只打 annotated tag，message 内嵌版本事实：

  ```
  v1.0.0 — 4H趋势定方向 + 1H入场基线
  APP=1.0.0
  STRATEGY=v1_4h_1h
  RULE=v2026-10-27
  ```
- tag 一旦发布不可修改、不可删除、不可在其上继续提交。修复走 `release/v1` 分支，发 `v1.0.1`。
- 版本号语义：MAJOR = 策略大版本，MINOR = 规则批量变更，PATCH = 缺陷修复。

**已执行**：tag `v1.0.0` 打在 `d16ae60`，分支 `release/v1` 指向该 tag（均在本地）。

### 5.2 v2 策略参数

| 维度 | v1_4h_1h | v2_1d_4h |
|---|---|---|
| 趋势周期 / 根数 | 4h / 600 | 1d / 600 |
| 趋势数据门 | 200 根 | 200 根（P2 观察后决定是否降到 155） |
| 入场周期 / 根数 | 1h / 240（实际取 max(300)） | 4h / 400 |
| 斜率回看 / 走平阈值 | 20 根 / 0.5% | 20 根 / 2.0% |
| 纠缠判定 | `|EMA21−EMA55|/price < 0.1%` | `|EMA21−EMA55| < 0.15×ATR` |
| 重复信号窗口 | 3h | 12h |
| 待确认窗口 | 4 根 | 3 根 |
| 挂单 TTL | 60 min | 240 min |
| 复盘观察窗 | 24h | 120h |
| 扫描节拍 | 每小时 `:00` | `:05`，UTC 0/4/8/12/16/20 |

趋势状态机（EMA21/55/144 + ADX + ATR，11 态）与前置门（仅放行 `aligned_bull` / `aligned_bear`）**完全复用**，不改逻辑。

> 纠缠判定改 ATR 归一化是必须的：0.1% 绝对带宽在日K几乎永不触发，纠缠态会失效，震荡行情会被误判为 aligned。

### 5.3 风险口径与冲突处理

**口径**：单笔止损金额 = 风险基数 × 10%。风险基数仍按 `_capital_base`（首位数取整、上限 5000、不超过本金）。

| 钱包 | 风险基数 | v1 单笔（3%） | v2 单笔（10%） | 10% 实际占权益 |
|---|---|---|---|---|
| 1,000 | 1,000 | 30 | 100 | 10% |
| 5,000 | 5,000 | 150 | 500 | 10% |
| 50,000 | 5,000（封顶） | 150 | 500 | 1% |

必须同步处理的三个冲突：

| 冲突 | 问题 | 处理 |
|---|---|---|
| 日熔断 | 9% = 450 U < 单笔 10% 止损 500 U，一笔满损当天即停 | 日熔断抬到 25% |
| 杠杆下限 | 4H 单止损距离常 3~8%，`TRADING_LEVERAGE_MIN=8` 对应强平距离约 10.5%，超 8% 被拒单 | 下限降到 3，`max_stop_pct=8%` |
| 近锚折价 | `NEAR_ANCHOR_RISK_FACTOR=0.7` 使近锚单实际 7% | 设为 1.0 |

### 5.4 策略开关与配置表

新增 `strategy_configs` 表，每行一个策略，`enabled` 即开关：

| 字段 | 说明 |
|---|---|
| `version` PK | `v1_4h_1h` / `v2_1d_4h` |
| `enabled` | 是否启用 |
| `trend_interval` / `entry_interval` | 周期 |
| `trend_window` / `entry_window` | 拉取根数 |
| `risk_pct` | 单笔风险百分比 |
| `max_open_trades` | 策略内单数上限 |
| `pending_ttl_min` | 挂单存活分钟 |
| `repeat_window_hours` | 重复信号窗口 |
| `review_obs_hours` | 复盘观察窗口 |
| `scan_minute` / `scan_hours` | 调度 |

种子数据：

| version | enabled | trend | entry | risk | max_open | ttl | scan |
|---|---|---|---|---|---|---|---|
| `v1_4h_1h` | 是 | 4h | 1h | 3% | 3 | 60 | `:00` 每小时 |
| `v2_1d_4h` | 否 | 1d | 4h | 10% | 2 | 240 | `:05`，UTC 0/4/8/12/16/20 |

> v1 的 `max_open` 从 5 降到 3：与 4H 的 2×10% 合并后，理论上限从 35% 降到 29%，低于日熔断 25% 不会长期穿透。

### 5.5 并行调度

运行时形态：

```
celery beat（单个）
  └─ hourly-scan（每小时 tick）
       └─ run_scan_task
            ├─ 读 strategy_configs WHERE enabled
            ├─ 按 scan_hours 判断本轮该跑哪些策略
            └─ 逐策略串行扫描，各自落 ScanRecord(strategy_version)
```

**8 点冲突处理**（北京 8 点 = UTC 0 点，1H 与 4H 同时收盘）：

| 冲突 | 处理 |
|---|---|
| 交易所限频 | 1H `:00`、4H `:05` 错峰 |
| 并发打满 worker | Redis `SETNX scan_lock`，TTL 10 分钟；拿不到锁跳过本轮并记 `skipped: locked` |
| AI 配额争抢 | `ai_max_per_scan` 拆成按策略两个池 |
| 同币信号冲突 | 按优先级仲裁：4H > 1H；同级取 `quality_score` 高者；落败方记 `blocked_by:<strategy>` |

**不能靠先到先得**：扫描顺序固定后，配置里排前面的策略永远赢，等于固定偏好。

### 5.6 开单与分层限额

| 层级 | 作用域 | v1 | v2 | 说明 |
|---|---|---|---|---|
| 单笔风险 | 策略 | 3% | 10% | 独立 |
| 策略内单数 | 策略 | 3 | 2 | 独立 |
| 账户总单数 | 账户+环境 | — | — | 合计 5，冗余校验 |
| 日/周/月熔断 | 账户+环境 | **合并** | **合并** | 触发后两策略同时停开仓 |
| 组合热度 | 账户+环境 | **合并** | **合并** | 0.25 |
| 币种占用 | 账户+环境 | **互斥** | **互斥** | 同币只能一个策略持仓 |

熔断阈值（以风险基数为分母，合并计算当日已平仓净亏）：

| 熔断 | 现值 | 双策略 |
|---|---|---|
| 日亏停开仓 | 9% | 25% |
| 周回撤减速 | 15% | 35% |
| 月回撤停开仓 | 25% | 50% |

校验：v1 三单满损 9% + v2 两单满损 20% = 29% 理论最大，日熔断 25% 会在第 3 笔大亏时先触发。

**同币处理**：保持全局互斥（现 `trade_engine.py` L510-L528 已有硬拦）。补充三件事：

1. 拦截原因区分 `blocked_by_symbol_same_strategy` / `blocked_by_symbol_other_strategy`。
2. 被占用的信号仍然落库，用于统计「4H 占用导致 1H 错过多少机会」。
3. 前端在 4H 持仓卡片标注「占用中，1H 同币信号已跳过」。

### 5.7 巡检与移动止损

现状是读单值 `kline_interval` 拉 K 线，两策略共用会互相污染：设 1h 则 4H 单被噪声扫损，设 4h 则 1H 单移损滞后 4 小时。

处理：

1. `settle_trades` 按 `TradeRecord.strategy_version` 分组，每组用 `strategy_configs.entry_interval` 拉 K 线。
2. **巡检频率不变**（每小时），对账、补挂 SL、识别外部平仓必须高频。
3. **移损按周期触发**：4H 单只在新的 4H K 线收盘后才重新计算跟进价；判断方式是比较 `上次移损时的 K 线收盘时刻` 与当前周期上一根收盘时刻。
4. 持仓时长告警按策略：1H 12h/24h，4H 48h/96h。

### 5.8 持仓导入

现状：`TradeRecord` 只有 `strategy_id`，无周期字段。

规则：

1. 导入接口增加 `strategy_version` 参数；两策略都启用时**必填**，只有一个启用时默认取它。
2. 导入后写入 `TradeRecord.strategy_version` 与 `entry_interval` 快照。
3. 无法判定来源的标记 `external`，按 4H 周期巡检（周期大、移损慢，不会误砍），前端高亮。
4. 导入单通常无 TP1/TP2，跟进逻辑兼容：无 TP 时只用结构止损，不触发保本夹紧。

## 8. 实施阶段

| 阶段 | 内容 | 准入 / 验收 |
|---|---|---|
| **P0** | v1 冻结（tag / 分支 / manifest）+ 版本常量 + `strategy_version` 列 + `/api/version` + `release.sh --tag` | 线上行为零变化；`/api/version` 三元组正确 |

## 9. 验收标准

| 项 | 标准 |
|---|---|
| 版本 | `v1.0.0` 可独立构建部署；`/api/version` 与镜像 tag 一致 |
| 开关 | 只开 1H / 只开 4H / 双开，三种状态行为正确 |
| 错峰 | 北京 8 点无并发扫描，锁生效有日志 |
| 互斥 | 同币已有 4H 仓时 1H 信号落库但不下单，原因可查 |
| 限额 | 4H 满 2 单后 1H 仍可开单；日熔断触发后两策略同时停 |
| 巡检 | 4H 单止损只在 4H 收盘后变动；1H 单不受影响 |
| 导入 | 必须选策略；`external` 仓位按 4H 巡检 |
| 复盘 | 两策略胜率/期望分开呈现，无混算 |

## 10. 回滚

| 场景 | 动作 |
|---|---|
| 版本异常 | `release.sh --tag v1.0.0`（先平仓撤单） |
| 仅参数不合适 | 页面改 `strategy_configs`，不动镜像 |
| 关闭某策略 | `enabled = false`，不影响另一策略在跑单的巡检 |
| 数据兼容 | 新列全 nullable；历史行 NULL 视为 v1 |

## 12. 不做

- 双栈容器并行（资源不足，beat 重复调度）
- 同币同向叠加 / 反向对冲
- 两套独立账户与独立熔断账本
- 策略间资金分配（同一账户共享保证金）
- UI 内热切换版本
