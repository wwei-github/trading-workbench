# 回踩命中改造方案（方向职责拆分）

- 状态：方案定稿待实施（2026-10-21）
- 关联：[链路审计 spec](file:///Users/wangwei/Documents/github/trading-workbench/docs/需求文档/06-四小时趋势一小时周期链路审计/spec.md)、[任务清单](file:///Users/wangwei/Documents/github/trading-workbench/docs/需求文档/06-四小时趋势一小时周期链路审计/tasks.md)、需求文档 05（回踩触点优化方案）
- 范围：只改筛选判据（`scanner` / `technical` / `scan_filters`）+ AI 提示词口径；**不含回测**，不含出场逻辑重构

## 1. 背景与证据

系统目标：**按 4h 趋势做 1h 周期的单子**。但当前筛选链中 `direction` 一个字段承担了两个互斥职责：

1. 4h 的**趋势方向**（做不做、做哪边）；
2. 1h 的**动量方向**（找哪边的入场形态）。

回踩入场的定义就是「价格逆着 1h 动量回到价值区」，而现有判据要求「1h 动量方向必须等于 4h 方向」。二者在几何上互斥：能同时满足的形态只剩「单根长影线插到均线、收盘拉回、三票来不及翻转」。

### 1.1 反事实重放数据（2026-09-20 ~ 10-12）

方法：339 个进入扫描池的币种，逐 1h 收盘，用当前生产函数（`htf_context` / `compute_indicator_votes` / EMA 触点 / `range_score`）重算。样本 101,875 个 (币种, 小时)，其中 4h 前置门通过 24,891 个（24.4%），几何触点 9,201 次。

| 触点 | 触点次数 | 票数不足 | 方向反转（flip） | 票数通过 | 通过率 | 被 range_score 杀 | 最终存活 |
|---|---|---|---|---|---|---|---|
| EMA21 | 4,335 | 2,062 (47.6%) | 218 (5.0%) | 2,055 | 47.4% | 1,387 (67.5%) | 668 → 15.4% |
| EMA55 | 1,738 | 697 (40.1%) | 693 (39.9%) | 348 | 20.0% | 275 (79.0%) | 73 → 4.2% |
| EMA21(4h) | 2,204 | 551 (25.0%) | 1,110 (50.4%) | 543 | 24.6% | 518 (95.4%) | 25 → 1.1% |
| EMA144 | 924 | 168 (18.2%) | 595 (64.4%) | 161 | 17.4% | 160 (99.4%) | 1 → 0.11% |

### 1.2 三条结论

1. **`direction_flip` 占比随回撤深度单调上升**（5.0% → 39.9% → 50.4% → 64.4%）：回撤越深，1h 三票越可能整体反向，「票数足够地反向」而非「票数不足」。
2. **`range_score` 是第二层放大器**：通过方向门的样本中，EMA144 有 99.4% 被它单独杀掉。
3. **深度回撤被结构性消灭**：EMA144 在 924 次几何命中中只存活 1 次（0.11%）。这不是阈值松紧问题，而是判据结构问题。

> 局限：单位为「(币种, 1h 收盘)」，同一段回撤跨多根 K 重复计数，属**每次扫描通过率**而非独立事件；`票数通过` 未叠加金K确认，是方向上界。本表证明「排除机制存在」，不证明「被排除的样本为正期望」。

## 2. 设计原则

| 职责 | 归属 | 说明 |
|---|---|---|
| 做不做、做哪边 | 4h `htf_context`（`aligned_bull/bear` + `direction`） | 前置门保持不变，4h 仍是唯一趋势权威 |
| 回踩入场定向 | **4h 方向**（新增） | 回踩是趋势内回调，方向必须跟趋势 |
| 1h 三票 | **确认度 / 质量分 / 仓位折扣**（新增） | 不再能否决定方向，只影响「信多少」 |
| 突破入场定向 | 1h 净差（保持现状） | 突破本身需要动量确认，保留 `votes` + `direction_flip` 硬门 |

## 3. 改动清单

### 3.1 不引入运行时开关

本次改造直接替换判据，不新增 `ScanFilters` / `config` 开关，也不保留旧分支（避免双口径长期并存与提示词漂移）。需要回滚时直接 `git revert` 本次提交。

### 3.2 `scanner.detect_indicator_candidate`：定向顺序调整（核心）

把「方向票关」与「方向冲突关」从**触发之前**移到**触发之后**，并只对突破类生效。

**原顺序**：票数关 → 净差定向 → 方向冲突关 → 逆势锁 → `range_score` 硬拒 → `detect_trigger`

**新顺序**：4h 定向（回踩/突破共用）→ 逆势锁 → `range_score` 只计算 → `detect_trigger` → 按触发类型分流校验（突破查票数，回踩只记分）

替换原票数关与定向段：

```python
votes = compute_indicator_votes(klines, htf_bg=htf_res)

# 4h 未给出方向（数据降级）→ 直接拒绝，不再回落到 1h 定向
if gate_dir is None:
    _reject("gate_4h")
    return None, ({"op": "expire", "reason": "direction_flip"} if pending else None)

# ── 定向：回踩与突破统一按 4h 方向；1h 票降级为确认度 ──────────────
direction = 1 if gate_dir == "long" else -1
same_n = (votes["bull_n"] if direction == 1 else votes["bear_n"]) if votes else 0
opp_n = (votes["bear_n"] if direction == 1 else votes["bull_n"]) if votes else 0
votes_ok = same_n >= DIR_VOTE_MIN
votes_flip = opp_n >= DIR_VOTE_MIN
```

4h 逆势锁（`STATE_LOCK_CONTRA`）保持原位；`aligned_*` 下它与新定向天然一致。

`range_score` 改为只计算值、不立即拒绝：

```python
rs, _rs_reasons = range_score(
    klines, gate_ev=htf_res.get("evidence") if htf_res else None)
```

在 `detect_trigger` 返回之后、白名单过滤与 `event_out` 写入之前插入：

```python
if trig is not None:
    if trig["type"] in (BREAKOUT, TREND_BREAKOUT):
        # 突破必须动量同向：沿用原两道关
        if flt.direction_vote_gate_enabled and not votes_ok:
            _reject("votes")
            return None, pending_op
        if flt.direction_conflict_gate_enabled and votes_flip:
            _reject("direction_flip")
            return None, pending_op
    # trigger_pullback_confirm：不否决，票数只进质量分

# 震荡闸门：突破类仍硬拒；回踩类降权不拒
range_penalty = False
if rs >= RANGE_SCORE_REJECT:
    if trig is not None and trig["type"] == PULLBACK_CONFIRM:
        range_penalty = True
    else:
        _reject("range_score")
        return None, ({"op": "expire", "reason": "range_score"} if pending else None)
```

**注意**：`event_out`（破轨事件）写入必须移到类型判定之后。否则在 1h 反向时按 4h 方向记录的「突破事件」会污染 retest 事实源。

#### 3.2.1 金K方向随之修正（无需改 `candlestick.py`）

金K层本身已经是「按方向找反转形态」的写法（[candlestick.py L662-L674](file:///Users/wangwei/Documents/github/trading-workbench/backend/app/services/strategy/candlestick.py#L662-L674)）：

- `GOLDEN_BULLISH = hammer / bullish_engulfing / morning_star / piercing_line`
- `resolve_golden_evidence(klines, wanted, patterns)` 先按 `p["direction"] == wanted` 过滤，再裁决
- `trigger.detect_trigger` 传入的 `wanted = "bullish" if direction == 1 else "bearish"`

所以**看涨吞没本身是被支持的**，问题在于 `wanted` 的来源：现状 `direction` 由 1h 方向票净差决定，回踩时 1h 偏空 → `direction = -1` → `wanted = "bearish"` → 系统在多头回踩的支撑位上寻找的是**看跌吞没/流星**（跌破延续信号），找到后又被 `direction_flip` 以「方向与 4h 相反」扔掉。这是双重错误：找错了形态，再否掉找错的结果。

改为 4h 定向后，`wanted` 自动变为 `"bullish"`，看涨吞没 / 锤形线 / 启明星 / 刺透线全部进入候选，**不需要修改 candlestick 检测器**。两点需知：

1. 吞没的实体基线门 `body2 ≥ 近 20 根中位实体 × 0.6`（[L216-L229](file:///Users/wangwei/Documents/github/trading-workbench/backend/app/services/strategy/candlestick.py#L216-L229)）保留——弱吞没仍被拒，属形态质量门，与方向无关；
2. 上影硬门已于 2026-10-16 删除，改为 `0/1/3/5` 梯度加分（`DECISION_SHADOW_BONUS_GRADES`），长上影的看涨吞没照常确认，只少加分；
3. 上线瞬间 pending 池中 `direction=-1` 的存量记录会因方向不符而过期（`window_expired` / `direction_flip`），属预期，不影响新信号。

### 3.3 `technical.compute_quality_score`：回踩单独的基础分

若只改定向，深回撤会因 `50 + direction*net*10` 得到 20 分（`net=-3`），排序垫底后被 `ai_max_per_scan` 配额挤掉，等于又死在配额上。

```python
if trigger_type == PULLBACK_CONFIRM:
    # 回踩：同向票数加分，反向票不扣分
    same_n = (votes["bull_n"] if direction == 1 else votes["bear_n"]) if votes else 0
    score = 50 + same_n * 10          # 0/1/2/3 → 50/60/70/80，与原刻度一致
else:
    score = 50 + direction * (votes["net"] if votes else 0) * 10
```

并把 `range_penalty` 作为入参传入，命中时 `score -= 8`。

### 3.4 `ai_analyzer.py`：提示词必须同步

筛选放行后，AI 看到 1h MACD 死叉 / RSI 42 仍会给低分或直接 `skip`，前面改动会被 AI 层吃掉。在 `_RULE_HTF_HARD` 之后追加硬规则：

> 回踩确认单（`trigger_pullback_confirm`）的定向以 4h 为准。1h MACD/RSI/布林与 4h 相反属于正常回撤，**不得据此降低推荐分或拒绝开单**；仅当价格结构跌破 4h 关键位（做多时 1h 收盘跌破 4h EMA144 且 4h 状态不再是排列）时才可拒绝。

门槛按触发类型分档：突破 `rec ≥ 70`，回踩 `rec ≥ 60`（依据：正式网 rec 60–69 段胜率 12.5% 主要来自突破单，需在观测期复核）。

### 3.5 线上配置核对

改代码不一定生效，实施前检查 `SystemConfig.scan_filters`：

| 配置 | 要求 |
|---|---|
| `allowed_triggers` | 必须包含 `trigger_pullback_confirm` |
| `pullback_touch_refs` | 必须包含 `ema21` / `ema55` / `ema144` / `ema21_4h` |
| `pending_confirm_window_bars` | 建议 4（现状） |
| `ema_touch_min_bars` | 200（现状） |
| `direction_vote_gate_enabled` / `direction_conflict_gate_enabled` | 保持 True |

### 3.6 下行阻塞点：RR 铁律会二次拦截

深回撤触点的结构止损更宽（常见 1.2~1.6×ATR）。`TP1_MAX_ATR=2.0` 且 `TP1_MAX_R=0`（R 腿关闭）时，RR = TP1距离/止损距离 会落到 1.25~1.6，被 `AI_RR_MIN=1.5` 拦下。**筛选放行后仍有相当一部分到不了下单。**

处理方式（按优先级）：

1. 回踩类单的 `rr_min` 分档到 1.2~1.3（独立配置项 `AI_RR_MIN_PULLBACK`）；
2. 或对回踩类放开 `TP1_MAX_ATR` 到 2.5（需同步调整 TP1 数量，避免 RR 与期望脱节）；
3. 不做：不允许以「放宽止损」换 RR。

### 3.7 执行层配套（不改判据）

深回踩是价格修复最快的一类，而当前「分析完成后不触发执行 + 1% 偏离门 + 每小时巡检」会让它们在下一小时因价格跑掉被 `blocked`。要让回踩真正成交到账户，需并行：

- `ai_tasks.run_ai_analysis_task` 分发完成后链式触发一次执行；
- 或把执行巡检恢复到 30min / 打开 `EVENT_EXEC_ENABLED`。

## 4. 安全阀（必须与改动同时生效）

样本量预期放大 10~100 倍，风险敞口同步放大，以下三条不允许缺省：

1. **回踩仓位折扣**：`votes_flip=True`（1h 反向 ≥2 票）时仓位 ×0.5；
2. **同向约束**：`SAME_DIRECTION_CAP` 0 → 6；
3. **组合热度**：`PORTFOLIO_HEAT_CAP` 0 → 0.06。

## 5. 验收标准（可观测，不做回测）

观察期 ≥2 周 / 影子 ≥30 笔，按 `RULE_VERSION` 严格分组，不与旧样本混算。

| 指标 | 目标 | 数据来源 |
|---|---|---|
| `trigger_pullback_confirm` 从 0 命中到非 0 | ≥20 笔/周 | `scan_results.signal_type` |
| 各触点 `reject_stage` 分布 | EMA144 的 `direction_flip` 占比从 64.4% 降至 <20% | `funnel_json` |
| 各触点最终存活率 | EMA55 ≥15%、EMA144 ≥5% | `funnel_json` |
| 回踩单占全部开单比例 | 20%~40% | `trade_records` |
| 回踩单确认形态分布 | 做多回踩中「看涨吞没/锤形线/启明星/刺透线」占比 >80%；**出现看跌吞没确认多头回踩 = 0**（方向回归检查） | `scan_results.pattern` |
| 回踩单 vs 突破单的 avg R / 胜率 | 观测期只记录，不作优劣结论 | `trade_reviews` |
| 成交率（信号→开仓） | ≥60%（不达标说明 3.7 未修） | 信号与订单对账 |

**观察期禁止的动作**：不得因为前 30 笔盈亏调整 RR/TP/仓位参数——样本未达统计门槛。

## 6. 回滚

无运行时开关。回滚方式为 `git revert` 本次提交，筛选链恢复旧口径（净差定向 + 触发前票数/冲突关 + `range_score` 硬拒）。涉及 `compute_quality_score` 与 AI 提示词的改动在同一提交内，一并回滚。

## 7. 明确不做

- 不关闭 `direction_conflict_gate_enabled` 全局：会连突破单一起放开逆势，混淆两类形态；
- 不全局放宽 `range_score`：其 +0.10R 证据来自旧通过集，全局放宽会用新样本否定旧结论；
- 不放宽 4h 前置门（`STATE_ALIGNED` 之外的状态继续禁开）；
- 不改突破路径的动量确认要求；
- 不允许用放宽止损宽度来满足 RR。

## 8. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 样本放大导致同向堆叠 | 单边行情集中回撤 | 第 4 节三条安全阀 |
| AI 层仍按动量打分拒绝 | 改动失效、命中率不升 | 3.4 提示词 + 分档门槛 + 观测 `skip` 原因分布 |

| 观察期样本不足就调参 | 过拟合新样本 | 第 5 节纪律 + `RULE_VERSION` 隔离 |
