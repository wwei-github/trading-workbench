# 01-币种筛选与扫描

> 现行版本：RULE_VERSION v2026-10-01（2026-10-01）。本文对照代码整理，以代码为准；历史拍板记录见 docs/archive/。

---

## 1. 概览

扫描是整个合约系统的入口：从全市场 USDT 永续合约中，按「流动性门槛 → 币种过滤 →
指标多数决定向 → 触发确认」的漏斗筛出候选信号，落库 `scan_results` 后按质量分
配额分发 AI 分析。设计原则（backend/app/services/scanner.py:1-15 模块 docstring）：

- **指标为主、信号为触发器**：方向判定权归 7 项技术指标多数决（与 AI 提示词的
  多数决规则同一把尺子），触发器只回答「此刻是否出现与候选方向一致的入场点」。
- **两段拉取省请求**：1h 六票预筛不达标不补拉 4h。
- **信号判定全部基于已收盘 K 线**（klines[-2]），同根 K 线同结果，与扫描时刻无关。

黑名单补充口径（blacklist_service.py）：

- B 层（盘口滑点实测 `market_slippage_estimate`，默认上限 0.3%）不在扫描阶段，

## 3. 扫描链路

### 3.1 入口：定时 vs 手动

| 维度 | 定时扫描 | 手动扫描 |
|---|---|---|
| 触发 | Celery beat `hourly-scan`（celery_app.py:48-52，每小时第 2 分钟，等 K 线收盘） | `POST /api/scans`（api/scan.py:54-70），有 running 记录时 409 |
| 记录 | `run_scan_task` 无 scan_record_id 时新建（scan_tasks.py:32-36） | API 先建 `scan_type="manual"` 记录再投递 |
| 重复命中抑制 | 生效：同 (symbol, signal_type) 在 `repeat_window_hours`（默认 3h）内已命中不落库（scanner.py:415-427、`_suppress_repeat_hits` scanner.py:590-621） | 不抑制（2026-09-20 拍板：手动 = 对最近已收盘 K 线的完整评估，与 :02 定时同根 K 线应得同样结果） |
| 飞书命中通知 | 发送（scanner.py:436-441） | 不发送（用户在场） |
| 满仓跳过 AI | 在跑单达 `max_open_trades` 时跳过本轮 AI 分发（`_slots_full` scanner.py:564-588，只统计 OPENED；查询失败按未满仓处理） | 不受限 |

防重三道闸（scan_tasks.py:46-93，仅定时）：

1. 已有 running 记录 → 本轮标 failed 跳过；
2. 10 分钟内已有 scheduled completed → 跳过（休眠唤醒后 beat 积压背靠背执行）；
3. UTC 小时锁：Redis `SETNX scan:hourly:{YYYYMMDDHH}`（TTL 2h），防 beat 双发 /
   消息重投导致「扫描命中」飞书通知双发（2026-09-28）。

### 3.2 单币判定链 `detect_indicator_candidate`

单币检测入口为 `detect_indicator_candidate`（scanner.py:133-244，2026-09-17 管线
重设计后已无 `_evaluate_symbol` 这个名字，部分旧文档沿用旧称），Scanner 与
watchlist.refresh 共用同一套逻辑与阈值。判定链逐步：

1. **votes6 预筛**（scanner.py:163-167）：1h K 线（`max(kline_window, 300)` 根）
   算 6 项指标票（MACD/布林/RSI/SuperTrend/ADX/OBV，technical.py:518-525）。
   `voted < 5` 或 `|net6| < 2` → 直接判中性返回 None（第 7 票也够不到 3，
   省 4h 请求）。活跃 pending 走前置过期 `expire(direction_flip)`（票崩）。
2. **4h 第 7 票**（scanner.py:169-176）：补拉 4h K 线 200 根算 `4h背景(EMA21/55)`
   票；拉取失败降级为无 4h 票，不中断。
3. **votes 终判**（scanner.py:177-178）：7 票 `voted < 5` 或 `|net| < 3` → 中性
   跳过（-2~+2 震荡不开单），pending 同样 `direction_flip` 过期。
4. **4h ranging 过滤**（scanner.py:180-191，2026-09-28）：`analyze_htf_background`
   （technical.py:409-461）ADX<20 判 `ranging` → 不进候选（连 AI 分析都不给，
   震荡市 EMA 反复交叉下 1h 信号胜率塌陷）；4h 复算失败降级放行。
5. **4h 方向一致门**（scanner.py:193-200，2026-09-28）：4h 有趋势方向
   （bullish/bearish，dir=±1）时 1h 信号方向必须一致——4h 看多只产生多头信号；
   纠缠（mixed，dir=0）不设限；拉取/复算失败降级放行。与 4h 冲突的活跃 pending
   不可能被确认，按方向失守过期。
6. **触发器 `detect_trigger`**（trigger.py:306-524，决策矩阵见 3.3）：命中则计算
   质量分（`compute_quality_score`，technical.py:672-729：基础分 50+|net|×7，
   4h 同向强 +10/弱 +5、反向强 -12/弱 -8，突破+ADX≥25 +5，量比≥1.2 +5，
   RSI 极端 -8，OBV 背离 -6），组装候选 dict（每币至多 1 个）。
   T1 突破触发在白名单过滤**之前**先写破轨事件动作（scanner.py:205-211）——
   破轨是市场事实，白名单只决定是否产生突破信号。
7. **触发类型白名单**（scanner.py:212-216）：白名单外类型不产生候选（连 AI 都不
   进），但 pending 处置照常执行（突破抢先 supersede、窗口过期 expire），保持
   回踩池状态机自洽。
8. **无触发** → 观察池（不落库，下轮重算）；触碰转 pending 的补 Stage-1 快照
   （质量分按回踩口径计，scanner.py:217-222）。

并发执行：`ThreadPoolExecutor(max_workers=BINANCE_CONCURRENCY=8)`（scanner.py:399）。
扫描线程只读快照与收集动作，所有落库由主流程统一执行（独立 session）。

### 3.3 触发器决策矩阵（trigger.py，docs/19 §4.1 + docs/22 触点）

方向 = 多数决符号（1 多 / -1 空）。信号判定全部基于已收盘 K 线（klines[-2]）；
pending 有效期 = 其 `stage1_candle_open` 恰为 klines[-3] 开盘时间（上一根已收盘
K 线，开盘时间精确比对，免疫扫描时刻漂移与轮次缺失）。

| 行 | 条件 | 结果 |
|---|---|---|
| T1a | 顺向长实体收盘越过最近**未破**摆动前高/前低（结构突破） | `trigger_breakout`，pending 被抢先 → supersede |
| T1b | 结构突破未命中，收盘破 N 根 Donchian 滚动轨（窗口不含信号 K 线与未收盘根） | `trigger_trend_breakout`，与 T1a 同轮互斥（结构优先） |
| 行2 | 当根触碰触点 + 同向金K | `trigger_pullback_confirm`（当根确认），pending 一律被抢先 |
| 行3 | 未触碰但有金K + 有效同向 pending | `trigger_pullback_confirm`（次根确认），pending → confirm |
| 行4 | 未触碰有金K + pending 方向不一致或窗口过期 | None，pending → expire |
| 行5 | 触碰但无金K | None，→ upsert pending（转待确认池） |
| 行6/7 | 未触碰无金K | None，有效 pending 窗口到期 → expire |

突破类共享闸门：① 最小突破幅度 `breakout_threshold`（毛边不算）；② 长实体短影线
（实体/K线全长 ≥ 0.70，2026-09-30-2 放宽）；③ 放量为加分项（≥量比门槛 +5 分，
不卡死）；④ 追高上限 `breakout_max_pct`（越位超限不产生突破触发，0=关闭）。

金K 证据：`detect_all_patterns` + `resolve_golden_evidence`（candlestick.py）。
2026-10-01 收窄：仅流星线维持复合确认（双流星/流星+趋势K），锤形线恢复
单根直接确认；2026-10-01-2 倒锤形线退出看涨白名单（看涨回踩不认长上影）。
纯金K独立触发（trigger_candlestick）2026-09-29 下线——正式网复盘
28 笔 6 胜负期望，金K必须与触点配合。

回踩触点（docs/22，启用白名单 `pullback_touch_refs`，标注优先级 retest > swing >
ema21 > ema55 > ema144，横向结构语义强于均线）：

- **retest** 突破回测位：破位价来自 `breakout_events`（T1 触发时 scanner upsert），
  影线可入带、收盘须守住——回踩不破 = 突破有效性确认；
- **swing** 摆动结构位：多头只认最近 HL / 空头只认 LH，时效门 bars_ago ≤ 40；
- **ema21**：原口径不加门；**ema55/144**：数据门（`ema_touch_min_bars`）+ 排列门
  （快线在慢线同侧）+ 斜率门（近 5 根同向）。

破轨事件生命周期（scanner.py:702-757，`breakout_events` 表）：T1 触发 upsert（同
方向刷新位价与锚点；反向破轨旧行 expired 后新建）→ touch_ref=retest 的回踩金K
落库时 consume → 超 `retest_window_bars` 窗口的 active 行批量 expired。

### 3.4 待确认池 pending 状态机（scanner.py:759-827）

每币至多一条活跃 pending（status=pending），批量预取快照（`_prefetch_pendings`
scanner.py:625-657，每轮一次查询），处置动作收集后统一落库（`_apply_pending_ops`，
独立 session，失败整体回滚——下轮按快照重评估，不产生不可恢复状态）：

- **upsert**：同方向触碰刷新锚点续命（换触碰根、等待窗口重新计时）；无活跃行则
  新建；方向反转旧行 expired（direction_flip）后同事务新建（保留审计链，不原地
  改写方向）；
- **confirm**：终态 confirmed，回填确认形态与 `confirmed_scan_result_id`（放在
  `_save_results` 之后以便关联新记录 id；Stage-1 触点是 retest 时同步 consume
  破轨事件）；
- **supersede**：终态 superseded（T1 突破 / 当根确认抢先）；
- **expire**：终态 expired（window_expired / direction_flip）。

### 3.5 收尾：排序 → 抑制 → 落库 → 通知 → AI

1. 候选按质量分降序、同分按 24h 成交额（scanner.py:409-413）；
2. 重复命中抑制（仅定时，见 3.1）；
3. `_save_results` 独立 session 写 `scan_results`，返回 {symbol: 新 id} 供
   confirm 回写（scanner.py:487-536）；
4. 定时且有新命中 → 飞书卡片（见 §7）；
5. pending 处置落库 → 破轨事件处置落库；
6. AI 分发：`run_ai_analysis_task.delay`（ai_tasks.py:142 按 `ai_max_per_scan`
   配额、quality_score 降序取前 N；指纹缓存 FINGERPRINT_TTL_MIN 兜底同币同信号
   不重复调 LLM）。

## 4. 筛选参数（scan_filters）

筛选漏斗可调参数的单一来源（scan_filters.py）：`system_config.scan_filters`
（JSONB，可空）有值优先生效，缺键回落 env（settings.*），env 未配置回落代码默认。
**优先级：DB JSONB > env > 代码默认**。逐键容错：类型错误/负数/inf/nan 按缺失
回落，不让一条坏配置烧掉整轮扫描；白名单键全不勾/全非法视为配置事故回落全量
（触发类型）或默认（触点，静默全空会让回踩管线停摆）。

|---|---|---|---|

| `breakout_channel_bars` | 20（config.py:35） | 5 ~ 200 | ③ 触发层：Donchian 通道回看根数 |

| `breakout_vol_ratio` | 1.2（config.py:36） | 0 ~ 10 | ③ 触发层：放量加分门槛（量比口径，达标 +5 分不卡死） |

## 7. 定时任务与通知

### beat 调度（celery_app.py:47-52）

```python
"hourly-scan": {
    "task": "app.tasks.scan_tasks.run_scan_task",
    "schedule": crontab(minute=2),   # 每小时第 2 分钟，等待 K 线收盘
    "kwargs": {"scan_type": "scheduled"},
}
```

配套：`task_acks_late=True` + `worker_prefetch_multiplier=1`；worker 进程 fork 后
重启日志线程并 dispose 连接池（celery_app.py:11-25，04:02 扫描整批失败的根因修复）。
任务入口 `run_scan_task`（scan_tasks.py:15-115）负责建记录/防重/任务记录
（open_task/close_task，前端「任务记录」列表）。

### 飞书扫描命中卡片（scanner.py:53-86 `_scan_hit_card`）

- 触发条件：`scan_type == "scheduled"` 且抑制后 new_hits 非空（scanner.py:436-441）；
  手动扫描不推送。经 `feishu_bot.send_app_card` 发送，失败只记日志不影响扫描与
  AI 链路。
- 卡片体：蓝色 header「🔎 定时扫描命中 N 个」+ lark_md 命中行
  （加粗币种 + TRIGGER_FAMILY 信号族中文名 + 金K形态中文名 + 质量分）；
  超 8 条正文截断，note 脚注「仅列前 8 个，共命中 N 个」；未知信号/形态有兜底
  文案不吞值。
