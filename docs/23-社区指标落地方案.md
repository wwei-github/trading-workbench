## 0. 边界与原则（先立规矩，再动手）

1. **插件是展示层，不是决策层**：`lightweight-charts-indicators` 在浏览器由 oakscriptjs 计算，
   后端是 Python，**调不到插件**。任何要进决策链的指标都必须在后端用**同口径**（周期、
   平滑方式 RMA/Wilder、时区/会话）重新实现，并跑**样本外回测**。
2. **每个改动 = 一个可开关、可回滚的实验**：新增开关默认 `off`，只有回测 **PASS** 才进
   「影子模式」（`docs/14-影子模式方案.md`），再决定是否替换旧逻辑。
3. **一次只验一个假设**，优先正交、少而精（防过拟合/多重检验）。禁止把多个指标一起堆进同一版本。
4. **前端图只用于「肉眼研究」**：可用 `host-ema-multi`/`bb`/`rsi`/`atr`/`macd`/`adx` 等对照后端口径，
   但**图好看 ≠ 策略有效**，结论只能来自回测。

## 1. 批次与优先级

| 批次 | 工作项 | 目标 | 预期收益 | 风险 |
|---|---|---|---|---|
| **P0** | Squeeze 释放触发 | 在震荡评分卡（只做「过滤」）之外，新增「压缩→释放」入场**触发** | 抓波动率扩张起点，提高突破前埋伏质量 | 假释放多，需方向过滤 |
| **P1** | SuperTrend / Chandelier 跟踪止损 | 用 ATR 轨道**替换/补充固定 ATR 止损** | 趋势单让利润奔跑，缩小回撤 | 反复被扫，需与 EMA144 结构配合 |
| **P2** | Donchian 通道突破确认 | 强化 `trigger_breakout` 的突破判定（现靠实体比例） | 突破阈值数据化、可调 | 与现有触发器重叠，需做去重 |
| **P3** | ADX/DMI 门可视化调参 + ZigZag 结构对照 | 现有门已用 ADX、结构用 `swing.py`，用插件指标辅助**调参/对照** | 门参数更透明、结构识别可比对 | 仅研究，不改逻辑 |

## 2. 逐项落地清单

### P0 — Squeeze 释放触发

**假设（预注册）**：1H 上「布林带收口 + ATR 通道压缩（squeeze）后，首次释放且方向与 4H EMA144 一致」时
入场，比当前「仅突破/回踩确认」的样本胜率更高。

**口径与参数**（对齐插件 `squeeze-momentum` / `ttm-squeeze-pro` 默认）：
- `squeeze` 判定：`BB(20, 2σ)` 上/下轨 **完全落在** `KC(20, mult=1.5×ATR)` 之内。
- `release`：最近 `RELEASE_WINDOW=3` 根内 `squeeze=true`，当前根 `squeeze=false`。
- 方向：`momentum = linreg(close − donchianMid(20))` 的符号（或 TTM 直方图符号）。
- 周期：`KLINE_INTERVAL`（1h）；背景方向仍取 4H EMA144（复用现有 gate）。

**改动点**
- [ ] `backend/app/services/strategy/technical.py`：新增 `squeeze_state(bars, length=20, bb_mult=2, kc_mult=1.5, window=3)`（复用已有 `atr_series`、布林带）。**注意 warm-up ≥ 20+3 根**。
- [ ] `backend/app/services/strategy/trigger.py`（L71 附近枚举）：新增 `signal_type = "trigger_squeeze_release"`，并定义其触点优先级（排在 `trigger_pullback_confirm` 之后/并列，需明确）。
- [ ] `backend/app/config.py`：新增 `SQUEEZE_TRIGGER_ENABLED=False`、`SQUEEZE_RELEASE_WINDOW=3`、`SQUEEZE_KC_MULT=1.5`（对齐 `BREAKOUT_CHANNEL_BARS` 等现有配置的写法）。
- [ ] 扫描服务：在候选生成处判断开关；仅当 `enabled` 且方向与 4H 背景一致时产出该 `signal_type`。

**回测对照设计**（范式抄 `backend/scripts/sweep_reclaim_replay.py`）
- [ ] 新建 `backend/scripts/squeeze_release_replay.py`：样本取 `ScanResult` 中已确认信号，按
      「是否 squeeze 释放」分 `squeeze_release` / `no_squeeze` 两桶，用
      `ExchangePool.get_klines_range` 拉后续 K 线，统计 `win_tp1/win_tp2` 与 `Δ = win_rate(release) − win_rate(no_squeeze)`。
- [ ] 输出含：样本量、主判定 Δ、方向合理性、敏感性网格（`window × kc_mult`）、集中度（单币/单月占比）、PASS/FAIL。

**判定闸门（PASS 条件，落地时按经验值微调）**
- 样本量 `n ≥ 200`；`Δ win_rate ≥ +5%` 且方向合理；敏感性网格符号一致；单币/单月占比 `< 30%`。

**风险 / 回滚**：假释放 → 需 4H 方向过滤；开关 `off` 即完全回滚，无数据迁移。

### P1 — SuperTrend / Chandelier 跟踪止损

**假设**：将固定 ATR 止损替换为 `SuperTrend(10, 3)` 或 `Chandelier Exit(22, 3)` 跟踪止损后，
趋势单的**盈亏比**提升且**最大回撤**不恶化。

**口径与参数**（对齐插件默认）：SuperTrend `atrPeriod=10, factor=3`；Chandelier `atrPeriod=22, atrMult=3`。

**改动点**
- [ ] `backend/app/services/strategy/technical.py`：新增 `supertrend_series(bars, period=10, factor=3)`、`chandelier_stop(bars, period=22, mult=3)`（复用 `atr_series`）。
- [ ] 风控止损计算处（`docs/05-风控体系.md` 对应实现）：新增跟踪止损分支，`STOP_MODE ∈ {fixed_atr, supertrend, chandelier}`。
- [ ] `backend/app/config.py`：新增 `STOP_MODE="fixed_atr"`、`TREND_STOP_ATR_PERIOD=10`、`TREND_STOP_FACTOR=3`。
- [ ] 交易记录/复盘：止损来源要落库标注（便于归因区分固定/跟踪），不改预测逻辑。

**回测对照设计**
- [ ] 用已有 trade/复盘数据（`TradeReview`）做**事后重放**：同一批入场点，分别用 `fixed_atr` vs `supertrend` 模拟止损轨迹，对比 **期望 R、盈亏比、最大回撤、被扫次数**。
- [ ] 新脚本 `backend/scripts/stop_mode_replay.py`（同范式）。

**判定闸门**：期望 R 提升 `≥ +0.1R` 或最大回撤下降 `≥ 20%`，且被扫次数增幅 `< 30%`。

**风险 / 回滚**：跟踪止损在震荡市反复被扫 → 需与结构门（`ema_gate.structure_1h`）联动；`STOP_MODE` 切回即回滚。

## 3. 防偏差与过拟合纪律（每项都适用）

- [ ] **无未来函数**：信号只用「已收盘」K 线；最后一根未收盘不得参与判定。
- [ ] **Warm-up**：所有指标至少预热 `max(周期) + 缓冲` 根（如 BB20+release3 → ≥23，含 4H 背景再乘比例）。
- [ ] **样本外**：按时间切分（如最近 30% 为 holdout），只用样本内调参，**样本外只跑一次**看结果。
- [ ] **多重检验**：同一假设只调一轮网格，记录所有尝试次数（防择时过拟合）。
- [ ] **集中度**：剔除单币/单月主导（占比 < 30%）。
- [ ] **口径一致**：后端实现周期必须与前端展示一致（插件 `ema` 单实例默认 9 ≠ 后端 144，看后端请用 `host-ema-multi`）。

## 4. 统一验收指标（回测报告模板）

| 指标 | 定义 | 门槛 |
|---|---|---|
| 样本量 n | 有效复盘样本 | ≥ 200（P0）/ ≥ 100（P1） |
| 胜率 | win_tp1 占比 | 提升且 Δ 显著 |
| 盈亏比 / 期望 R | 平均盈利/平均亏损；期望 R | 不劣化，期望 R 提升 |
| 最大回撤 | 区间峰值回撤 | 不恶化（P1 目标下降） |
| 稳健性 | 敏感性网格符号一致 | 一致 |
| 集中度 | 单币/单月占比 | < 30% |
