## 一、目标与范围

### 1.1 影子模式定义

> 让新规则先「实习」一段时间，只打分不发工资——分数够格才转正。

- **打标**：候选特征在管线各接入点被完整计算，结果与当时的决策上下文一起落库；
- **零影响**：打标行为对扫描、AI 分析、开仓、巡检的任何路径**无行为改变**（仅 OI 特征有 +10 请求/轮的只读预算，见 §四）；
- **归因**：复用现有复盘归因链，把每个标记关联到结果（真实交易盈亏或逐K回放假想结果）；
- **评估**：每日任务按 `feature_key × value 分桶` 统计胜率/期望 R 与基线对比；
- **裁决**：按**预注册标准卡**（§七）决定升格、继续观察或 FAIL 关闭——标准卡在影子开始前锁定，事后不可回调。

### 1.2 影子 ≠ 历史回放

| 维度   | 预注册回放（docs/26 模式）     | 影子模式（本文档）                         |
| ------ | ------------------------------ | ------------------------------------------ |
| 数据   | 历史K线回算                    | 同期真实行情                               |
| 速度   | 快而糙（分钟级出结论）         | 慢而真（≥1 周自然样本积累）                |
| 对照组 | 需构造                         | **天然公平**：影子单与真实单面对同一批行情 |
| 失真源 | 数据可得性、参数对齐、成交假设 | 无（唯一失真是样本量积累慢）               |
| 适用   | 先杀明显不行的（第一步）       | 验证纸上逻辑是否在真实市场成立（第二步）   |

两者是**串行的两道闸**，不是替代关系（见 §八 流程）。

## 二、总体架构（四环）

```
① 打标 ──→ ② 归因 ──→ ③ 评估 ──→ ④ 裁决

① attach point 计算特征 → 写 shadow_marks（含 decision 快照）
② 复用复盘链：scan/analysis 标记 → TradeReview.outcome（逐K回放）；
              trade 标记 → TradeRecord 真实盈亏 → R
③ celery beat 每日任务：按 feature_key × value 分桶 → {n, win_rate, avg_r, baseline}
④ 预注册标准卡（§七）裁决：升格 / 继续观察 / FAIL 关闭
```

设计原则：**打标与评估解耦**——打标代码只管「算出来、记下来」，评估代码只管「join 起来、算出来」，两者通过 feature_key + ref 关联，互不感知。

## 三、数据模型：通用 shadow_marks 表

```python
# backend/app/models/shadow.py（新文件，未实施）
class ShadowMark(Base):
    __tablename__ = "shadow_marks"

    id:          UUID 主键
    created_at:  DateTime        # 打标时刻（决策时刻）
    feature_key: String(32) 索引 # 特征标识（§1.3 表）
    ref_type:    String(16)      # 'scan_result' | 'ai_analysis' | 'trade'
    ref_id:      UUID 索引       # 指向对应表主键
    symbol:      String(20)
    testnet:     Boolean
    value_json:  JSON            # 特征值 + 分桶 + 计算快照
    decision_json: JSON          # 打标时刻真实系统行为快照
```

**字段设计理由**：

- `value_json` 存**原始数值**（如 `{"atr_ratio": 0.52, "bucket": "compress"}`）而非只存分桶结论——防止评估期想改分桶口径时需要重算历史；
- `decision_json` 记录打标时刻真实系统的处置（`opened` / `skipped` / `vetoed` / `quota_missed` / `gate_blocked:<闸门名>`），用于消除**幸存者偏差**：被现有闸门拦下的候选也在表里，才能回答「若放行会怎样」；
- 单表通用所有特征（12 个特征挂不同管线点），**不侵入** ScanResult/AIAnalysis 现有列；
- 复合索引建议 `(feature_key, created_at)`（评估任务按时间窗扫描）与 `(ref_type, ref_id)`（归因 join）。

迁移遵循仓库惯例：幂等 `CREATE TABLE IF NOT EXISTS`（[database.py](../backend/app/database.py) 模式），PG 迁移用 information_schema 守卫。

## 四、特征注册表（代码约定）

```python
# backend/app/services/shadow.py（新文件，未实施）
SHADOW_FEATURES: dict[str, ShadowFeature] = {
    "cvd_div": ShadowFeature(
        name="CVD 背离（订单流免费子集）",
        attach="scan_candidate",            # 接入点标识
        compute=compute_cvd_div,            # (db, symbol, klines) -> value_json | None
        bucket=lambda v: v["bucket"],       # 分桶规则
        card="CARD_CVD",                    # 预注册标准卡引用（§七）
        enabled=True,
    ),
    ...
}
```

约定：

1. **启停改代码**（`enabled` 开关）：打标本零风险，不进 system_config UI；唯一例外 `oi_conf` 每轮 AI 配额前 10 候选 +10 只读请求/小时，若需紧急止血可直接置 False，无需发版改配置；
2. `compute` 返回 `None` 表示当前数据不足以计算（数据缺失**不打标**，评估自然无此样本，不产生「缺失组」伪统计）；
3. 打标必须**幂等**：同一 `ref_id + feature_key` 重复打标以 UPDATE 覆盖（扫描重跑/复盘重跑场景）；
4. 打标包 try/except 全吞（记 WARNING 日志）——影子代码任何异常**不得**影响主管线。

## 五、归因链路（按 ref_type 三条）

> 核心洞察：`replay_suggestion`（[review_tasks.py](../backend/app/tasks/review_tasks.py)）的逐K回放引擎对**未开单的 suggest 分析同样产出假想结果**——因此挂在扫描/分析上的影子标记，无论真实系统有没有开单，都能拿到「如果做了会怎样」的答案。这是影子评估不需要真实承担风险却能得到真实统计的关键。

| ref_type      | join 路径                                     | 结果口径                                                                                |
| ------------- | --------------------------------------------- | --------------------------------------------------------------------------------------- |
| `scan_result` | ScanResult → AIAnalysis → TradeReview.outcome | `win_tp1 / win_tp2 / loss / expired`；无 AI 分析的候选（配额未进）记 `no_analysis` 单列 |
| `ai_analysis` | AIAnalysis → TradeReview.outcome              | 同上；`pending`（未到 24h）下一轮再看                                                   |
| `trade`       | TradeRecord（closed）                         | `R = realized_pnl ÷ risk_amount`（真实盈亏，含滑点手续费——这是与回放的本质差异）        |

- 评估**不回填** marks 行，查询时 join——避免双写漂移；TradeReview 未复盘的标记该轮跳过、下轮自然补上；
- baseline（对照组）取**同期全部同 ref_type 标记**的整体胜率/均值 R，而非硬编码历史值。

## 七、预注册标准卡（docs/26 模板）

> 纪律：**标准卡在影子开始前填写并提交入库（本文档），影子跑完前不可修改阈值**——事后调标准 = 自欺，这是 docs/26 刺透/乌云 FAIL 即关先例的核心价值。

### 卡模板

```
卡号 / 特征 key：
定义口径：（计算公式、分桶边界，与 §四 compute 函数一致）
机制假设：（为什么预期有信息量——一句话）
成功标准：最小样本 n ≥ __（每桶）；判定指标 __ ≥ __；（可多个，全部满足）
评估周期：≥ __ 天
决策规则：达标 → 升格路径（§八）；不达标 → FAIL 关闭归档；接近 → 续观察 __ 天
```

### 首批三张卡

**CARD-01 `cvd_div`（CVD 背离）**

- 定义：近 N 根 CVD 斜率符号 × 与价格新高/新低的背离方向；桶 = `bullish_div / bearish_div / no_div`；
- 假设：价创新高而主动买压未跟随的突破，胜率低于总体；
- 成功标准：n ≥ 80/桶；`no_div` vs `bullish_div`（多头信号侧）win_rate 差 ≥ 5pp，且 avg_r 差 ≥ 0.05；**且与 OBV 票同票率 < 80%**（防共线，docs/13 #3 预期边界）；
- 周期 ≥ 14 天；达标 → 升格为第 8 票（|net|≥4）；同票率 ≥ 80% → 改为「替换 OBV」重立项。

**CARD-02 `oi_conf`（OI 四象限）**

- 定义：ΔOI 24h 符号 × 信号方向 → 桶 = `confirm / diverge`（新钱入场 vs 回补/去杠杆）；
- 假设：背离组（价涨 OI 跌等）胜率显著低；
- 成功标准：n ≥ 60/桶；diverge 组 win_rate ≤ confirm 组 −5pp；
- 周期 ≥ 14 天；达标 → 升格 quality_score ±3 修饰（排序层，不进闸门——OI 是慢变量）。
- 落地口径（2026-10-05 打标上线，仅明确分桶实现、不改阈值）：桶由 ΔOI 符号单独决定——增=新钱入场 `confirm`、减=回补/去杠杆 `diverge`（两方向对称：新多入场与新空入场都是 OI 增）；信号方向（扫描时指标票 net 符号）只进 value_json 供评估期四象限细分。24h 前值取快照环内距 now−24h 最近的样本（容差 18~30h），无前值只存快照不打标。快照环为 Redis zset（2026-10-06 由进程内 dict 迁移：worker prefork 10 子进程各持独立内存，进程内环永远凑不出 24h 前值，上线以来零打标的根因；环与 broker 同实例，前缀 `shadow:oi:` 隔离）。

**CARD-03 `vol_regime`（波动率状态机）**

- 定义：ATR14/ATR100；桶 = `compress(<0.6) / normal / expand(>1.4)`；
- 假设：压缩期突破假信号率高；
- 成功标准：n ≥ 100（compress 桶）；compress vs normal win_rate 差 ≥ 8pp；
- 周期 ≥ 21 天（regime 切换慢）；达标 → 压缩期 quality_score 折价（影子已验证差异幅度定折价权重）。

**CARD-04 `macd_div`（MACD 背离，缠论盘整背驰可取子集）**

- 定义：近 24 根已收盘K线前后半段比较——后半段 max(high) 抬升而 MACD 柱峰值衰减 → `diverge_bear`（多头信号质量差）；后半段 min(low) 下移而柱低谷抬升 → `diverge_bull`（空头信号质量差）；其余 `confirm`（桶语义与 cvd_div 实现对齐）；实现 `strategy/technical.analyze_macd_div`，2026-10-05 打标上线；
- 假设：价新高而柱峰衰减（顶背离）的突破动能不跟随，胜率低于总体；价新低而柱谷抬升对称；
- 成功标准：n ≥ 60/桶；`confirm` vs `diverge_bear`（多头信号侧）win_rate 差 ≥ 5pp，且 `confirm` vs `diverge_bull`（空头信号侧）win_rate 差 ≥ 5pp；
- 周期 ≥ 14 天；达标 → quality_score 折价（排序层修饰，不进闸门——背驰后趋势仍可延续，只折价不拦截，docs/13 #11）。

**CARD-08 `sweep_reclaim`（流动性猎取确认，docs/13 #10 转影子）**

- 定义（2026-10-07 锁定不可回调）：scheduled 扫描回踩确认候选，`touch_ref ∈ {swing, retest}`（**EMA 触点族不打标**——同日预注册回放证明该族插针收回为常态 ~91%、无选择性）。参考位 = **生产原生触点位（零漂移）**：swing 当根确认 = `trigger._detect_swing_touch` 同输入复算、swing 次根确认 = `PullbackPending.ema21`（Stage-1 触碰锚点）、retest = 破轨事件 price / pending 锚点。15m 口径：插针窗 = [min(Stage-1 锚点 bar 开盘, 信号 bar 开盘−2h), 信号 bar 收盘]（上限 24h），击穿深度 d=0.1%；收回 = 末次插针起 N=8 根内 15m 收盘回参考位内侧（k=0 含单根长脚插针当根收回；截至信号 bar 收盘——打标时刻未来不可知）。桶 = `sweep_reclaim / sweep_open / no_sweep`。
- 假设：结构位下方止损堆被扫后收回（sweep_reclaim）→ 趋势恢复概率高于干净触碰（no_sweep）；插针未收回（sweep_open）最差——sweep_open 桶同时回答升格后的门语义（要求收回的等待成本 vs 直接排除）。
- 成功标准：**swing 族主判定**——n ≥ 30/桶；Δ = win_rate(sweep_reclaim) − win_rate(no_sweep) ≥ +3pp；且 win_rate(sweep_reclaim) ≥ win_rate(sweep_open)。retest 族为观察列（不参与主判定）。
- 周期 ≥ 14 天；达标 → 升格为回踩 Stage-2 附加确认档（门语义按 sweep_open 桶数据定，仍走预注册回放/规则补丁流程）；任一不满足 → FAIL 关闭归档（docs/26 刺透/乌云先例）。
- 请求预算：每个 swing/retest 族回踩候选 +1 次 15m 只读拉取（130 根，docs/14 §四 oi_conf 先例同款）。

**CARD-10 `r2_slope`（趋势质量 R²/slope，2026-10-08 锁定不可回调）**

- 定义：近 24 根已收盘 1h 收盘价最小二乘回归（`swing.linear_regression`，与 CARD-07 结构 R² 同引擎）——r² = 拟合优度，slope_pct = slope ÷ 均价 × 100（每根 %，跨币可比）。桶 = `r2_high(≥0.7) / r2_mid(0.4~0.7) / r2_low(<0.4)`；slope 方向不进分桶（方向由票数/4h 背景闸门承担），记 value_json 作观察列。
- 背景与假设：强趋势（高 R²）段的信号延续概率高，震荡（低 R²）段假信号率高。ScanResult.r_squared 列在历史 R² 门槛废弃时已置 0 恒空（docs/16 §2 此前记「已算已展示」有误，立卡时更正），本卡影子侧自算零成本、与生产判定零耦合。
- 成功标准（全部满足）：判定桶 n ≥ 60/桶（r2_high 与 r2_low；r2_mid 为观察列不进判定）；win_rate(r2_high) − win_rate(r2_low) ≥ +5pp，且 avg_r 差 ≥ +0.05R。
- 周期 ≥ 14 天。
- 决策规则：达标 → 升格 quality_score 修饰（排序层，与 CARD-03/04 同档；闸门化需单独 bump RULE_VERSION 走预注册回放）；avg_r(r2_low) ≥ avg_r(r2_high) → 判无信息量，FAIL 关闭归档；n 不足 → 续观察 2 周复评一次，仍不足则关闭。

`time_stop_would` 的卡在其条目启动影子时按同模板补填；**CARD-07（`reentry_precond`）卡已预注册**于 [13-流派融入路线 #12 状态注](13-流派融入路线.md)（2026-10-06 锁定不可回调：总体=CLOSED 且 exit_reason="sl"，结构三件=EMA 排列+ADX(14,1h)≥20+止损前 48 根收盘回归 R²≥0.5，续走=出场后 24h 内 signed-R MFE≥0，裁决门槛=structure_ok 桶 n≥60 且 P(续走)≥40%）。**P-08 序贯判据（2026-10-08 预注册，不可回调）**：structure_ok 桶续走率 SPRT，H0: p=40% vs H1: p=50%，α=0.05/β=0.20——早停 h1=达标方向证据（可提前进升格流程，仍走 §八）、早停 h0=低于门槛方向证据；预注册时点已积累 decided≈7（远未跨边界，判定不受影响）。报告 `sequential` 字段呈现。

**CARD-09 `rec70_shadow`（评分门槛前向对照，2026-10-07 锁定不可回调）**

- 背景：存量回看（2026-09-14~10-07，正式网）rec 60-69 段 16 笔胜率 12.5% / avg −0.659R，70+ 段 29 笔 41.4% / +0.324R（测试网同向）——但这是**事后分桶**，直接提 `TRADING_MIN_RECOMMENDATION` 有事后选择偏误（三桶取优的 p-hacking 风险）。本卡以前向窗口验证「60-69 段真实期望为负」能否复现。
- 定义：trade_record 宿主（`tag_trade_close` 内打标，不依赖 K 线），按开仓时 `ai_snapshot.recommendation` 分桶 `rec60_69 / rec70plus`；读数 = 真实盈亏（win = pnl>0，avg_r = Σ R）。正式网主判定组，测试网对照组；**评估仅计入 closed_at ≥ 2026-10-08**（`REC70_START`，窗口前存量只打标不计入）。
- 假设：prompt 锚点定义的分数分水岭（60=勉强达标 / 70=多重共振）与真实盈亏分水岭一致，60-69 段期望显著为负。
- 成功标准（全部满足）：正式网 rec60_69 桶 n ≥ 15；avg_r(rec60_69) < 0；win_rate(rec60_69) + 8pp ≤ win_rate(rec70plus)。测试网同窗同向作佐证，不进判定。
- 周期 ≥ 28 天（正式网 60-69 段 ≈4.6 笔/周）；期间**不改 prompt 评分锚点定义**（防分数分布漂移污染对照）。
- 决策规则：达标 → `min_recommendation` 正式提至 70（配置页）；avg_r(rec60_69) ≥ 0 → 判存量 16 笔为运气差，卡关闭归档、门槛保持 60；n < 15 → 续观察 2 周复评一次，仍不足则关闭。
- **P-08 序贯判据（2026-10-08 预注册，不可回调）**：rec60_69 桶每笔 R 均值 SPRT（正态近似），H0: μ=0 vs H1: μ=−0.30R（效应量取存量 −0.659R 约半——「显著负」的操作性定义），α=0.05/β=0.20——早停 h1=支持提门槛方向（仍走上方决策规则流程），早停 h0=「存量是运气差」方向证据；报告 `sequential` 字段呈现。**正态近似局限（2026-10-08 检测发现）**：小样本时样本 sd 易低估总体 sd，LLR 虚高可致过早 h1/h0（如 n=2、r=[−0.6,−0.4] 即 LLR=10.5 早停）——序贯读数仅为方向性证据，早停**不直接改门槛**，仍走上方决策规则与人工拍板；比例卡（CARD-07）不依赖样本 sd，无此问题。

## 八、升格/关闭流程

```
预注册回放（docs/26 模式，快而糙）──FAIL──→ 归档，不进影子
        │ 通过
        ▼
填标准卡（§七）→ 实施打标（§十）→ 影子跑
        │                            │
        │             ┌───────────────┼──────────────┐
        ▼             ▼               ▼              ▼
     影子跑满      达标           接近           不达标
        │             │               │              │
        ▼             ▼               ▼              ▼
     评估报告      升格：          续观察          FAIL 关闭：
                   排序修饰 →      （延长一次，     marks 保留 90 天后清理，
                   投票/闸门成员    需写明理由）    结论写回本文档 §九归档表
                   bump RULE_VERSION
```

- 升格分两档：**排序修饰**（quality_score ±N）影响小先走；**投票/闸门成员**改变信号流向，必须单独 bump RULE_VERSION（复盘按版本分组隔离，[06-复盘归因](06-复盘归因.md)）；
- FAIL 关闭不是浪费：负面结论与 docs/26 一样有存档价值（防止后人重复踩坑）。

## 九、边界与非目标

1. **影子不改变任何行为**：即使统计显著，未走 §八 升格流程前，任何代码不得引用影子数据做决策；
2. **样本量不足禁止下结论**：`sufficient=false` 时日报只陈述数字；
3. **组合形状特征不适用**：β热度/熔断类特征没有「单笔归因对象」（它影响的是组合回撤分布而非单笔胜率），其验证靠实施后的回撤分布对比，不走本框架；
4. **影子标记不参与 AI 上下文**：LLM 看不到影子标签（防止间接影响决策，污染对照）；
5. **数据保留**：marks 保留 90 天滚动清理（`created_at` 索引支持）；FAIL 归档只留结论不留明细。
