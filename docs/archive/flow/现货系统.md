# 现货系统全流程

> 基于代码现状整理（2026-09-24）。现货子系统（docs/18）与合约系统**零侵入隔离**：后端独立文件（`services/spot_*`、`api/spot.py`、`models/spot.py`、`tasks/spot_tasks.py`），前端独立组件，仅在全局头部以 Segmented 切换「合约 | 现货」两个业务域。
>
> 前端入口：头部 Segmented 选「现货」后共 4 个子 Tab：持仓总览 | 回测 | 历史记录 | 策略配置（tab key：overview / backtest / history / settings，见 ScanResult.tsx:209-247）。

---

## 0. 定时调度（celery_app.py:79-93）

| 时刻 | 任务 | 说明 |
|---|---|---|
| 每日 08:08 | `run_spot_daily_task` | 屯币日检：日 K 收盘后 8 分钟，错开 08:05 合约日报 |
| 周一 08:15 | `run_spot_dca_task` | 周度定投（P1），`dca_enabled` 开关才执行 |
| 周一 08:30 | `run_spot_weekly_review_task` | AI 周度研判（P1，纯展示无执行权限），在定投之后 |

## 1. 文件布局

| 文件 | 职责 |
|---|---|
| `app/services/spot_engine.py` | 决策引擎：阈值常量 + 纯函数 `evaluate_day` |
| `app/services/spot_client.py` | 现货 REST 客户端（/api/v3），账号解析、K 线、下单 |
| `app/services/spot_backtest.py` | 回测引擎 `run_backtest`（与实盘共用 evaluate_day） |
| `app/api/spot.py` | 端点：评分、配置、持仓、历史、回测提交/查询 |
| `app/models/spot.py` | 表：现货订单/记录、`spot_backtests`、`spot_kline_cache` |
| `app/tasks/spot_tasks.py` | Celery 任务：日检、定投、周度研判、回测异步执行 |

## 2. 决策引擎（spot_engine.py）

- **阈值常量**（spot_engine.py:31-45）：RSI 买入/卖出档位、回撤档位、布林上轨、MA30 周乖离等。
- **核心纯函数 `evaluate_day(...)`**（spot_engine.py:130-279）：
  - 签名要点：`(symbol, as_of_date, kline closes, ...)`——输入是**截至某日**的 K 线序列；
  - 输出：买入/卖出/持有决策、评分、gates（条件闸门明细）、lots 与 quote amount；
  - **设计铁律**：实盘日检与回测循环调用同一个函数，保证回测与实盘逻辑一致。

## 3. 数据源与精度（spot_client.py、api/spot.py:38-88）

1. K 线必须走 Binance **REST `/api/v3`**（合约 fapi 有基差，混用会导致策略判断偏差）；
2. 精度解析：`/api/v3/exchangeInfo?symbol=X` 的返回包在 `symbols` 数组里，须按数组内元素取 filters；**过滤器缺失必须报错**，不得静默兜底默认精度（否则市价单 -1013 LOT_SIZE）；
3. K 线缓存：优先读 `spot_kline_cache`（symbol+interval 唯一），缺失/过旧时经 `SpotClient.klines()` 拉取并回写；新鲜度检查时毫秒时间戳**必须先 /1000** 再传 `utcfromtimestamp`。

## 4. 实盘日检链路（spot_tasks.py:53-83）

1. Celery beat 每日 08:08 触发 `run_spot_daily_task`；
2. 拉取目标币种日/周/月 K 线，落盘缓存后调用 `evaluate_day` 评分；
3. 当前阶段**纯评分推送，不直接下单**；买入执行由前端「一键确认」人工触发（现货交互卡片）；
4. **环境开关与合约完全独立**（api/spot.py:91-163）：
   - `spot_trading_testnet`：现货独立测试网/正式网开关；
   - `spot_enabled_keys`：正式网启用账号集合；
   - 测试网专用 key：`BINANCE_SPOT_TESTNET_API_KEY/SECRET_KEY`（**现货测试网与合约测试网是两套系统，key 不互通**；未配置时回落 `BINANCE_TESTNET_*` 但现货侧会 401）；
5. `SpotClient` 账号解析（spot_client.py:47-75）：从注册表解析账号、按环境选 `SPOT_TESTNET_BASE` 或 `settings.BINANCE_BASE_URL`；实例属性与公开方法禁止同名（fetch_account 命名教训）。

## 5. 回测系统（spot_backtest.py）

1. **入口 `run_backtest(...)`**（spot_backtest.py:31-50）：多币种、日/周/月 K 线、预算、时间区间参数；
2. **日历重放**（spot_backtest.py:134-203）：逐日截断历史数据喂给 `evaluate_day`（as_of_date 递进），**无未来函数**；维护现金、持仓、订单明细、权益曲线；
3. **结果指标**：净增币、基准超额（vs 持有不动）、最大回撤、成交分布；
4. **异步执行**（spot_tasks.py:120-183）：前端「现货 → 回测」Tab 提交 → `spot_backtests` 表落任务（summary/daily_series/orders_detail JSON）→ Celery `run_backtest_task` 拉数执行回写 → 前端轮询展示。

## 6. 前端展示

- **持仓总览**：当前现货持仓、评分卡（evaluate_day 输出）；
- **回测**：提交表单（币种/区间/预算）+ 结果展示（净增币、基准超额、最大回撤、成交分布）；
- **历史记录**：`react-chrono@2.6.1` 垂直时间轴（**必须 2.x，3.x 要 React 19 与项目冲突**），节点含买卖、AI 研判、每日评分及结果；顶部 Segmented 过滤：全部 / 交易 / AI 研判 / 每日评分（tab key 从 `orders` 更名为 `history`）；
- **策略配置**：现货环境开关、定投参数、监控币种等；
- 买入确认采用飞书/页面「一键确认」卡片模式，确认后才执行市价买入（精度按 §3 规则处理）。

## 7. 与合约的隔离边界

- **零改动合约文件**：合约既有逻辑文件不因现货新增而修改；现货新增全部独立命名（spot_* 前缀）；
- **复用基础设施**：DB 会话（database.py 迁移机制）、飞书通知（feishu_bot）、celery beat 调度、.env 账号注册表；
- **配置零交集**：合约用 `trading_testnet` / `live_trading_keys` / `current_account_key`；现货用 `spot_trading_testnet` / `spot_enabled_keys`，互不影响（project memory 硬约束）；
- **前端**：BizMode = 'futures' | 'spot'（ScanResult.tsx:30-57），tab 记忆互不冲突；嵌套 tab 内容必须 `overflowY: auto; overflowX: hidden` 防横向滚动。
