## 一、链路总览（一张图）

```
Celery beat 定时扫描（run_scan_task 收尾，scanner.run 提交后）
        │ fire-and-forget 派发（失败只记日志，不影响扫描主流程）
        ├──→ ① run_strategy_signals_task      影子信号生产
        ├──→ ② run_strategy_observations_task L1 观测快照（不依赖 enabled）
        └──→ ③ evaluate_shadow_signals_task   影子信号推演回填
                 │
   ① registry → enabled 插件 → 逐币 1h/4h K线 → build_signal
        │      → strategy_shadow_signals 落库（只记录，绝不开单）
   ② observe() 证据包 → strategy_observations 落库（3h 去重/30 天保留）
   ③ 信号龄 ≥4h → 信号后 1h K线 → replay_exit（策略出场语义）
        │      → 回填 outcome / r / eval_bars
                 │
        GET /api/strategies/{, /signals, /observations, /analysis}
                 │
        前端 StrategiesPanel（清单/影子信号+推演列/影子分析卡/L1 观测卡）
        前端 TradingConfigPanel（注册表编辑：开关/仓位预算/风险权重）

   ┄┄┄ 未实施（虚线）┄┄┄
   S2：影子数据评审通过 → 信号进执行层（trade_engine 消费 StrategySignal）
   S3：出场分流（exit_spec 按策略解析，与 P2 回测结论合并执行）
```

**两条硬隔离**（docs/20 铁律）：

- **策略 = 信号生产者，系统 = 信号消费者**：插件是纯计算体，不碰 DB、不下单、不读全局配置；行情由调用方注入、参数由 registry 注入（影子/实盘同代码，便于测试）。
- **影子纪律**：`strategy_tasks.py` 刻意不 import 任何执行层模块；影子信号与 `TradeRecord`（实盘单）严格隔离，S2 解锁前任何行都不会触发开单。

**与原生 golden_k 管线零共享**：内置策略信号走 `scan_results → ai_analyses → trade_records` 原路径，不落影子表；插件信号不落 `scan_results`。golden_k 全链路对插件体系无感知，`strategy_registry` 为 NULL 时系统行为与接入前完全一致。

## 二、触发与调度

| 方式 | 链路                                                                                            | trigger 记录                                                   |
| ---- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 定时 | `run_scan_task` 收尾（[scan_tasks.py](../backend/app/tasks/scan_tasks.py) L99-110）依次派发 ①②③ | `scan`                                                         |
| 手动 | `POST /api/strategies/signals/refresh`、`/observations/refresh`、`/signals/evaluate`            | `manual`（②③支持 trigger 参数；①按是否传 scan_record_id 判定） |

- 三任务 `max_retries=0`，任何异常只记日志 + `task_records` 落 failed，**绝不影响扫描主流程**（影子纪律）。
- `task_records.task_type`：①`strategy_signals` ②`strategy_observations` ③`shadow_evaluate`。
- universe 约定：三任务缺省都回落**最近一轮扫描的标的集**（绑定 golden_k 扫描节奏，控制行情 API 负载）；无扫描记录时返回 skipped，不跑全表。

## 三、注册表与插件协议

### 3.1 注册表（`system_config.strategy_registry` JSON 列）

解析规则（[registry.py](../backend/app/services/strategies/registry.py)）：

- `NULL` / 解析失败 → 仅内置 `golden_k_ai`（现状零行为变化）；
- 未知 id 忽略并告警；未知键拒绝并告警（合法键 `{id, enabled, max_positions, risk_weight, config}`）；
- 数值越界 clamp：`max_positions` 1~10、`risk_weight` 0.1~1.0；
- `golden_k_ai` 恒存在且不可禁用（`max_positions=10`，占返回列表首位）；
- 插件条目缺省 `enabled=False`（前端不显式配置就不写注册表，保持 NULL 语义）。

### 3.2 插件协议（[base.py](../backend/app/services/strategies/base.py)）

```python
@dataclass
class StrategySignal:          # 与 AIAnalysis 三价语义对齐，trade_engine 未来消费的唯一形态
    strategy_id, symbol, direction(long/short), entry, stop,
    tp1, tp2,                  # 0 = 无
    reason, confidence(0~1), signal_type(pullback/cross…),
    raw: dict                  # 策略私有证据快照（落库归因用）

class StrategyPlugin(Protocol):
    id, display_name
    scan_candidates(universe) -> list[str]        # 筛币预筛
    build_signal(symbol) -> Optional[StrategySignal]  # None = 不触发
    exit_spec() -> dict                           # 出场语义声明（S3 前仅回测用）
```

rule of two：协议字段/信号形态必须两个策略都用得上才准加。`ema_trend` 另有 `observe()`（L1 观测证据包，协议外扩展方法，第一版仅它需要）。

### 3.3 新增插件三步

1. `services/strategies/` 新建子模块实现协议（`build_signal` 以 `klines_1h/klines_4h` 显式参数承接行情注入）；
2. `registry.py` 的 `KNOWN_STRATEGIES` 加 id + `get_strategy` 加分支；
3. 交易配置页注册表加条目（或直接改 `strategy_registry`）。可选：`strategy_tasks.EVAL_EXIT_OVERRIDES` 加该策略的推演出场语义。

## 四、信号生产链（① run_strategy_signals_task）

流程（[strategy_tasks.py](../backend/app/tasks/strategy_tasks.py)）：

1. `load_registry` → `enabled_plugin_entries` → 剔除 `golden_k_ai`；无插件 → skipped；
2. universe：`symbols` 参数 > 指定/最近 `scan_record_id` 的 distinct 标的；无 → skipped；
3. 逐策略：`get_strategy(id, registry_raw)`（config 注入）→ `scan_candidates(universe)`；
4. 逐币拉 1h+4h 各 300 根（`KLINE_LIMIT`）→ `build_signal`；
5. **去重**：同策略同标的同方向 24h 内（`DEDUP_HOURS`）已有信号则跳过；
6. 落库 `strategy_shadow_signals`；单币失败 rollback 吞掉（逐币容错）。

### 4.1 ema_trend 判定链（[ema_trend.py](../backend/app/services/strategies/ema_trend.py)）

一律已收盘 K 线判定（`_closed` 统一剔除最后一根未收盘根）；1h/4h 各需 ≥200 根已收盘。

```
4H 趋势闸门 _gate_4h（三重否决，全过才给方向 up/down）
  ├─ 斜率：|EMA144[-1]−EMA144[-20]|/close < 0.5% → 走平拒
  ├─ 缠绕：近 10 根收盘穿 EMA144 > 2 次 → 震荡拒
  └─ ADX(14) < 20（cfg.adx_min）→ 无趋势拒
        ↓
1H 结构 _structure_1h（方向性排列 + ATR 归一发散度）
  ├─ 多头 EMA21>EMA55>EMA144 / 空头镜像（不排列拒）
  ├─ |EMA21−EMA55|/ATR14 ≥ 0.5 且 |EMA55−EMA144|/ATR14 ≥ 1.0（不足拒）
        ↓
入场（回踩优先，金叉补充）
  ├─ _pullback：影线触及 EMA21/55 ±0.3 ATR 容差带 + 方向K线（多阳/空阴）
  │   + 收盘站回触点均线 + 量 ≤1.5×MA20（放量下跌非健康回踩）
  │   → stop=触点值 ∓ 0.5×ATR，confidence=0.6
  └─ _cross：EMA21 上(下)穿 EMA55（已收盘两根对比，须在 EMA144 有利侧）
      + 方向K线 + 量 ≥1.2×MA20 → stop=EMA55 ∓ 0.5×ATR，confidence=0.55
        ↓
三价：entry=当根收盘；tp1=回看 20 根摆动前高/前低（距入场 < 1R → 0，
      即纯跟踪语义）；tp2 恒 0
```

参数全部 `EmaTrendConfig`（registry `config` 注入，越界/非法回默认）：`div_fast_mid=0.5` `div_mid_slow=1.0` `adx_min=20` `touch_band_atr=0.3` `stop_atr=0.5` `vol_pullback_max=1.5` `vol_cross_min=1.2` `min_rr=1.0` `tp_swing_bars=20`。

落库 `raw` 证据键：`gate_4h{direction, slope_pct, wraps, adx, close_vs_ema144}`、`structure_1h{aligned, div_fast_mid, div_mid_slow, atr}`、`touched`、`vol_vs_ma20`、`range_score`（L2 评分卡总分）、`macd_zero`（零轴状态）——观测口径，不拦截。

## 五、L1 观测链（② run_strategy_observations_task）

纯观测**不依赖 registry enabled**（ema_trend 停用也持续积累定标素材，P1 启用条件要求 ≥4 周连续样本）：

- 同标的 3h 内（`OBS_MIN_HOURS`）已有快照跳过（4h 节奏）；保留期 30 天（`OBS_RETENTION_DAYS`）滚动清理；
- 观测器 `EmaTrendStrategy({})` **出厂参数**（不随 registry 变动，口径稳定）；
- `observe(klines_1h, klines_4h)` 证据包（与 build_signal 共用内部判定，同口径）：
  - `range_score: {score, items[8]}`——L2 震荡评分卡（[range_score.py](../backend/app/services/strategies/range_score.py)）：
    | # | 项目 | 阈值（观测期出厂值） |
    |---|---|---|
    | 1 | 4h EMA144 斜率走平 | <0.5%/20根 |
    | 2 | 4h 缠绕 EMA144 | 近10根 >2 次 |
    | 3 | 1h 三线不排列 | 多空排列均不满足 |
    | 4 | 1h 发散度不足 | \|EMA21−EMA55\|/ATR < 0.5 |
    | 5 | 1h ADX 弱 | < 18 |
    | 6 | BBW 低分位收口 | 近120根 <30 分位 |
    | 7 | 反复穿越 EMA21 | 近20根 ≥4 次 |
    | 8 | 量能低迷 | 近20根 CV < 0.3 |
    总分 0~8，≥3 视为震荡；K 线不足记 `hit=None` 不计分。**出厂阈值仅供观测统计，不得直接用于拦截**（P1 定标流程预注册在 docs/19 §3.2）。
  - `stochastic`——KDJ（RSV→K=SMA(3)→D=SMA(3)→J=3K−2D，近 3 根金叉/死叉标记）；
  - `macd_zero`——MACD 零轴状态 `above / pullback_hold / below / mixed`；
  - `gate_4h` / `structure_1h`——同 4.1 证据（允许 None，闸门不过也算观测有效样本）。

## 六、影子推演链（③ evaluate_shadow_signals_task）

对**未推演且信号龄 ≥4h**（`EVAL_MIN_AGE_HOURS`）的影子信号跑 `replay_exit` 假想回放，回填三列：

1. 每轮取最旧 200 条（`created_at` 升序，防单轮过长）；
2. 拉 1h 420 根（`KLINE_LIMIT + EVAL_FWD_BARS`），取**信号时刻之后**的已收盘 K 线前 120 根（`EVAL_FWD_BARS`）为前向窗口；
   - 时间基准：`created_at.replace(tzinfo=timezone.utc)` 显式 UTC 换算（DB 存 naive UTC；naive `.timestamp()` 会按本地时区解释，已修）；
   - **断档守卫**：首根距信号 >2h（窗口未覆盖信号时刻，Celery 长期停机/停盘积压）→ 标 `invalid` 落袋，防止永久积压与 R 失真；
3. `replay_exit(direction, entry, stop, tp1, tp2, fwd, overrides={"fwd_bars": 120, **EVAL_EXIT_OVERRIDES[策略id]})`；
4. 回填 `outcome / r / eval_bars / evaluated_at`；单条失败吞掉。

**策略出场语义映射**（`EVAL_EXIT_OVERRIDES`，keys ⊆ `OVERRIDE_KEYS` 有测试锁死）：

| 策略          | overrides                                                                                | 语义                                                                                      |
| ------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `ema_trend`   | `tp_qty_override=(0,0)`、`be_trigger_r=1.0`、`trail_atr_k=2.0`、`sig_exit="ema55_break"` | 纯跟踪 V1：无固定止盈，MFE≥1R 武装保本，ATR×2 跟进（无 D1 退化摆动腿），收盘破 EMA55 出场 |
| 其他/golden_k | 缺省                                                                                     | 引擎基线（TP 分批 + 跟进）                                                                |

**replay_exit 的 P2 出场变体能力**（[backtest_engine.py](../backend/app/services/backtest_engine.py)，供 ③ 与 P2 回测共用）：

- `tp_qty_override`：`(q1,q2)` 覆盖 TP1/TP2 出仓比例；`(0,0)`=纯跟踪 V1（`pure_trail` 无条件激活跟踪腿）；
- `sig_exit`：`ema55_break`（收盘破 EMA55）/ `ma20_break_2bar`（连续 2 根收盘破 MA20）/ `macd_death_cross`（零上死叉，空头镜像零下金叉）——收盘判定、当根收盘价出场（无前视；MACD 分支 33 根预热截除 + ε 浮点噪声守卫）；
- 守卫：`tp1=0` 或 `q1=0` 不挂目标腿（防多头 `high≥0` 恒真造零价废腿）；SL 根内优先，信号出场仅在未触 SL 时成交。

**outcome 值域与 R 口径**：`loss / win_tp1 / win_tp2 / be_exit（保本/跟进扫出，含仅 tp0）/ open（窗口耗尽）/ invalid（断档）`。`r` = 全腿合计含费净 R；**open 与 invalid 不进 decided 分母**（P-04 口径诚实原则，docs/16）。

## 七、分析统计链（GET /api/strategies/analysis）

影子期分析，是 docs/20 §4.2 **并发准入判定的数据源**：

- **per-strategy 统计**：`signals / evaluated / decided / open / wins / win_rate / avg_r / total_r`；`decided` 排除 `{"open","invalid"}`；胜率 = wins/decided；期望 R = avg_r。
- **两两重叠率**（插件策略间）：同标的同方向、信号时间 ±24h 内双发的频率，**较少一方口径**（遍历较少方计数，每条最多命中 1 次，保证 ≤100%）。判定铁律：**重叠率 >50% = 伪分散，只跑其一**（相关系数 >0.7 同理，待样本积累后补算）。

## 九、S2/S3 解锁路径（未实施，预注册口径）

| 阶段            | 内容                                                                                                 | 解锁条件                                                                                                                         |
| --------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **S2 开单权限** | 指定 strategy_id 的影子信号进执行层（trade_engine 消费 `StrategySignal` 三价，14 道闸门/风控全适用） | 影子期数据评审：decided 样本足够、期望 R 为正、重叠率 ≤50% 且与 golden_k 相关性可接受；新策略 `risk_weight` 0.5 起步（风险驯化） |
| **S3 出场分流** | `exit_spec` 按策略解析进生产出场骨架                                                                 | 与 P2 回测结论合并执行（docs/20 预注册；出场骨架不可变，参数按策略注入）                                                         |
| **P1 闸门定标** | L1 观测阈值由分位数重估替换出厂值                                                                    | ≥4 周连续观测样本（观测任务已在积累）                                                                                            |
| **P2 回测**     | 出场变体 V1/V2/V4 用 `replay_exit` 新能力跑历史对照                                                  | 随时可跑（引擎能力已就位：`tp_qty_override` / `sig_exit` 三模式）                                                                |

**并发准入铁律**（docs/20 §4.2，多策略同时启用时）：同标的同方向双发互斥（先到先得）；方向对锁禁止；信号重叠率 >50% 或相关系数 >0.7 = 伪分散，只跑其一；每策略独立 `max_positions` 预算子集 + `risk_weight` 乘进单笔风险额。

## 十、纪律与负清单（摘自 docs/20，实施时刻遵守）

- S1 影子期**只记录不决策**：影子信号任何一行都不得触发开单/改仓；
- 插件策略之间完全不可见，不共享状态；协同只发生在底座（预算/风控/复盘）；
- 评分卡/L1 观测**只算不拦**，出厂阈值不得直接用于拦截；
- 影子链路任何异常不得影响扫描主流程与原生 golden_k 管线；
- 协议演进走 rule of two，避免为单一策略提前抽象。
