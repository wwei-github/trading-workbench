# 16 - 在跑单浮动收益巡检与 AI 持仓建议设计

> 2026-09-20 立项。四个关键决策已拍板：① 触发策略 = 首次浮亏 + 冷却刷新；② 浮动收益展示 = 合并合计 + 悬浮拆分；③ AI 建议形式 = 结构化结论 + 文字；④ 动作边界 = 仅展示 + 建议离场时飞书通知，**绝不自动执行**。

## 1. 背景与问题

- 收益列对在跑单只显示**已实现部分**（TP1/TP2 止盈成交后 `_record_realized` 写入），未触 TP 的在跑单显示 `-`——持仓中的浮盈浮亏完全不可见，用户只能去交易所 App 看当前走势。
- 亏损在跑单缺乏过程性诊断：只有平仓后才有 AI 错误归因（docs/12），持仓期间走势走坏、开仓逻辑被破坏时没有任何提示。
- 巡检时机成熟：每小时 :10 `settle_trades` 已经拉取全仓位 `positions()`（含交易所侧 `unrealized_pnl`），更新浮动收益**零额外交易所请求**。

## 2. 需求 A：在跑单浮动收益巡检更新

### 2.1 口径定义

| 字段 | 在跑单（OPENED/TP1_HIT/TP2_HIT） | 已平仓（CLOSED） |
|---|---|---|
| `realized_pnl` | 已实现部分（TP 成交累计，现口径不变） | 全程净额（现口径不变） |
| `unrealized_pnl`（新增） | 交易所仓位 unrealized_pnl 快照（每小时 :10 刷新） | 终态置 0 |
| `pnl_pct`（口径扩展） | **(realized + unrealized) ÷ risk_amount × 100**（全程口径） | realized ÷ risk_amount（不变） |

- 浮动收益取**交易所为真相**（与结算巡检同一原则），不做本地价格估算。
- 数据节奏与现有约定一致：每小时 :10 变动 + 手动刷新，**前端不加轮询**。

### 2.2 数据流（`settle_trades` 内）

对每条非终态记录、且未走"仓位归零结算"分支的：

1. `unrealized = float(pos.get("unrealized_pnl") or 0)`（`pos` 来自本轮已拉取的 `env_positions`，无新增 API 调用）；
2. `rec.unrealized_pnl = round(unrealized, 6)`；
3. `rec.pnl_pct = round((realized + unrealized) / risk_amount * 100, 2)`（risk_amount 有效时）；
4. 仓位归零结算分支：`rec.unrealized_pnl = 0`（终态无浮动）。

### 2.3 展示（TradesPanel 收益列，合并+悬浮）

- 在跑单收益列主数字 = `realized + unrealized`（全程合计），正负着色规则不变；
- 悬浮 Tooltip 拆分：`已实现 X.XX · 浮动 Y.YY`（各自着色）；
- 已平仓显示 realized，行为不变（与资金分析页 analytics 口径保持一致）。

## 3. 需求 B：浮亏在跑单 AI 持仓建议

### 3.1 触发与冷却（拍板：首次 + 冷却刷新）

触发条件（两者同时满足）：

- 状态 ∈ {OPENED, TP1_HIT, TP2_HIT}；
- 全程收益 `total = realized + unrealized < 0`。

刷新规则：

| 场景 | 行为 |
|---|---|
| 首次浮亏（`ai_advice_at` 为空） | 立即诊断 |
| 距上次诊断 ≥ **3 小时**（冷却期，常量 `ADVICE_COOLDOWN_HOURS = 3`） | 重新诊断 |
| 距上次诊断 < 3h，但 total 较上次诊断时（`ai_advice_pnl` 基线）**恶化 ≥ 0.5R**（risk_amount 为分母） | 提前重新诊断 |
| 收益转正 | 不触发；已有建议保留展示，标注分析时间 |
| `AI_API_KEY` 未配置 | 全部静默跳过 |

> 冷却参数先走常量，不做页面配置（避免过度设计；若后续需要，参照补丁参数惯例进 system_config）。

### 3.2 任务编排（关键：锁外执行）

**结算巡检持有 Redis 锁 `lock:trade_open`（TTL 900s），LLM 调用（单笔 10~30s）绝不能进锁内**，否则会挤掉即时开仓等锁窗口。

```
每小时 :10 run_auto_trade_task
  ├─ 锁内：settle_trades（需求 A 写 unrealized_pnl + 收集诊断触发清单）
  ├─ 锁外：对触发清单逐条 .delay(run_position_advice, trade_id)（celery 子任务，失败隔离）
  └─ 子任务内：重查状态（可能已被 SL 结算为 CLOSED → 跳过）→ 组事实包 → LLM → 落库 → 通知
```

### 3.3 AI 事实包（程序算事实，AI 只做判断）

新建 `backend/app/services/position_advisor.py`，模式复用 [ai_attribution.py](../backend/app/services/ai_attribution.py)（事实包 JSON + 单次 LLM 调用 + 词表校验）：

```json
{
  "symbol": "...", "direction": "long",
  "opening_thesis": {
    "trade_type": "...", "recommendation": 72,
    "analysis": "开单时 AI 分析结论（ai_snapshot，截断 1500 字）",
    "plan": {"entry": 0.1, "stop_loss": 0.098, "take_profit_1": 0.105, "take_profit_2": 0.11}
  },
  "position_now": {
    "entry_fill": 0.1002, "current_price": 0.0965,
    "stop_loss_now": 0.098, "tp1": 0.105, "tp2": 0.11,
    "qty": 1000, "remaining_ratio": 1.0,
    "leverage": 10, "margin_used": 10.0, "risk_amount": 2.0,
    "realized_pnl": 0, "unrealized_pnl": -3.7,
    "total_pnl": -3.7, "pnl_pct": -185.0, "hold_hours": 5.2
  },
  "kline_facts": {
    "entry_pos_in_20bar_range": 0.82,
    "mfe_pct": 0.6, "mae_pct": 4.1,
    "ema_state": "空头排列", "atr_pct": 1.8,
    "bars_held": 5
  },
  "klines_recent": "开仓前 24 根 + 持仓至今（1h，升序，含 OHLV，字段压缩）"
}
```

- K 线经 `ExchangePool.get_klines_range`（与交易复盘 K 线同源），按 `rec.testnet` 无关——K 线走行情源不受交易环境影响；
- **不给 AI 绝对价格建议权**：提示词明确"建议只做结构性描述，不输出具体委托价"（沿用「AI 决策结构级锚定」项目原则）。

### 3.4 AI 输出（结构化 + 文字，拍板）

```json
{
  "thesis_valid": false,
  "trend_broken": true,
  "action": "exit",
  "reason": "跌破开仓依据的支撑位且 EMA 转空头，开仓逻辑失效（≤120字）",
  "detail": "完整分析（≤500字，可空）"
}
```

- `action` 枚举：`hold` 继续持有 / `tighten` 建议收紧止损 / `reduce` 建议减仓 / `exit` 建议离场；
- 词表外 `action` 落 `hold` 兜底；JSON 解析失败记日志、不落库（下轮按"未诊断"重试）。

### 3.5 存储（trade_records 新列）

| 列 | 类型 | 说明 |
|---|---|---|
| `unrealized_pnl` | NUMERIC(20,6) | 浮动盈亏快照（需求 A） |
| `ai_advice` | JSON | 最新诊断结论（3.4 结构） |
| `ai_advice_at` | DateTime | 最近诊断时间（NULL=未诊断，冷却判定基准） |
| `ai_advice_pnl` | NUMERIC(20,6) | 诊断时的 total_pnl（0.5R 恶化判定基线） |

- **迁移必须进 `database.py` `_run_migrations`**（幂等 `ADD COLUMN IF NOT EXISTS`，create_all 不会改已有表——项目铁律）；
- 每次诊断同时写一条 `TradeEvent(event_type="AI_ADVICE", detail=完整结论)`，操作历史时间线可回溯全部历史建议。

### 3.6 展示（拍板：结构化标签 + 理由摘要）

- 收益列后新增「AI 建议」列（宽度 ~180）：
  - 无建议：`-`；
  - 有建议：action 中文 Tag（hold=蓝 / tighten=橙 / reduce=金 / exit=红）+ reason 截断一行，悬浮看全文（含 detail 与分析时间）；
  - 非在跑单保留最近一次建议淡显（历史参考），在跑单才显示「重诊」link 按钮（小号 link 风格，符合按钮规范）；
- 手动触发：`POST /api/trades/{trade_id}/advice`，复用同一诊断函数，无视冷却（人工显式请求）；执行中按钮 loading。
- 展开行左侧 AI 卡片下方追加「持仓诊断」区块（ai_advice_at + action + reason + detail）。

### 3.7 通知（拍板：仅展示 + 离场建议推送）

- `action == "exit"` 时经 `notify.send_feishu_text` 推送：币种、方向、浮亏幅度（X.XX USDT / -Y%）、理由；
- **防刷屏**：与上一次 action 相同则不重复推送（对比 `ai_advice` 中旧 action）；
- 通知失败仅记日志，不影响落库。

| 位置 | 变更 |

## 5. 边界与异常

- **结算竞态**：诊断子任务执行前重查记录状态，已 CLOSED/FAILED 跳过；
- **LLM 失败/超时**：记日志不落库，`ai_advice_at` 保持 NULL，下轮巡检按"首次"重试；
- **环境切换**：仓位数据来自巡检时对应环境的 trader；诊断用数据全部来自 DB 落库值，不依赖运行时环境；
- **无 risk_amount 的老记录**：pnl_pct 与 0.5R 判定跳过，仅按 3h 冷却刷新；
- **诊断与结算同轮**：:10 巡检先写浮动收益，诊断基于本轮最新值判断，两需求天然串接。

## 6. 验收标准

1. 在跑单每小时 :10 后，收益列显示全程合计收益，悬浮见「已实现 · 浮动」拆分；未触 TP 的单不再显示 `-`；
2. 已平仓单收益列与资金分析页 analytics 完全一致（回归不破坏）；
3. 在跑单首次浮亏后 10 分钟内出现 AI 建议；冷却期内 LLM 调用次数为 0；
4. 浮亏较上次诊断恶化 ≥ 0.5R 时提前刷新；
5. `action=exit` 时飞书收到一条通知，同单连续 exit 不重复推；
6. 手动「重诊」无视冷却立即返回新结论；失败有明确错误提示；
7. 结算巡检任务持锁时长不因 AI 诊断延长（诊断全在锁外子任务）。
