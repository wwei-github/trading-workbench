# 18 - 现货屯币系统设计（BTC / ETH / BNB 低买高卖持续累积）

> 2026-09-23 立项设计。目标不是短线盈利，而是**长期净增币数最大化**：在固定投入下，比「傻定投」囤到更多的币。

---

## 1. 目标与定位

| 维度     | 定位                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 标的     | 白名单硬编码三币：BTC / ETH / BNB（USDT 交易对），不做其他币             |
| 核心动作 | 低买高卖：折价分批买入 → 过热分批卖出（只卖波段仓）→ 现金等下一次折价    |
| KPI      | **币本位**：累计净增币数、对比「等额定投基准」的超额币数；而非 USDT 盈亏 |
| 周期     | 最小决策周期 = 日K，无日内交易（与合约系统的分钟级信号完全隔离）         |
| 执行     | P0 半自动（飞书卡片一键确认）→ P1 全自动（可开关）                       |
| 环境     | 复用 testnet / live 双环境模式，现货 testnet 先跑通                      |

与现有合约系统的关系：**完全独立模块，零侵入硬约束**。

**隔离原则（工程铁律，贯穿所有分期验收）**：

1. **后端**：现货全部新增文件（`services/spot_*`、`tasks/spot_*`、`api/spot.py`、`models/spot.py`），**不修改任何合约现有文件的既有逻辑**——允许的触碰仅限「纯挂载点」：`main.py` 注册 router 一行、`celery_app` beat schedule 增加现货条目、`database.py` 迁移函数追加现货建表语句、`models/__init__` 导出一行；合约的 trade_engine / trade_tasks / binance_trader / scanner 等一行不动
2. **Binance 通道**：现货走独立封装 `spot_client.py`（现货 REST `/api` 端点），不复用合约 fapi 客户端实例，互不共享连接与缓存
3. **数据**：现货独立建表（spot_orders / spot_weekly_reviews / spot_kline_cache），不向 trade_records / system_config 既有列写入任何数据（spot_settings 用 system_config 上的**新增独立 JSON 列**，不改既有列语义）
4. **定时任务**：现货 beat 条目独立命名（`spot-*`），与合约任务无共享状态、无锁交叉
5. **前端**：现货全部新增组件（`Spot*Panel.tsx`、`spotApi.ts`），合约组件零改动；唯一触碰 ScanResult.tsx 是加 Segmented 切换器与 spotItems 分支（futuresItems 原样保留）
6. **验收标准**：每个分期结束时「合约全链路行为与改动前完全一致」是**一票否决项**——现货代码可以回滚/删除而不留任何痕迹（除独立新表外）

资金池分开（现货用独立的 USDT 预算口径）、订单表分开、定时任务分开；复用限于基础设施的**只读引用**（LLM 客户端、飞书推送函数、tabMemory、GLASS 风格常量）。

## 2. 核心设计理念

### 2.1 双层仓位：底仓 + 波段仓

```
持仓市值
├── 底仓（≥70%）  只进不出，屯币主体，由折价买入 + 定投累积
└── 波段仓（≤30%） 高卖低买增厚筹码，卖出规则只允许动这一层
```

- 卖出信号永远只卖波段仓 → 避免「卖飞底仓」踏空大周期
- 波段仓卖出的 USDT 回到现金池，专用于下一次折价买回（低卖高买的循环闭环）

### 2.2 多周期分级决策（月定环境 → 周定仓位 → 日定执行）

```
月K（环境层）：现在是牛市还是熊市/深度回撤？ → 决定「敢投多少」
        ↓
周K（仓位层）：中期趋势向上还是向下？ → 决定「能否卖 + 买入力度」
        ↓
日K（执行层）：今天是否超卖/过热？ → 决定「今天买几份 / 卖几份」
```

### 2.3 设计立场：不设硬止损

屯币标的为头部资产，硬止损（亏钱卖币）与「累积币数」目标直接冲突。风险控制改由三层替代：

1. **环境层限速**：熊市/深度回撤期降低单次投入、拉长买入间隔
2. **投入上限**：单币累计投入硬上限（配置），到顶停止买入
3. **分档折价买入**：越跌买越多（RSI/回撤分档），天然摊低成本

此立场记录在案，属主动取舍（理由：止损在屯币场景=把浮亏变成永久亏损，且卖在底部概率最高）。

## 3. 三周期指标体系

### 3.1 月K —— 环境层（每月 1 日更新）

| 指标     | 参数              | 判定                                               | 作用                                                   |
| -------- | ----------------- | -------------------------------------------------- | ------------------------------------------------------ |
| 年线     | MA12月            | 现价在 MA12月 **上方** = 牛市环境；下方 = 熊市环境 | 熊市环境：买入份数上限降为 2、禁止卖出（只攒便宜筹码） |
| 历史回撤 | 现价 ÷ 历史最高价 | 回撤 > 50% = 深度价值区                            | 深度价值区：买入力度 +1 档（历史统计的大周期底部特征） |

月K 数据量小（BTC 十几年 ≈ 150 根），一次拉全量缓存即可。

### 3.2 周K —— 仓位层（每周一 08:15 更新）

| 指标   | 参数    | 判定                             | 作用                                           |
| ------ | ------- | -------------------------------- | ---------------------------------------------- |
| 牛熊线 | MA30周  | 现价在 **上方** = 中期多头       | 上方：波段仓卖出解锁（可高卖）；买入正常力度   |
|        |         | 下方 = 中期空头                  | 下方：**只买不卖**；折价买入力度 +1 档         |
| 周RSI  | 14      | < 40 = 中期低位；> 70 = 中期高位 | 低位：加分；高位：仅当牛熊线上方时允许触发卖出 |
| 周MACD | 12/26/9 | 金叉 / 死叉                      | 趋势确认辅助分                                 |

### 3.3 日K —— 执行层（每日 08:05 检查）

买入触发（需通过周K闸门）：

| 信号       | 参数                | 分档                  | 份数            |
| ---------- | ------------------- | --------------------- | --------------- |
| 日RSI 超卖 | RSI(14)             | < 30 / < 25 / < 20    | 1 / 2 / 3 份    |
| 高点回撤   | 现价 ÷ 30日最高收盘 | > 15% / > 25% / > 35% | 1 / 2 / 3 份    |
| 布林下轨   | BOLL(20, 2)         | 收盘 < 下轨           | 份数 +1（叠加） |

- RSI 档与回撤档**取高者**（不叠加），布林下轨可 +1，单币单日上限 3 份
- MA200日 过滤：现价在 MA200 下方买入 → 属「折价买入」，与上表叠加无冲突；在上方则要求 RSI 更极端（< 28 才买 1 份），避免牛市半山腰接货过多

卖出触发（需月K非熊市 或 周K牛熊线上方；只卖波段仓）：

| 信号       | 参数                | 分档          | 动作                          |
| ---------- | ------------------- | ------------- | ----------------------------- |
| 日RSI 超买 | RSI(14)             | > 70 / > 80   | 卖 1 / 2 份波段仓             |
| 低点反弹   | 现价 ÷ 30日最低收盘 | > 30% / > 50% | 卖 1 / 2 份（取高者，不叠加） |
| 布林上轨   | BOLL(20, 2)         | 收盘 > 上轨   | 卖 1 份                       |
| 牛熊线乖离 | 现价 > MA30周 × 1.3 | 触发          | 卖 1 份（过热降仓）           |

- 单币单日卖出上限 2 份；卖出所得 USDT 进入现金池
- 份 = 持仓数量的 1/10 与最小卖出门槛（10 USDT）取大者（BNB 注意最小名义值）

## 4. 评分模型与 AI 参与架构

### 4.0 评分（可解释，类似合约 quality_score）

```
accumulation_score (0~100) = 环境分(30) + 仓位分(30) + 择时分(40)

环境分(30)：MA12月上方 20 / 下方 5；距 ATH 回撤 > 50% 再 +10
仓位分(30)：MA30周上方 15 / 下方 5；周RSI < 40 +10；周MACD 金叉 +5
择时分(40)：日RSI 档位 20/15/10/0；回撤档位 15/10/5/0；布林下轨 +5
```

| score   | 动作                   |
| ------- | ---------------------- |
| ≥ 70    | 强力买入（3 份）       |
| 55 ~ 70 | 买入（2 份）           |
| 40 ~ 55 | 小额买入（1 份）或定投 |
| < 40    | 等待                   |

规则分档与评分映射双轨并行：**实际份数 = min(规则分档, 评分映射)**，两者互为校验，页面展示评分明细（每个分数可定位到具体指标当前值，避免黑盒）。

### 4.1 AI 触点 1：周度环境研判（advisory，无执行权限）

每周一 08:30（周K更新后），将三周期指标快照（月K环境 / 周K牛熊线 / 日K近 30 日走势摘要）+ 上周研判文本喂给 LLM，输出**结构化研判**（JSON）：

```
regime:              积累期 / 上升期 / 分配期 / 下降期（四阶段周期定位）
outlook_btc/eth/bnb: 偏多 / 中性 / 偏空（各币下周倾向）
risks:               未来一周风险提示（≤3 条）
commentary:          研判正文（Markdown，≤300 字）
```

- **仅展示**：落 `spot_weekly_reviews` 表 + 飞书卡片推送 + 页面「持仓总览」研判卡展示
- **不参与评分计算、不触发任何订单、不改变任何规则参数**——纯粹的人读研判，与自动决策完全解耦
- 复用合约系统 LLM 客户端与 agent 管线；频率低（每周 1 次），成本可忽略
- 连续周研判留档形成「AI 周记」，人可回看 AI 对行情的判断历史（对 AI 观点质量的自我校验）

### 4.2 AI 触点 2：大额信号复核（降档制，类比合约 dual-judge）

触发条件：日K 信号产生的**单币买入或卖出达 3 份（最高档）**时，执行前先过 AI 复核。

- AI 输入：信号明细（命中规则 + 评分拆解）+ 三周期指标快照 + 近 30 日K线摘要
- AI 输出（结构化）：`keep`（维持 3 份）/ `reduce`（降为 2 份）+ 理由
- **权限边界**：AI 只能维持或降 1 档，**不能加档、不能取消信号、不能改方向/币种/金额**——比合约 dual-judge 的 keep/veto 更柔：完全否决会错过深度折价筹码（与屯币目标冲突），降档保留制衡力又不放弃积累机会
- AI 结论与理由随订单落 `trigger_detail.ai_review`，订单列表可回看，事后可归因 AI 降档是否正确
- 执行约束：LLM 调用（10~30s）走 Celery 异步，**不进任何 Redis 锁**（沿用合约系统 docs/16 工程惯例）；复核失败/超时按 `keep` 降级处理（不阻塞执行）
- 频率预估：3 份信号本身罕见（RSI<20 或回撤>35% 才触发），全年个位数次数，成本忽略不计

### 4.3 AI 权限边界汇总

| 触点     | 能做                   | 不能做                                                |
| -------- | ---------------------- | ----------------------------------------------------- |
| 周度研判 | 输出观点、推卡片、留档 | 影响任何决策/参数/订单                                |
| 大额复核 | 维持 / 降 1 档         | 加档、取消、改方向/币种/金额                          |
| 执行层   | —                      | AI 永远不直接下单（与合约「绝不自动平仓」同级的铁律） |

## 5. 资金与仓位管理

```
配置（每币独立）：
per_order_usdt   单份金额，默认 100 USDT
max_total_usdt   单币累计投入上限，默认 3000 USDT
dca_enabled      周度定投开关（无信号也持续累积的兜底），默认开
dca_amount       定投单次金额，默认 50 USDT

全局：
spot_budget      现货总预算（与合约资金隔离的记账口径）
usdt_reserve     买入后钱包 USDT 不得低于现货预算的 20%（保留弹药）
```

- **定投兜底**：每周一固定买入 dca_amount（与信号买入共用订单表，trigger_type=dca），保证无触发信号时也在累积
- **BNB 特殊性**：手续费抵扣 + Launchpad 价值 → 可配 min_hold_qty 最低持有量，卖出规则不得使其跌破
- 最小名义值校验：单笔 < 10 USDT 的买入自动合并到下次（Binance 门槛）

## 6. 执行节奏与定时任务（Celery beat，均北京时间）

| 任务             | 时间            | 内容                                                                                |
| ---------------- | --------------- | ----------------------------------------------------------------------------------- |
| 日K择时检查      | 每日 08:05      | 拉日K → 算指标 → 出买卖信号 → 3 份信号过 AI 复核（§4.2，异步）→ P0 推飞书卡片待确认 |
| 周K环境更新      | 每周一 08:15    | 拉周K → 更新牛熊线/周RSI/周MACD 状态 → 执行定投                                     |
| 周度 AI 环境研判 | 每周一 08:30    | 三周期指标快照 → LLM 结构化研判 → 落库 + 飞书卡片（仅展示，§4.1）                   |
| 月K环境更新      | 每月 1 日 08:20 | 拉月K → 更新月线环境 → 月度总结推飞书                                               |
| 持仓对账         | 每日 09:00      | 币安现货账户对账（数量/成本基准校验，漂移告警）                                     |

错峰设计：与合约系统巡检（每小时 :10）错开；四个任务均为轻量计算 + 最多 3 币请求，无锁竞争。

## 7. 数据模型与接口

### 7.1 新表

```python
# spot_orders：现货订单（含信号/定投/手动）
class SpotOrder(Base):
    symbol: str                  # BTCUSDT / ETHUSDT / BNBUSDT
    side: str                    # BUY / SELL
    trigger_type: str            # signal / dca / manual
    trigger_detail: JSON         # {score, rule_hits[], env:{monthly, weekly}, ai_review:{verdict, reason}} 快照（参照 docs/16 的 32KB 截断原则）
    qty: float | None            # 成交数量（市价买入用 quoteOrderQty 时回填）
    quote_amount: float | None   # 成交 USDT 金额
    price: float | None          # 成交均价
    status: str                  # PENDING_CONFIRM / FILLED / CANCELLED / FAILED
    fail_reason: str | None
    testnet: bool
    binance_order_id: str | None
    created_at / executed_at

# spot_weekly_reviews：AI 周度研判留档（§4.1，仅展示用）
class SpotWeeklyReview(Base):
    week: str                    # ISO 周标识（如 2026-W39）
    regime: str                  # 积累期 / 上升期 / 分配期 / 下降期
    outlook: JSON                # {btc: 偏多/中性/偏空, eth: ..., bnb: ...}
    risks: JSON                  # 风险提示数组（≤3 条）
    commentary: str              # 研判正文 Markdown
    indicator_snapshot: JSON     # 输入给 LLM 的三周期指标快照（复盘 AI 判断依据）
    created_at

# spot_backtests：回测任务与结果（§10）
class SpotBacktest(Base):
    params: JSON                 # {symbols, start, end, budget, per_order_usdt, dca...} 参数快照（可复现）
    status: str                  # RUNNING / DONE / FAILED
    summary: JSON | None         # 净增币/超额/笔数/最大回撤/期末市值/评分分布
    daily_series: JSON | None    # 每日评分与持仓序列（曲线用）
    orders_detail: JSON | None   # 模拟订单明细（32KB 截断惯例，全量走接口分页）
    error: str | None
    created_at / finished_at

# spot_settings：配置（单行 JSON 列挂 system_config 现有表，或独立 3 行 per-coin 表）
#   推荐：system_config 加 spot_settings JSON 列（币种白名单固定，结构可控）
```

持仓**不落库**：实时从币安 `/api/v3/account` 查询；成本基准由 spot_orders 聚合计算，避免本地持仓状态漂移。P2 加 spot_snapshots 每日快照（基准对比报表用）。

### 7.2 K线数据（关键技术差异）

- 现货与合约 symbol 相同（BTCUSDT），但**K线必须走现货端点** `/api/v3/klines`（合约走 fapi，两者存在资金费率/溢价基差，屯币执行在现货，须用现货价格）
- 现有 klines 服务按合约实现 → 新增 `spot_klines(symbol, interval, limit)`，interval 支持 `1d / 1w / 1M`
- 月K/周K 数据量小，落本地缓存表（每日/每周增量更新），日K 拉近 400 根够算 MA200

### 7.3 API

```
GET  /api/spot/overview      三币持仓 + 成本 + 净增币 + 当前评分 + 最新周度研判（聚合一屏）
GET  /api/spot/orders        订单列表（分页，可按 symbol/side 过滤，含 ai_review 结论）
GET  /api/spot/score/{symbol}  评分明细（三周期各指标当前值 + 得分 + 规则命中）
GET  /api/spot/reviews       AI 周度研判列表（AI 周记回看）
GET  /api/spot/timeline      运营时间轴（days 参数，聚合成交/定投/周研判/月环境/对账告警，§9.2.3）
POST /api/spot/backtest      发起回测（异步 celery 返回 task_id，§10）
GET  /api/spot/backtest      回测任务列表
GET  /api/spot/backtest/{id} 回测结果（汇总 + 模拟订单明细 + 每日评分序列）
PUT  /api/spot/settings      配置更新（开关/单份金额/上限/定投）
POST /api/spot/execute       手动执行待确认订单（P0 飞书按钮走此接口，复用 card.action.trigger 链路）
```

### 7.4 下单执行

- 买入：市价单 `quoteOrderQty=金额`（直接按 USDT 金额买，免去算数量）；卖出：市价单按 `quantity`
- 复用账号体系（docs/17）：spot key 同样走账号注册表解析，P0 固定用 live-1（现货屯币暂不扇出，多账号屯币属 P2 备选）
- 成交回报：`/api/v3/order` 查询成交均价与数量回填订单

## 8. 风控规则汇总

| #   | 规则                                                                                        |
| --- | ------------------------------------------------------------------------------------------- |
| 1   | 白名单硬编码三币，接口层拒绝其他 symbol                                                     |
| 2   | 单币累计投入 ≤ max_total_usdt；到顶后仅允许卖出                                             |
| 3   | 买入后 USDT 保留垫 ≥ 现货预算 20%                                                           |
| 4   | 熊市环境（月K）禁止卖出、买入上限 2 份；周K牛熊线下方只买不卖                               |
| 5   | 卖出只动波段仓，底仓锁定；BNB 不得跌破 min_hold_qty                                         |
| 6   | 单币每日最多执行 1 次（信号窗口每日一次，天然冷却，防 RSI 低位连日追买过量——每日最多 3 份） |
| 7   | 现货 testnet 先行验证 ≥ 2 周再切 live；切 live 时沿用现有「自动总闸默认关」的安全模式       |

**组件选型**：

| 方案                                   | 说明                                                                                                                | 结论    |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------- |
| **react-chrono（采用，2026-09-23 用户指定）** | 专用垂直时间轴组件：轴线圆点/卡片布局开箱即用，items 支持 ReactNode 卡片（类型 Tag + 明细），theme 可配色；已实装于「历史记录」Tab（P0 用 task_records type=spot 日检评分作事件源） | ✅ 采用 |

**数据结构**（`GET /api/spot/timeline?days=90`，新增接口）：

```typescript
interface SpotTimelineItem {
  ts: string; // 事件时间
  kind:
    | "trade"
    | "dca"
    | "weekly_review"
    | "monthly_env"
    | "reconcile"
    | "system";
  symbol?: "BTC" | "ETH" | "BNB"; // trade/dca 有
  side?: "BUY" | "SELL";

  meta?: {
    score?: number; // 当时评分
    qty?: number;
    quote?: number;
    ai_review?: string; // keep/reduce
    regime?: string; // 周研判的周期定位
  };
  ref_id?: string; // 跳转订单详情/周记详情
}
```

**渲染规则**（复用 EVENT_META 模式）：

| kind          | 圆点色     | 图标语义                             |
| ------------- | ---------- | ------------------------------------ |
| trade(BUY)    | 绿（涨色） | ↓买入箭头                            |
| trade(SELL)   | 红（跌色） | ↑卖出箭头                            |
| dca           | 蓝         | 定投                                 |

#### 9.2.4 KPI 条

三个数字并排（同交易记录概览风格）：

- **累计净增币**：Σ(买入币数 − 卖出币数)，按币分别显示再合计 BTC 本位折算
- **vs 定投基准超额**：实际净增币 −（同期投入 USDT ÷ 各期买入均价）——正为领先

**策略配置（settings）**：现货环境与账号区块（见下）+ 三币各自的开关 / 单份金额 / 投入上限 / 定投设置 + 全局预算与 USDT 保留垫 + **全自动开关（P2）**，表单风格对齐系统配置弹窗

## 10. 回测系统（规则验证，2026-09-23 补充）

### 10.1 定位

- **目的**：真金白银上线前，任选历史区间快速验证规则参数——KPI 与实盘一致：**币本位净增币 vs 同期定投基准超额**
- **与实盘同构**：回测 = 按历史日历逐日重放与实盘完全相同的决策逻辑；**唯一差异是跳过 AI**（用户拍板 2026-09-23）：
  - AI 周度研判：不生成（本就是纯展示，不影响决策）
  - 大额信号 AI 复核（§4.2）：跳过 → 3 份信号按满额执行，订单标注 `ai_review: 'backtest_skipped'`
  - 其余全部一致：三周期指标、评分、买卖规则、风控闸门、定投、手续费、最小名义
- **数据**：现货公开 K 线（live 端点，`spot_kline_cache`），无需 testnet——testnet K 线本身是模拟数据，回测一律用真实历史

### 10.2 引擎同构（防止回测/实盘两条代码路径漂移）

**P0 引擎必须写成纯函数**（这是回测可行性的前置条件）：

```
evaluate_day(symbol, as_of_date, klines_to_date, env_state, settings) -> Decision
# Decision: {action: BUY(n)/SELL(n)/HOLD, score, rule_hits[], env_snapshot}
```

- 实盘日检任务与回测循环**调用同一个函数**，禁止回测单独实现一套指标计算
- 违反此条的 PR 一票否决（与「合约零侵入」同级的工程铁律）

### 10.3 回测流程

**输入**：币种（BTC/ETH/BNB 单选或全部）/ 起止日期 / 初始 USDT 预算 / 配置（单份金额、投入上限、定投开关与金额）

**步骤**：

1. **预热**：拉取区间起始日前 300 根日K（MA200 预热）+ 区间前全部周K（MA30周预热）+ 区间前 ≥12 根月K（MA12月预热）
2. **逐日推进**：对区间内每一天，只用 ≤ 当日的数据计算指标（**杜绝未来函数**），口径对齐实盘——日K收盘（北京时间 08:05）触发
3. **日历重放**：周一执行周K环境更新 + 定投；每月 1 日执行月K环境更新；日K信号当日以**收盘价模拟市价成交**
4. **成本与风控全生效**：手续费 0.1%（可配 BNB 抵扣 0.075%）、最小名义 10 USDT、单币投入上限、USDT 保留垫、熊市/牛熊线闸门

**输出**（落 `spot_backtests` 表，detail 遵循 32KB 截断惯例）：

- 汇总：区间净增币 / 定投基准超额 / 买卖笔数 / 期末持仓市值 / 最大回撤（币本位 + U 本位）/ 评分分布
- 明细：每笔模拟订单（与 spot_orders 同结构）+ 每日评分与持仓序列
- 参数快照：完整输入配置（可复现）

### 10.4 回测与实盘差异声明（全量列出，不做隐性近似）

| 项           | 实盘             | 回测           | 说明                                                  |
| ------------ | ---------------- | -------------- | ----------------------------------------------------- |
| AI 周度研判  | 每周生成展示     | 不生成         | 本就不影响决策，无差异                                |
| 大额 AI 复核 | keep/reduce 降档 | 跳过，满额执行 | 明确标注；3 份信号罕见，对长期结果影响有限            |
| 成交价       | 市价实时成交     | 信号日收盘价   | BTC/ETH/BNB 深度好、单笔金额小（$100 级），滑点可忽略 |
| 手续费       | 实际费率         | 0.1% 假设      | 保守假设（BNB 抵扣实际更低）                          |
| 资金费率     | 无（现货）       | 无             | 现货无此成本                                          |

### 10.5 前端「回测」子 Tab

```
┌─────────────────────────────────────────────────────┐
│ 表单：币种(三选/全部) · 日期范围 · 预算 · [开始回测]  │
├─────────────────────────────────────────────────────┤
│ 汇总卡：净增币 / vs 定投超额 / 笔数 / 最大回撤        │
```

- 回测为异步 celery 任务（多年 × 3 币为纯计算，秒级~十秒级），发起后轮询状态，完成渲染结果
- 历史回测列表可保存对比（不同参数区间的结果并排看超额差异）

### 10.6 无未来函数验收（硬性）

单元测试：同一交易日 T，用「全量数据」与「截断到 T 的数据」分别计算指标与评分，**结果必须逐位一致**；抽查 MA200 / MA30周 / RSI / BOLL 四项。此测试进 CI，指标实现改动必须过。

- 日内交易（最小周期日K，每日一个执行窗口）
- AI 深度参与（每日信号 AI 确认/调仂数——日频下 LLM 链路重且增益存疑，AI 只做周度研判与大额降档复核）
- 自动提币 / 理财申购
- 多账号现货扇出执行（P2 备选；P0/P1 启用账号开关已就绪，总览已聚合，P1 先单账号执行再验证扇出）
