# 币安币种筛选工作台 — MVP 需求文档

> 版本：v1.0 (MVP)  
> 日期：2026-09-08  
> 状态：草稿，待评审

---

## 1. 项目背景与目标

### 1.1 背景
加密货币市场币种众多（币安现货交易对数千个），人工逐个排查是否出现"突破下跌趋势线"等技术信号耗时且容易遗漏。需要一个自动化工具，**定时批量扫描**币安所有币种，筛选出符合特定技术形态的标的，并在前端集中展示，帮助交易者快速发现机会。

### 1.2 目标（MVP）
1. 每小时自动拉取币安全部现货交易对的 K 线数据。
2. 对每个币种执行"**突破下跌趋势线**"判定，输出符合条件的币种列表。
3. 前端以表格形式展示结果，支持按时间筛选、分页、排序。
4. 保留历史扫描记录，可查看每次扫描的结果。
5. 支持手动触发一次扫描（便于调试与即时获取）。

### 1.3 非目标（MVP 暂不做）
- 实盘交易下单、止盈止损。
- 多策略组合、自定义策略编辑器。
- 实时 WebSocket 推送（MVP 用轮询 + 手动刷新）。
- 用户体系与权限（MVP 单用户）。
- 多交易所支持（仅币安）。

## 2. 功能需求

### 2.1 数据采集
- F-01 定时扫描：后端每小时（整点）自动触发一次全市场扫描。
- F-02 手动扫描：前端提供"立即扫描"按钮，调用后端接口立即执行一次扫描。
- F-03 币种范围：默认扫描币安所有 USDT 现货交易对，排除杠杆代币（UP/DOWN/BEAR/BULL 等）与稳定币交易对。
- F-04 K 线周期：MVP 使用 **日线（1d）** K 线，取最近 120 根用于趋势线拟合。
- F-05 数据来源：币安公开 REST API（`api.binance.com`，通过配置支持镜像域名切换）。

### 2.2 筛选策略：突破下跌趋势线
- F-10 下跌趋势线定义：在最近 N 根 K 线窗口内，连接价格的**局部高点**形成一条向下倾斜的直线（线性回归拟合高点）。
- F-11 突破判定：最新收盘价 **向上突破** 该趋势线（收盘价 > 趋势线在当前位置的预测值），且突破幅度 ≥ 阈值（默认 1%，可配置）。
- F-12 趋势有效性：趋势线斜率必须 < 0（即确为下跌趋势），且 R² ≥ 阈值（默认 0.5）以保证拟合质量。
- F-13 输出字段：币种代码、当前价格、突破幅度(%)、趋势线斜率、R²、扫描时间。
- F-14 结果去重：同一币种若已在近期（如 24 小时内）被命中，标记为"重复命中"，但仍保留记录。

> 算法参数（窗口长度、突破阈值、R² 阈值）均通过后端配置项暴露，便于调整。

### 2.3 结果展示（前端）
- F-20 扫描结果列表：表格展示命中的币种，列包括币种、当前价、突破幅度、斜率、R²、扫描时间、状态（新命中/重复命中）。
- F-21 排序：支持按突破幅度、扫描时间排序（降序）。
- F-22 筛选：支持按扫描时间范围筛选（最近一次 / 最近 24 小时 / 最近 7 天）。
- F-23 分页：每页 20 条，支持翻页。
- F-24 扫描状态：顶部展示"最近扫描时间"、"扫描中"状态、"命中数量"。
- F-25 手动刷新：点击按钮重新拉取最新结果（不触发新扫描，仅刷新数据）。
- F-26 历史扫描记录：可查看历史每次扫描的命中数量与时间，点击查看该次详情。

### 2.4 配置管理
- F-30 扫描配置：在前端展示当前扫描配置（周期、窗口、阈值等），MVP 只读展示。

## 3. 非功能需求

### 3.1 性能
- 单次全市场扫描（约 300~500 个有效交易对）应在 **3 分钟内** 完成。
- 前端列表接口响应 < 500ms。

### 3.2 可靠性
- 币安 API 单币种请求失败不影响整体扫描，记录错误并跳过。
- 扫描任务支持并发（建议 5~10 并发）控制速率，避免触发币安限流。
- 定时任务持久化，服务重启后仍按计划执行。

### 3.3 可观测性
- 后端日志记录每次扫描的：开始时间、结束时间、扫描币种数、命中数、失败数。
- 接口请求记录 INFO 级别日志。

### 3.4 可维护性
- 配置项集中管理（环境变量 / 配置文件）。
- 策略逻辑与数据采集解耦，便于后续新增策略。

### 3.5 部署
- 使用 Docker Compose 一键启动（后端 + 前端 + 数据库 + Redis + Celery Worker）。

## 7. 核心算法设计：突破下跌趋势线

### 7.1 步骤
1. 获取币种最近 120 根日线 K 线（开盘、最高、最低、收盘）。
2. 提取每根 K 线的**最高价**序列 `highs[0..N-1]`。
3. 找出局部高点：`highs[i]` 大于左右各 2 根 K 线的最高价（窗口 5）。
4. 对局部高点的索引-价格做**线性回归**，得到斜率 `slope` 与截距 `intercept`，并计算 `R²`。
5. 判断是否为有效下跌趋势：`slope < 0` 且 `R² >= 0.5`。
6. 计算趋势线在当前位置（最后一根 K 线）的预测值：`trend_value = slope * (N-1) + intercept`。
7. 最新收盘价 `close_last` 突破判定：`breakout_pct = (close_last - trend_value) / trend_value`。
8. 若 `breakout_pct >= 0.01`（1%），则命中。

### 7.2 边界处理
- K 线数据不足 30 根：跳过该币种。
- 局部高点少于 3 个：跳过。
- 斜率 >= 0：非下跌趋势，跳过。
- R² < 0.5：趋势线拟合度差，跳过。
- 所有数值计算做 `NaN/Inf` 检查。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 币安 API 地域不可达 | 扫描失败 | baseUrl 配置化，支持镜像域名；启动时探测可用端点 |
| 币安 API 限流 | 扫描中断/数据不全 | 并发控制（5~10）、指数退避重试、User-Agent 标识 |
| 单次扫描耗时过长 | 阻塞后续定时任务 | Celery 任务并发执行，超时保护；结果增量写入 |
| 趋势线算法误判 | 结果噪音大 | 参数可配置；MVP 后引入多周期确认 |
| 数据量增长 | 数据库膨胀 | scan_results 表按月份分区或定期归档（MVP 后） |
