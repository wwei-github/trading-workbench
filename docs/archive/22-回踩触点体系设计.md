# 22 - 回踩触点体系设计（突破回测 / 摆动结构 / 多周期 EMA）

> 2026-09-28。背景：关键位子系统（docs/21）已整体移除（触发/质量分/AI 锚点/图表全链路），
> 回踩触碰回归单一 EMA21 口径。本文设计「回踩金K 出现在哪里才可靠」的触点体系：
> 前三类高语义位置 + EMA 多周期扩展。设计原则：**复用两段式确认骨架，触点可插拔、
> 逐键可配置、可按复盘数据淘汰**。

---

## 1. 问题定义

回踩金K 的可靠性 = 趋势背景（已有：指标多数决 + 4h 震荡过滤）× **位置语义** × 两段式确认（已有）。

现状缺口：触碰对象只有 EMA21，漏掉两类高价值场景——

- **强趋势中价格不回踩 EMA21**，浅回撤直接在突破位/前 HL 企稳续涨；
- **深回撤踩穿 EMA21** 到 EMA55/144 才企稳，EMA21 口径完全接不住（此时金K悬空 >1.5% 被拦截，反而错过深回踩趋势续延）。

## 2. 触点体系总览

| #   | 触点       | touch_ref | 语义                                                       | 可靠性                       | 止损距离        |
| --- | ---------- | --------- | ---------------------------------------------------------- | ---------------------------- | --------------- |
| ①   | 突破回测位 | `retest`  | 前压力收盘突破后变支撑，回踩不破=突破有效性确认            | 最高（趋势+结构双背书）      | 窄（位下方）    |
| ②   | 摆动结构位 | `swing`   | 上一波 HL（更高低点）是多头认定的防守位，回踩企稳=结构延续 | 高（须 HL/LL 标签+趋势过滤） | 窄              |
| ③   | EMA21      | `ema21`   | 趋势动态价值区（**现状，行为不变**）                       | 高（已验证）                 | 最窄            |
| ④   | EMA55      | `ema55`   | 中深度回撤（1h ≈ 2.3 天）                                  | 中（须排列+斜率门）          | 中              |
| ⑤   | EMA144     | `ema144`  | 深回撤/大级别趋势线（1h ≈ 6 天）                           | 中（样本稀少）               | 宽→仓位自动缩小 |

**同根多触点命中时的标注优先级**：`retest > swing > ema21 > ema55 > ema144`
（横向结构语义强于均线；均线取最快的——最早确认、止损最紧）。

## 3. 判定规则（伪代码级）

统一约定：信号判定基于已收盘 K 线 `klines[-2]`；`o/h/l/c` 为该根开高低收；
方向 `dir=1 多 / -1 空`；band 默认 0.3%（可配）。

### 3.1 突破回测 `retest`

状态机在 scanner 侧维护（trigger 保持无 DB 依赖）：

```
# 事件记录：T1 突破触发时（trigger 返回 BREAKOUT），scanner 写入/更新事件
upsert breakout_events(symbol, dir, level=被穿轨道价, candle_open, expires_at=当前根+RETEST_WINDOW_BARS)
# 同向新突破 → 更新 level；反向突破 → 旧事件作废

# 触碰判定（trigger 内，scanner 查活跃事件传入 retest={price, dir}）：
多头: l <= level*(1+band) 且 c >= level      # 影线可下插，收盘须收回位上
空头: h >= level*(1-band) 且 c >= ... 对称:  c <= level
# 确认触发后事件标记 consumed（防重复信号）
```

- 窗口 `retest_window_bars` 默认 **24 根**（1h=一天，突破后越久回测语义越弱；0=关闭）
- 事件到期/反向突破即失效；不需 docs/21 的聚类状态机——**只记最近一次破轨，裸事件足够**

### 3.2 摆动结构 `swing`

复用 `recent_swings`（已现算、无前视：swing 点经 order 根确认后才有标签）：

```
多头: swings.lows 中最近一个 label=="HL" 的位 level，满足
      l <= level*(1+band) 且 c >= level
空头: swings.highs 中最近一个 label=="LH" 的位，对称
# 关键：只认 HL/LH（更高低点/更低压点）——LL/HH 不构成回踩结构，是接刀/追高
# 附加时效：bars_ago <= 40（太老的低点防守意义衰减）
```

### 3.3 EMA 多周期 `ema21 / ema55 / ema144`

触碰判定沿用现有语义（`低/高触及且收盘收回`），逐周期独立计算：

```
touch(emaX): l <= emaX <= c (多头)  /  c <= emaX <= h (空头)
```

**ema21 完全不变**（不加任何新门——保持已验证行为）。

**ema55/ema144 增设两道门槛**（防止把震荡当回踩）：

```
多头触碰 ema55 生效须同时满足:
  ① 排列: ema21 > ema55            （EMA55 之下还有 EMA21 托着，才是多头回踩）
  ② 斜率: ema55[-1] > ema55[-6]    （5 根斜率同向；走平的 EMA55 是震荡不是回踩）
多头触碰 ema144:
  ① 排列: ema55 > ema144（55 不可用时降级为只查斜率）
  ② 斜率: ema144[-1] > ema144[-6]
空头全部对称取反。
```

**数据窗口约束**（现值 `KLINE_WINDOW=240`，1h）：

- EMA55：240 根收敛出 ~185 个有效值，**可直接启用**；
- EMA144：240 根仅 ~96 个有效值，EMA 收敛不稳。**启用 ema144 前须把 kline_window 提到 ≥300**（页面可配，属系统配置非 scan_filters）。触发器内兜底：`len(klines) < 周期×1.7` 时该触点静默跳过。

**悬空拦截边界**：T2 纯金K（无任何触碰）的「距 EMA21 >1.5% 拦截」**保持不变**——
深回踩场景由 ema55/144 的**触碰确认**接住，不是放宽悬空门槛。两条路径语义清晰分离。

### 3.4 决策矩阵更新（docs/19 §4.1 增量）

| 行  | 条件                                      | 结果                                       | 变化                   |
| --- | ----------------------------------------- | ------------------------------------------ | ---------------------- |
| 1   | T1 Donchian 突破                          | BREAKOUT + **记录 retest 事件**            | +事件记录              |
| 2   | 当根触碰（任一启用触点）+ 金K             | PULLBACK_CONFIRM（touch_ref=最高优先触点） | 触点从 1 → N           |
| 3   | 有效 pending + 本根金K（未触碰）          | 次根确认（沿用 pending 的 touch_ref）      | pending 增记 touch_ref |
| 4   | 无触碰 + 金K                              | T2 纯金K + 悬空拦截                        | 不变                   |
| 5-7 | pending 处置（supersede/expire/窗口过期） | 不变                                       | 不变                   |

pending 机制完全复用：Stage-1 = 任一启用触点触碰，窗口仍是「恰好下一根」。

## 4. 数据与状态模型

1. **新表 `breakout_events`**：id / symbol / direction / level_price / candle_open /
   status(`active`|`consumed`|`expired`) / created_at。scanner 在 T1 触发时 upsert，
   确认消费、窗口过期/反向突破置失效；同币同方向同时最多一条 active。
2. **`pullback_pendings` 加列 `touch_ref VARCHAR(16) NULL`**（行3确认时回填 reason 与落库）。
3. **`scan_results` 加列 `touch_ref VARCHAR(16) NULL`**：触点维度落库，是下游三个消费方
   （前端展示 / 复盘快照 / AI 结构化字段）的唯一事实源。迁移走 database.py 既有
   `ADD COLUMN IF NOT EXISTS` 模式。
4. **`trade_reviews` 加列 `touch_ref VARCHAR(16) NULL`**：review_tasks 创建快照时从
   ScanResult 复制（与 signal_type/position/ema_state 同链路），复盘分组统计的依据；
   旧数据 NULL 自然归入「未标注」组，不污染新分组。
5. trigger.py 签名增量（全部关键字参数、向后兼容）：
   `detect_trigger(klines, direction, pending=None, flt=None, retest=None)`——
   scanner 查活跃事件后传入 `{price, direction}`；返回 trigger dict 新增 `touch_ref` 键。

## 5. 配置项（scan_filters，DB > env > 代码默认，逐键容错沿用）

| 键                         | 类型      | 默认        | 说明                                                                                      |
| -------------------------- | --------- | ----------- | ----------------------------------------------------------------------------------------- |
| `pullback_touch_refs`      | list[str] | `["ema21"]` | 启用的触点白名单，子集 ⊆ {retest, swing, ema21, ema55, ema144}；空/全非法回落 `["ema21"]` |
| `retest_window_bars`       | int       | 24          | 突破回测有效窗口（0=关闭 retest）                                                         |
| `structure_touch_band_pct` | float     | 0.3         | retest/swing 横向位的触碰带宽（%）                                                        |
| `ema_touch_min_bars`       | int       | 200         | 触碰判定的最小 K 线数（EMA144 兜底门，数据不足跳过该触点）                                |

4 个新键即完成分阶段开关：**默认 `["ema21"]` = 完全等价现状**，页面勾选即灰度，
任意组合可回滚。PUT /config 校验表同步扩充（\_SCAN_FILTER_RANGES + 白名单键校验）。

## 6. 下游联动（三个消费方）

### 6.1 AI 分析：信号块加结构化触点字段

现状核实（ai_analyzer.\_build_messages）：传给 AI 的是 币种/信号类型/当前价格/突破幅度/
K线形态/信号理由/信号闸门/形态位置/摆动结构/量能——**回踩位置目前只有 signal_reason
自由文本**（"回踩EMA21(1.23)企稳"），AI 无法结构化区分触点质量。

改造：信号块加一行独立字段（scan_result.touch_ref 直传，不经文本解析）：

```
回踩触点: 突破回测位（retest）| 摆动结构位（swing）| EMA21 | EMA55 | EMA144 | —
```

同步在纪律片段 `_RULE_TOUCH`（新增）给一句触点语义注解：retest=突破有效性确认、
swing=结构防守位、EMA=趋势价值区，供 AI 在盈亏比与止损结构判断时区分语义强度。
P1 锚点解析**不接入** retest/swing 位（维持 §10 出圈决定）。

### 6.2 前端：扫描结果表加触点标签

- `ScanResult` API 响应与 TS 类型加 `touch_ref` 字段（NULL 显示 "—"）；
- 扫描结果表信号类型旁渲染小标签（retest=「回测」/ swing=「结构」/ ema21=「EMA21」
  / ema55=「EMA55」/ ema144=「EMA144」），复用现有标签样式，无新组件。

### 6.3 复盘：触点维度胜率

- **快照复制**：review_tasks 创建 TradeReview 时从 ScanResult 复制 touch_ref；
- **分组统计**（api/scan.py 复盘分组接口）：分组键从 `signal_type` 扩为
  `(signal_type, touch_ref)`，响应 groups 增 touch_ref 字段；前端复盘页可按触点筛选/透视；
- **战绩回注（review_stats_inject）**：优先按 `(signal_type, touch_ref)` 分组查近 30 日
  胜率/EV，组内样本 ≥5 才注入；不足回落纯 signal_type 组——让「哪类触点真正赚钱」
  直接反馈进 AI 决策。**（2026-09-29 下线并整体移除**：历史胜率注入会以旧样本压制
  新触点/新类型的合理信号，评估只看当下事实；分组统计接口照常保留供人工复盘。）

- **质量分**：v1 **不动**（不加触点加分项）。先积累分组数据再决定是否给
  retest/swing 加权，避免无数据调参。

## 7. 测试计划

- trigger：多触点同根命中按优先级标注；ema55/144 排列+斜率门（排列破坏/斜率走平 → 不触发）；
  数据不足跳过 ema144；retest 带宽边界（影线下插收回 ✓ / 收盘破位 ✗）；swing 只认 HL/LH
  （LL 不触发）；ema21 行为与现测试逐条不变（回归保证）。
- scanner：T1 触发 upsert 事件；确认后 consumed；窗口过期/反向突破失效；pending.touch_ref 透传。
- 落库与展示：ScanResult.touch_ref 落库；AI 信号块含「回踩触点」行；复盘快照复制 touch_ref；
  分组统计按 (signal_type, touch_ref) 输出。
- scan_filters：新键解析/校验/容错（空列表回落、非法值逐键回落）。
- anchors/stats 既有测试不受影响。

## 8. 上线节奏与验证指标

| 阶段 | 动作                                | 通过标准                                         |
| ---- | ----------------------------------- | ------------------------------------------------ |
| P0   | 实现，默认 `["ema21"]`，行为零变化  | pytest 全过，线上信号量与改动前一致              |
| P1   | 页面启用 `retest + swing`，跑 2 周  | 分组复盘：两触点胜率 ≥ ema21 组的 80%，EV 不为负 |
| P2   | 启用 ema55（排列+斜率门生效）       | 同上；样本 ≥10 笔再评估                          |
| P3   | kline_window 提至 300 后启用 ema144 | 样本稀少，观察 ≥4 周再定去留                     |

淘汰机制：任一触点分组 EV 持续为负 → 页面取消勾选即下线，无代码回滚。

## 9. 风险与对策

| 风险                           | 对策                                                                    |
| ------------------------------ | ----------------------------------------------------------------------- |
| 信号量膨胀稀释 AI 配额         | 触点越多候选越多，但 ai_max_per_scan 上限不变，质量分排序自然截流       |
| ema55/144 在震荡市接刀         | 排列+斜率双门；4h 震荡过滤本就在前置层                                  |
| 摆动点标签滞后（order 根确认） | recent_swings 本就只含已确认点，无前视；时效门 bars_ago≤40              |
| 横向位与 EMA 双重计数          | 不去重——同根多触点是共振，标注取最高优先级即可，v1 不加分               |
| retest 事件表膨胀              | 同币单条 active + status 生命周期，量级 = 币种数×窗口内突破次数，可忽略 |

## 10. 不做什么（明确出圈）

- 不恢复 docs/21 的多源聚类/状态机/权重位表；
- 不做 Fib / 整数关口触点（历史实测噪音大）；
- 不给 AI 锚点解析接入 retest/swing 位（P1 锚点仍走摆动结构，避免再次耦合）；
- 区间边缘反转（震荡市策略）另立文档，不混入本触点体系。
