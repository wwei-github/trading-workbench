# 22-双周期扫描套

> 现行版本：RULE_VERSION `v2026-10-14-4`（2026-10-14）。本文对照代码整理，以代码为准；历史拍板记录见 docs/archive/。
>
> **一句话职责**：把「周期」从全局单例提升为**每套一份**的「扫描套 profile」，让**两套合约扫描链路并存**——`s1`（信号 1h / 背景 4h，现状，默认开）、`s2`（信号 4h / 背景 1d，新增，默认关）——信号链各自独立，执行引擎 / 全局风控 / 复盘归因**共享同一底盘**。
>
> **设计约束（历史教训）**：本项目 2026-10-10 刚把「多策略可插拔 + 影子层」整体退役为一套系统（docs/19 §八、archive/20）。本次**不复活** `strategy_registry` / 影子表 / 插件协议——只用**轻量常量注册表**（Python 常量，`services/scan_profiles.py`）实现，形态对应 archive/20 早已拍板的「共享底盘 + 双大脑」。

## 1. 两套定义与对照表

周期曾是**全局单例**（`settings.KLINE_INTERVAL` / `SystemConfig.kline_interval`），且背景周期 `"4h"` 在拉取点、闸门、触点枚举、提示词文本里**硬编码**。要并存两套，必须把「周期」提升为「扫描套 profile」参数并贯穿全链路。

| 套 | key | label | 信号周期 | 背景周期 | signal_window | htf_window | htf_touch_ref | 触点白名单 | 状态 |
|---|---|---|---|---|---|---|---|---|---|
| 套一 | `s1` | `1h·4h` | `1h` | `4h` | 240 根 | 300 根 | `ema21_4h` | 走页面配置（`pullback_touch_refs`，缺省 `DEFAULT_TOUCH_REFS`） | 现状链路，**默认开启** |
| 套二 | `s2` | `4h·1d` | `4h` | `1d` | 240 根 | 300 根 | `ema21_1d` | **内置触点集** `(ema21, ema21_1d, ema55)` | 新增，**默认关闭** |

- **根数口径**：`signal_window=240` / `htf_window=300` 两套**同值**——300 根是 TREMA144 的 SMA 种子 + 递推步数（根数口径，与周期无关），1d 用 300 根 ≈ 300 天同样够收敛，无需加宽（docs/17 §6）。
- **未知/空 key 回落**：`get_profile(key)` 对未知或 None 回落 `s1` 并告警（防拼错静默改了周期）；`DEFAULT_PROFILE_KEY="s1"`。
- **下游零回归**：`detect_indicator_candidate(..., profile=S1)` 默认参数即 s1，现有调用方（watchlist.refresh、全部测试）行为逐字不变。

## 2. 共享底盘边界

两套**共享同一底盘**（不按套复制基础设施），以此控制改动面：

| 维度 | 两套关系 | 说明 |
|---|---|---|
| 账号 | **共用** | 同一 `trade_engine` 账号扇出，不按套隔离 |
| 日/周/月熔断 | **共用** | 同一份风险预算与熔断阈值 |
| 连损降速 | **共用** | 同一份连损软熔断（配额减半） |
| AI 配额 / LLM 并发信号量 | **共用** | `ai_max_per_scan` / `LLM_CONCURRENCY` 全局唯一 |
| 筛选阈值 `scan_filters` | **共用** | JSONB 的所有键两套共用（DB > env > 代码默认）；**只有触点白名单按套内置**（触点语义与周期强绑定，共用会错配） |
| 持仓互斥 | **符号级** | 同一 symbol 只允许一个持仓（沿用 `trade_engine` 的 symbol 唯一判定），**先到先得**，不做 `(symbol, 套)` 双开 |
| 复盘归因 / RULE_VERSION | **共用** | 按 (rule_version, profile_key) 分组对比 |

**按套隔离**的仅三处：① 周期参数（signal/htf_interval、根数）；② 触点白名单（s2 内置）；③ 三层扫描防重（running 查询 / 10 分钟防重 / Redis 锁 key `scan:beat:{profile_key}:{bucket}`）——两套可并发跑，互不阻塞。

## 4. 触点集差异

- **新增跨周期触点 `ema21_1d`**（`scan_filters.TOUCH_EMA21_1D`）：语义 =「**4h 信号K影线触及 1d EMA21**」（s1 的 `ema21_4h` 语义 =「1h 信号K影线触及 4h EMA21」）。EMA21-on-htf 的计算逻辑本就周期无关，仅触点键不同；`TOUCH_LABELS` 增 `"ema21_1d":"EMA21(1d)"`。
- **触点白名单按套**：`s1` 走页面「回踩触点白名单」（`pullback_touch_refs`，缺省 `DEFAULT_TOUCH_REFS`）；`s2` 用**内置**触点集 `(ema21, ema21_1d, ema55)` 覆盖——**页面「回踩触点白名单」只作用于 s1**，s2 的触点勾选不生效。
- `ALL_TOUCH_REFS` 顺序新增 `ema21_1d`（`retest, swing, ema21, ema21_4h, ema21_1d, ema55, ema144`），触点优先级标注同源；`DEFAULT_TOUCH_REFS` 不动。
- ai_analyzer 触点语义注记增 `ema21_1d` 一行。

## 5. 两套启用开关语义（至少一套开）

`system_config` 新增两列：

| 列 | 默认 | 含义 |
|---|---|---|
| `scan_profile_s1_enabled` | `TRUE` | s1（1h·4h）是否运行 |
| `scan_profile_s2_enabled` | `FALSE` | s2（4h·1d）是否运行 |

- **可同时开**：两套并存并发跑。
- **至少一套开（硬约束）**：两套皆关视为**非法配置**——「策略配置」弹窗前端**禁止保存**并提示「至少保留一套运行」；后端 `PUT /config` 按**合并后的生效值**判定，两套皆关返回 **400**。
- **同时约束定时与手动**：关闭的套，定时任务不跑、页面手动触发同样早退（`skipped`）。
- 与自动交易双网开关同风格（实盘安全基线：新套默认关）。

## 6. 1d 闸门阈值待标定项

- `gate_4h` 的三重否决阈值是**根数口径**（EMA144 斜率 ≥0.5%/20 根、近 10 根缠绕 ≤2、ADX≥20），**根数上通用**，但**统计含义在 1d 上不等价**（1d 单根波动远大于 4h，0.5%/20 根的斜率门在日线上更易通过）。
- 本次 **s2 先沿用默认阈值**跑通链路（不臆造值）；上线后按现有影子 / 复盘链（`shadow.py` 前向窗口 + `actual_review.py` 按 `rule_version` / `profile_key` 分组）对比两套命中率与盈亏，再决定是否给 s2 单独阈值。
- 预留扩展点：`ScanProfile.gate_overrides: dict`（如 `slope_pct_min` / `adx_min` / `tangle_max`），**该字段本次不预先臆造值**。

### 6.1 风控 ATR 倍数按套标定（2026-10-14-4）

Risk Guard 的三个 ATR 倍数（`SL_MIN_ATR` 止损宽度下限 / `TP1_MAX_ATR` 止盈一距离上限 / `TP2_MIN_GAP_ATR` 止盈二间距下限）在 `settings` 里是**按 1h ATR 校准**的，实际乘的是**本套信号周期**的 ATR14。s2 信号周期 4h，ATR ≈ 1.5~2× 1h ATR，若沿用同一倍率会把实际止损/止盈距离放宽 ~2×——故按套重新标定，取 1h 等效倍率（÷2）：

| 常数 | settings 默认（s1，1h） | s2（4h，1h 等效） | 说明 |
|---|---|---|---|
| `SL_MIN_ATR` | `0.3` | `0.15` | 止损宽度下限 |
| `TP1_MAX_ATR` | `2.0` | `1.0` | 止盈一距离上限（ATR 腿） |
| `TP2_MIN_GAP_ATR` | `0.5` | `0.25` | 止盈二间距下限（ATR 腿） |

- **落点**：三常数定义在 `scan_profiles.ScanProfile`（`sl_min_atr` / `tp1_max_atr` / `tp2_min_gap_atr`，默认 `None`），由 `resolve_risk_atr(profile_key)` 统一解析；`None` 表示沿用 `settings` 默认。s1 三字段保持 `None` → **逐字零行为变化**。
- **注入载体**：`profile_key` 随 signal dict 下传（沿用 `signal["tactic_names"]` 白名单闸门同构的载体模式），`validate_decision` / `render_signal_gate_block` / `render_system_prompt` 的新参数均为 `Optional` 且默认 `None` → 旧直调路径（含测试）回落 `settings`。
- **同源原则**：闸门（`risk_guard`）与两管线提示词（`ai_analyzer` P0 / `ai_agent` P1）都从 `resolve_risk_atr` 取值——AI 看到的倍数必须等于程序实际执行的倍数。
- **R 腿不动**：`TP1_MAX_R` / `TP2_MIN_GAP_R` 是止损距离口径、与周期无关，不经此解析。

## 7. 已知限制

- **漏斗关卡文案**：关卡码 `gate_4h` / `htf_state_lock` **字符串不变**（历史行与前端标签映射兼容）——s2 轮次里显示为「4h闸门」属**已知文案限制**（s2 实际背景为 1d），后续可按 profile 渲染。
- **筛选阈值不按套拆**：两套共用同一份 `scan_filters`；若需按套各调阈值，需把 `scan_filters` 拆为 `scan_filters_by_profile` + 配置页切换（本次不做）。
- **排序 / 位置沿用既有口径**：`position_ref`、质量分等沿用根数口径，未按套重标。

## 8. 数据模型与 API

- **`ScanRecord.profile_key`**：`String(16)`，NOT NULL DEFAULT `'s1'`，建索引；**历史行自动归 `s1`**（幂等迁移 `ADD COLUMN IF NOT EXISTS ... DEFAULT 's1'`）。
- **`TradeRecord.profile_key`**：可空快照，开仓时落来源套（沿用 `signal_type` / `rule_version` 快照惯例）。
- **`POST /scans`**：新增可选 `profile_key`（默认 s1）；「running 则 409」改为**按 profile** 判重。
- **`GET /scans/status`**：`ScanStatusResponse` 增 `profiles: [{key, label, enabled, last_scan, is_scanning}]`（供前端套选择器与状态展示）；原 `config.*` 保持 s1 口径。
- **`POST /scans/analyze`**：新增可选 `profile_key`；htf 拉取按 profile。
- **指纹**：`compute_fingerprint` 加入 `profile_key` 维度，防两套对同币同价命中同一指纹复用旧结论。
