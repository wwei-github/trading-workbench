## 1. 概览

AI 分析在链路中的位置：

```
扫描命中（scanner → ScanResult 落库）
    ↓
AI 分析任务（backend/app/tasks/ai_tasks.py）
    闸门 → 配额 → 指纹缓存 → LLM 调用（P0/P1 双管线）→ 落库 ai_analyses
    ↓
程序复核（risk_guard 校验回炉 / 双评委 veto / 4h 方向硬约束兜底）
    ↓
即时开仓分发（suggest 且评分 ≥60 → trade_engine 开仓闸门 → 开单）
```

| 模块 | 文件 | 职责 |

## 2. 分析管线

### 2.1 任务编排（ai_tasks.py）

`run_ai_analysis_task`（父任务）→ `run_ai_analysis_single`（子任务，Celery group 按币种并行）：

1. **开关闸门**：`cfg.ai_analysis_enabled` 只拦批量自动分析（与 trading_enabled 解耦）；手动单币重分析不受限；`AI_API_KEY` 未配置直接跳过。
2. **配额**：批量按 `quality_score` 降序、同分按 24h 成交额取前 `ai_max_per_scan`（scan_filters 生效值，env 缺省 `AI_MAX_PER_SCAN=10`）；当前账号当日连损 ≥2 时配额减半（连损降速软熔断，docs/24 A3）。
3. **LLM 并发信号量**：Redis zset 实现，全局上限 `LLM_CONCURRENCY`（默认 4）；等待超时 900s 降级放行。
4. **指纹缓存**：`compute_fingerprint` = symbol + signal_type + position + pattern + touch_ref + 价格 0.5% 对数分桶；`FINGERPRINT_TTL_MIN`（默认 60min）内同指纹沿用旧结论（`_copy` 复制落库）。**价格区失效不沿用**：现价已越过旧结论的止盈一/止损（`_conclusion_still_valid`）时重新分析。手动重分析（force）不短路。
5. **数据准备**：ExchangePool 拉 500 根 K 线（不足则强刷重取）；**现价更新为分析时刻最新价**（`klines[-1][4]`，未收盘 K 线收盘价——扫描到分析之间价格可能已移动，所有锚点换算以此为基准）；`recent_swings`（收盘价摆动点，高低点各 20）；4h K 线 200 根（失败降级为无 4h 背景）。
6. **口径解析**：`resolve_risk_budget`（pct/fixed 双口径，risk_label 注入提示词）；`cfg.max_stop_pct` 止损宽度硬上限注入门槛块。
7. 调用 P0/P1 管线 → 双评委（可选）→ `enforce_htf_constraint` → `is_pullback_wait` 标记 → 落库 → `push_done`。

落库后 `_dispatch_immediate_open`：suggest 且 `recommendation ≥ TRADING_MIN_RECOMMENDATION(60)` 且 `trading_enabled` 时分发开仓任务（唯一开仓通道；待回踩单照常分发，由开仓闸门按容差判定）。

### 2.3 程序入场门槛块（render_signal_gate_block）

ai_analyzer.py:93。触发器类型信号（trigger_breakout / trigger_trend_breakout / trigger_pullback / trigger_pullback_confirm）渲染对应门槛，**阈值读 scan_filters 生效值**（2026-09-28 动态化，消除与页面筛选配置的文本分叉），非触发器类型输出空串：

- **trigger_breakout**：突破位=收盘越过最近未破摆动结构前高；突破幅度 ≥`breakout_threshold`（毛边不算），>`breakout_max_pct` 视为追高不触发；放量（量 ≥ 中位量 `breakout_vol_ratio` 倍）为加分项（质量分+5，不拦截）；突破K长实体（实体 ≥70% 全长）。
- **trigger_trend_breakout**：收盘破 `breakout_channel_bars` 根 Donchian 滚动高低轨，其余同上。
- **trigger_pullback / trigger_pullback_confirm**：回踩触点 5 类（优先级 retest>swing>ema21>ema55>ema144）；横向位触碰带宽（影线可入带收盘守住）；两段式确认（触碰后当根同向金K，或上根触碰+本根金K）。
- **突破类公共段——止损锚降级链**（docs/23）：结构锚（摆动前低/前高外 0.3%）优先；仅当"唯一不达标原因是盈亏比"时才降级近锚（突破K极值外 0.3%），近锚达标才可开单并输出 `stop_anchor="near"`；量比 <1 缩量突破无近锚资格；近锚后盈亏比 >4 重新评估；近锚宽度须 ≥0.3×ATR。
- **止损宽度硬上限**：`stop_cap_pct`（cfg.max_stop_pct）非空时注入"程序硬闸，超限必弃单"，供 AI 定止损前自验（2026-09-29，避免无效调用）。

### 2.4 系统提示词结构与纪律段（P0）

`SYSTEM_PROMPT`（ai_analyzer.py:164）为带槽位模板，`render_system_prompt(risk_label)` 渲染（页面预览与实际调用同源）。纪律段为模块级常量（`_RULE_*`），P0/P1 共享防文本漂移：

| 纪律段 | 内容要点 |
|---|---|
| `_RULE_HTF_HARD` | **方向硬约束（最高优先级）**：4h 强多头仅可开多、强空头仅可开空，违反一律 skip；唯一"程序无法补救只能 skip"的规则（另有程序兜底 enforce_htf_constraint） |
| `_RULE_VOTE` | 指标多数决：指标块末尾"指标方向"行为程序化统计（7 项投票），多空票数谁多以谁为准，平衡时自行结合 K 线结构与量能 |
| `_RULE_EMA` | EMA 排列不构成方向限制：多头排列不禁止做空，仅是趋势背景参考 |
| `_RULE_SL` | 止损纪律：结构位优先、影线极值兜底、两锚取更远者（摆动点与最近 5 根极值取更远）外 0.3%~0.5%；无摆动结构时用极值锚至少 0.3%；宽度不设百分比上限；程序不改写止损价 |
| `_RULE_TP` | 止盈锚定：距现价 ≤1×ATR 的位是争夺位不算目标；止盈一挂更远第一档结构位外侧留 0.2%~0.5%；**禁止跳档凑盈亏比**（不足 {rr_min}R 直接 skip）；止盈二取下一档且更远；无结构位时止盈一 = 入场 ± {rr_min}×止损距离 |
| `_RULE_STRUCT` | structure_break 三子形态（123法则/N字结构/2B法则）按行情阶段择一，震荡区间信号归 range_edge |
| `_RULE_DIRECTION` | 方向纪律：优先支撑做多/压力做空，现价离开结构位后按动能顺势给入场价 |
| `_RULE_TOUCH` | 回踩触点语义注解：retest 结构意义最强；有触点时止损优先锚定触点位 |

字段契约部分内嵌的关键纪律：**只允许现价入场**（2026-09-30 二次拍板，禁止回踩侧入场价——程序标记"待回踩"且不下单；RR 无法达标直接 skip，不得给回踩等待计划）；**三价硬约束**（做多 SL<入场<TP1，做空 TP1<入场<SL，违反直接打回浪费重试）；**盈亏比铁律**（程序按三价复算，声称值无效）；推荐度锚点（50=勉强达标 / 70=双重共振 / 85+=三重共振）；analysis ≤300 字"1. 2. 3."序号分点。

注入顺序（系统提示词末尾）：命中技能正文（`skill_library.render_matched`，P0 无工具循环直接注入）→ 用户自定义策略（`strategy_prompt`，**优先级最高**：用户策略 > 技能规则 > 默认纪律）。

P1 Agent 系统提示词（ai_agent.py:96 `AGENT_SYSTEM`）复用 `_RULE_HTF_HARD`/`_RULE_VOTE_BRIEF`/`_RULE_STRUCT_BRIEF`（analysis→reason 字段名适配），并叠加：锚点表达纪律（禁止编造绝对价格）、submit_decision 唯一出口、事实包数据边界与环境工具按需批量调用、近锚降级链 P1 版（`NEAR_STOP_RULE_AGENT`，仅突破类注入）。

## 3. 输出契约与程序复核

### 3.1 JSON 契约

P0 输出契约 = `risk_guard.TradeDecision`（Pydantic）：

| 字段 | 说明 |
|---|---|
| `trade_decision` | "suggest" / "skip"（必填） |
| `skip_reason` | skip 时必填，"1. 2. 3."序号最多 3 条 |
| `direction` | long / short，skip 时空 |
| `trade_type` | trend_follow / structure_break / range_edge 三选一（`TRADE_TYPES`；123/N字/2B 已合并入 structure_break） |
| `stop_anchor` | structure / near，仅突破类需输出 |
| `tactic_name / tactic_reason` | 战法命中标注（2026-10-02，仅借鉴不影响结论）：name 逐字取自本次注入战法清单，reason ≤60 字对照依据；未命中输出空串 |
| `entry_price / stop_loss / take_profit_1 / take_profit_2` | 三价+可选第二止盈，skip 时 0。**trail 模式（tp_mode=trail）时 TP2 强制清零**（程序 `_handle_submit` 硬清零）；TP1 仍必填——仅作盈亏比铁律校验参考价，程序不挂单 |
| `tp_mode` | 止盈模式二选一（2026-10-10，docs/19 §3.4）：`ladder` 分批止盈（震荡/结构位近，TP1/TP2 落袋）/ `trail` 纯跟踪（4h 强趋势、结构位远，武装保本后跟进让利润奔跑）；suggest 必填、skip 输出 null；system_config.tp_mode 强制配置优先于 AI 选择 |
| `risk_reward_ratio` | AI 声称值（落库用程序复算值覆盖） |
| `position_pct` | AI 估算值（程序按固定亏损法覆盖） |
| `recommendation` | 0-100：skip ≤30，suggest ≥50 |
| `analysis` | ≤300 字中文分点推理 |

P1 经 `submit_decision` 工具提交锚点（entry_ref/stop_ref/tp1_ref/tp2_ref + offset_pct，另有 `tp_mode` enum 参数，trail 时 tp2_ref 不提交），程序 `_resolve_price` 换算绝对价后构造同一 TradeDecision——两管线落库结构一致。

  "trade_type": "trend_follow",

### 3.2 parse_and_validate 校验项（risk_guard.py:339）

`parse_and_validate` = `normalize_raw`（宽松归一化：字符串数字转 float、direction 空串→None、非法 stop_anchor→None）→ Pydantic 校验 → `validate_decision`。校验链（2026-09-15 收缩拍板，仅保留可行性铁律）：

1. **skip 基本项**：skip_reason 非空；recommendation 超 30 仅修正不打回。
2. **suggest 基本项**：direction / trade_type / 三价为正，缺一打回。
3. **方向-价格一致性**（2026-09-16 恢复硬校验，ETHUSDT 空单反向止损案例）：多单 SL<entry<TP1、空单 TP1<entry<SL；TP2>0 时同侧且比 TP1 更远。RR 铁律全程 abs() 对方向盲，反向止损照样达标，此为交易所可挂性铁律。
4. **近锚一致性**（docs/23）：突破类 AI 声明 `stop_anchor=near` 时，止损须贴近突破K线极值锚（`klines[-2]`，最后一根已收盘）外 0.3%（`NEAR_ANCHOR_BUFFER`），容差 ±0.5%（`NEAR_ANCHOR_TOLERANCE`）；防"结构锚止损伪装近锚"。数据异常放行仅记 warning。
5. **盈亏比铁律**：RR = |TP1−入场| ÷ |入场−SL| 按三价复算 ≥ `AI_RR_MIN`(1.5)，AI 声称值不信。
6. **战法白名单闸门**（2026-10-02，非打回型）：`tactic_name` 不在本次注入清单（signal 携带 `tactic_names`，调用方从活动战法按环境装载）→ 直接清空不落库，reason 同进同出——LLM 编造/改写战法名丢弃，防脏键污染复盘分组；无白名单（旧调用方）一律清空。清单外**不打回不 skip**，仅丢标注。

**仓位复算**（固定亏损法，AI 不自报仓位）：仓位% = 风险预算 ÷ 止损距离%。pct 模式（默认）预算 = `RISK_BUDGET_PCT`(3%)；fixed 模式（risk_budget 实额 USDT）时 position_pct 置 None（分析期无钱包上下文，真实仓位由开仓引擎实算）。suggest 落库值：三价 round 8 位、RR 复算值、recommendation clamp 50~100、stop_anchor 归一（near 仅突破类有效，回踩类误报按 structure 落库）。

### 3.3 校验回炉循环（analyze_with_guard，ai_analyzer.py:485）

P0 入口 `analyze_with_guard`：1 次初始调用 + 2 次反馈重试（共 3 轮）：

- **校验失败**：违规明细以 user 消息反馈，AI 原始输出以 assistant 消息回放进上下文（模型看着自己原文改错，Reflection）。
- **解析失败**：`_LLMOutputError` 携带原始 content；上次输出非空时同样回放，附错误摘要（截断 200 字符）要求只输出合法 JSON。
- **重试耗尽**：`build_forced_skip("AI 输出多次未通过风控校验", last_violations)` 强制 skip——任何路径都有确定结论落库（recommendation=10，skip_reason 附违规明细前 3 条，截断 500 字符）。

### 3.4 AI 建议之后的程序级裁决

| 环节 | 代码 | 行为 |
|---|---|---|
| 双评委 veto | `dual_judge.run_dual_judge` | 转 forced skip，`veto_original` 快照原始三价（source=dual_judge），recommendation 压 ≤30 |
| 4h 方向硬约束兜底 | `technical.enforce_htf_constraint` | 强多背景下开空 / 强空背景下开多 → 程序强制 skip（LLM 无视提示词时把关），同样写 `veto_original`（source=htf_constraint） |
| 待回踩判定 | `risk_guard.is_pullback_wait` | suggest 且入场在现价回踩侧 → 仅落"待回踩"标识，不下单（提示词已禁回踩侧入场，保留作兜底）；`open_block_reason` 预置未开单原因 |
| 开仓闸门 | `trade_engine._attempt_open` | 交易所侧最后一道防线：方向-价格复核、现价偏离 ≤1%、RR 按现价复算 ≥1.5、强平闸门（`liquidation_gate_pct` = 1/杠杆 − MMR − 缓冲）、滑点实测、保证金可用性 |

落库（`_upsert_ai_analysis`，latest-wins）：决策字段 + `rule_version`（RULE_VERSION 快照，复盘按版本分组）+ `veto_original` + `pullback_wait` + `fingerprint` + `stage_trace`（P1）。

## 4. 双裁判 / Agent / 技能库

### 4.1 双评委辩论（dual_judge.py）

对**已通过风控校验的 suggest 决策**做多空对抗复核（移植 TradingAgents 思想）：

1. 多头评委（BULL_PROMPT）与空头评委（BEAR_PROMPT）各出 ≤120 字论据，二者互不依赖，`ThreadPoolExecutor` 并行调用。
2. 裁判（JUDGE_PROMPT）基于决策 + 辩论输出 `{"verdict": keep|veto, "reason": ≤80字}`；仅裁判挂 JSON 模式（评委输出论据正文）。
3. **安全边界**：裁判只能 keep 或 veto，无权修改价格/方向——杜绝"评委幻觉价位"绕过 Risk Guard；摇摆不定倾向 keep。
4. 事实包增厚（docs/24 D3）：ai_tasks `_build_judge_signal` 注入指标块与摆动结构摘要，评委可用数据核对三价与结构位矛盾（止损落在摆动区间内部、止盈近于争夺位）。
5. **降级哲学**：任何异常（LLM 失败/解析失败）降级为 keep——辩论是增强层，不阻塞主流程。
6. **veto 闭环**（docs/24 A5a）：否决时原始建议三价随 skip 快照落库（`veto_original`，source=dual_judge），复盘任务据此回放"被否决建议的假想表现"，对比通过单验证 veto 贡献；4h 硬约束否决（source=htf_constraint）走同一快照键名，便于分组对比。

调用链（ai_tasks.py `run_ai_analysis_single`）：P0/P1 管线产出 suggest → `push "gate"`（"⚖️ 双评委辩论复核中…"）→ `run_dual_judge` → keep 原样 / veto 转 forced skip → 后续 enforce_htf_constraint。

开关 `system_config.dual_judge_enabled`（默认 True，models/system_config.py:22）。开启时每笔 suggest 多花 3 次 LLM 调用。

### 4.2 P1 Agent 工具循环（ai_agent.py）

`analyze_coin_agent`：手写工具循环（已验证 GLM tool-calling 稳定，不引入框架），`MAX_ROUNDS = 5`：

- **工具**（TOOLS_SCHEMA，6 个）：`get_recent_klines`（30~200 根历史）、`get_funding`（资金费率+持仓量）、`get_market_breadth`（BTC/ETH EMA 形态+24h 涨跌）、`get_fear_greed`（恐贪指数）、`load_skill`（读技能正文）、`submit_decision`（唯一出口）。
- **锚点机制**：模型不报绝对价格，报 `(ref, offset_pct)`；`LEVEL_REFS` 枚举 = support / resistance / market / 线外锚点四件套（resistance_zone_low 等，解析到现价同侧第 nth 近摆动点，止盈一/二各一档）+ signal_low / signal_high（突破K极值，仅近锚用）。`_resolve_price` 换算，非法锚点走 errs 重试路径不静默。
- **校验即工具**：`submit_decision` 内嵌 `validate_decision`，违规明细作为工具结果返回，模型看着错处改；`stop_anchor` 由程序从 stop_ref 推导（signal_low/high → near），比 AI 自报更难滥用。
- **效率设计**：事实包首轮给足（40 根含 quote_vol 的 CSV / 摆动结构 / ATR / 指标块），首轮即可 submit；环境数据不在事实包，需时同轮批量调工具；轮内多工具 `ThreadPoolExecutor` 并行执行，结果按 tool_call 顺序回填（截断 12000 字符）。
- **收尾**：`MAX_ROUNDS` 内未提交有效决策 → `build_forced_skip`；返回值带 `stage_trace`（轮次/工具调用/耗时轨迹，落库供 `/ai-trace` 查询）。

与 ai_analyzer 的分工：P0（单次调用 + 流式 + 校验回炉）是批量生产主路径；P1（工具循环 + 锚点）仅在手动单币重分析且开关开启时使用，供需要补充数据/技能按需加载的场景。

### 4.3 技能库（skill_library.py）

可插拔领域能力包：`backend/skills/<name>/SKILL.md`，frontmatter 手写解析（name/description/use_when/version）。现有 5 个技能：

| 技能 | use_when | 要点 |
|---|---|---|
| trend-pullback | signal_type == uptrend/downtrend | 顺势回踩：锚点/止损/止盈纪律，EMA 矛盾降级 |
| structure-break | trend_reversal/uptrend/downtrend | 123·N字·2B 合并打法详解 |
| range-bound-fade | signal_type == range_bound | 区间高抛低吸，破位失效规则 |
| pin-bar-handling | pin_bar == true | 长影线确认加强/形态矛盾/止损放影线极值外仓位减半 |
| funding-extreme-handling | funding_extreme == true | 费率极端拥挤方向逆向处理（P0 事实中恒 False，仅 Agent get_funding 自查后按需 load） |

机制要点：

- **事实程序算，模型不猜**：`build_facts(signal, klines)` 产出布尔事实（signal_type / pin_bar=最后已收盘K影线>2×实体 / role=support|resistance / funding_extreme 恒 False / narrow_range 恒 False），P0/P1 共用。
- **use_when 判定安全**：事实字段替换 → 字符白名单过滤 → 空 builtins eval，无法逃逸。
- **两种消费方式**：P0 `render_matched`——命中即注入系统提示词正文（单条 4000 / 总量 6000 字符截断）；P1 `render_index`——索引段标注【当前命中】，模型按需 `load_skill`（正文 8000 字符截断），渐进式披露省 token。

## 5. 流式与进度

### 5.1 流式调用（llm_client.stream_completion）

- **背景**（2026-09-30 网关挂死治理）：GLM 推理模型非流式请求长推理期间零字节返回，读超时把"正确推理中"误杀成"网关挂死"（线上 4 连挂满 240s）；thinking 关闭参数被网关拒绝，**流式是唯一可行解**——reasoning 增量持续到达保持 socket 活跃。
- **StreamResult**：content（仅拼 delta.content，reasoning_content 增量不进正文）+ finish_reason + first_token_s（首正文增量耗时，-1=全程无正文）+ total_s，供延迟观测日志。
- **on_progress 回调**：首个增量立即触发、此后 ≥2s 节流，携带 reasoning_chars / content_chars / elapsed_s。
- **共享单例**：`get_client()` 模块级单例复用 httpx 连接池（省每次 TLS 握手 100~500ms），`max_retries=1`（SDK 默认 2 次会放大超时至 3×timeout），timeout=`AI_CALL_TIMEOUT_S`。
- **max_tokens=32000**：GLM 思考型 reasoning 计入配额，12000 曾被思考过程整体耗尽（3 次重试全空内容强制 skip）。
- **JSON 容错**：`json_mode_kwargs()`（`LLM_JSON_MODE` 开启时带 response_format=json_object，默认关——部分兼容网关 400）；`parse_llm_json` 标准解析失败降级 json_repair 修复（未转义引号/尾逗号），修复出空结果同样按失败抛；markdown 包裹在 `_call_llm` 剥除。

### 5.2 进度事件（ai_progress.py）

- **存储**：Redis list（key `ai:progress:{scan_result_id}`），逐事件追加，TTL 1h；push 任何异常静默失败（进度展示不影响主流程）。
- **事件类型**：`start`（symbol+pipeline）/ `gate`（缓存沿用、双评委复核中、网关重试等提示）/ `round`（P1 轮次）/ `tool`（P1 工具调用）/ `llm`（P0 流式增量计数，≥2s 一条，"推理中"活进度）/ `done`（decision+note）/ `error`。
- **读取**：`GET /scans/ai-progress/{scan_result_id}`（scan.py:1047）合成 status——落库=done、末事件 error=error、有事件=running、无事件=idle；前端 2s 轮询。
- **清理**：单币重分析触发时 `ai_progress.clear` 清空旧事件，保证事件流只属于本次分析。

P0 管线一次典型分析的事件流（前端按 ts 排序展示）：

```
{"t":"start","symbol":"XXXUSDT","pipeline":"agent"}
{"t":"round","round":0,"tools":[],"note":"单次调用管线思考中…"}
{"t":"llm","attempt":0,"reasoning_chars":18432,"content_chars":912,"elapsed_s":46.3}   ← ≥2s 一条
{"t":"done","decision":"suggest","note":"1. EMA多头排列…（截断80字）"}
```

P1 管线额外产生 `tool` 事件（`{"t":"tool","tool":"get_funding","args":""}`）与逐轮 `round` 事件，由 `progress_cb` 从 Agent 循环透传。

### 5.3 失败重试

子任务网关超时（"timed out"/"timeout"）：90s 后自动重试（max_retries=2，推 gate 事件），额度用尽推 error 收尾（否则前端永远停在"重试中"）；其他异常推 error + rollback。父任务分发失败自动重试（countdown=30，子任务幂等）。
