# 04 - 关键位筛选重构需求

> **状态**：待确认（确认后开发）
>
> **一句话需求**：筛选逻辑不再以"是否突破"为核心条件，改为 **价格处于关键位 + 出现 12 金K 即命中**；信号类型按高低点结构分类（上涨/下跌/反转/震荡），新增"位置"字段记录 12 金K 出现的位置。

---

## 1. 背景与现状问题

### 1.1 当前逻辑（三个独立策略，任一命中即可）

| 策略 | 核心条件 | 问题 |
|------|---------|------|
| 下跌突破 downtrend_breakout | LH+LL 结构 + 收盘价**刚突破**下跌趋势线（前一根还没突破） | 条件苛刻：只捕捉"突破后第一根K线"，错过突破后回踩关键位的入场点 |
| 上涨回调 uptrend_pullback | HH+HL 结构 + 回调至趋势线/HL 附近 + 看涨形态 + **前面不能有连续阳线** | 只认上涨中的回调，且形态只看 4 种看涨形态 |
| 区间震荡 range_bound | 水平/收敛结构 + 区间上下沿 30% 区域 + 指定形态 | 只覆盖震荡场景 |

**共性问题**：
1. 三个策略各自为政，过滤条件互不兼容，逻辑分散在 3 个文件里；
2. 形态识别只有 6 种（且实际过滤只用其中 4-5 种看涨形态），远少于交易系统的 12 金K；
3. **没有"关键位"概念**——前高前低、支撑压力、斐波那契位都没有计算，与《03-交易系统.md》的关键位体系脱节；
4. 缺少统一的"市场结构"分类，无法直接回答"这个币现在是什么状态"。

### 1.2 新逻辑核心思想

```
旧：结构判定 → 突破/回调/区间条件 → 形态加分
新：结构分类（打标签）→ 计算关键位 → 价格在关键位？→ 出现12金K？→ 命中
```

**过滤条件只有两个**（与《03-交易系统.md》§6.1 一致）：
1. **位置**：最新已收盘 K 线触及某个关键位（区域）；
2. **形态**：该 K 线出现 12 金K 之一。

信号类型与位置不再作为"门槛"，而是作为**分类标签**输出，供排序、展示和 AI 分析使用。

## 2. 关键位模块（新增 `key_levels.py`）

### 2.0 计算优化（2026-09-12）

在原始设计上补充两项，解决"新旧位置同等对待、固定 0.5% 区域不适应波动差异"的问题：

1. **触及时间加权**：每次触及权重 = 2^(−bars_ago/60)（半衰期 60 根已收盘 K 线）；
   支撑/压力聚类簇按**总权重 ≥ 1.2** 保留（≈近期 2 次触及；单点上限 1.0 天然要求 ≥2 次），
   纯久远旧点自然衰减淘汰。`touches` 仍为原始次数，`weight` 为加权强度（随关键位一并入库与进 AI 事实包）。
2. **区域半宽随 ATR 自适应**：半宽 = 0.5×ATR(14)/价格，限制在配置 `key_level_tolerance` 的 [0.5×, 2×] 倍内
   （默认配置 0.5% → 实际区域 0.25%~1%：高波动币更宽防假触及，低波动币更窄防信号泛滥）。
   ATR 计算下沉到 key_levels.calc_atr，risk_guard / AI 事实包共用。

摆动点右确认滞后（order=3）为刻意保留：取消右确认会引入重绘信号，危害大于滞后。

**优化效果回测（2026-09-12，12 币 × 1h × ~1000 根，事件 n≈8400）**：
判定口径统一为「收盘价距位中心 ≤0.25% 算触及；24 根内先到中心 ±0.75×ATR 算反应、先收盘越过 ±0.5×ATR 算击穿」：

| 指标 | 旧逻辑 | 新逻辑 |
|---|---|---|
| 平均关键位数 | 14.0 | 4.8（−66%） |
| 触及事件数 | 4763 | 3744（−21%） |
| 反应率（关键位质量） | 63.4% | 64.9%（+1.5pp，p≈0.08 边缘显著） |

按类别拆分验证时间加权论点：**被加权淘汰的旧位反应率仅 58.4%，比保留位 65.8% 低 7.4pp（n=2050，p<0.001 显著）**——
淘汰确有其效；整体提升温和是因为样本近半是前高/前低（两逻辑共有，64.4%），该部分不变。

### 2.1 关键位的构成

> **2026-09-12 两类化**：关键位标签收敛为两类——**支撑位（support）/ 压力位（resistance）**，
> `kind` 由角色动态推导（位在当前价上方=压力位、下方=支撑位，`kind == role`）。
> 前高/前低/区间顶/区间底不再作为新值产生（三种来源照常计算，仅标签收敛），
> 历史数据中的 `prev_high / prev_low / range_top / range_bottom` 保留兼容展示。

| 关键位 | 来源 | 类型 |
|--------|------|------|
| **支撑位** | 下方摆动低点（最近点 + 历史聚类 + 震荡下边界） | 支撑 |
| **压力位** | 上方摆动高点（最近点 + 历史聚类 + 震荡上边界） | 压力 |
| 斐波那契 50/61.8/80%（二期） | 最近一段趋势段回撤 | 支撑/压力 |

### 2.2 计算规则

1. **摆动点**：复用现有 `find_swing_points(closes, closes, order)`，收盘价计算，order 沿用系统配置（默认 3）。
2. **前高/前低**：摆动点序列中**最近一个**高点/低点。
3. **支撑/压力位聚类**：将更早的摆动高点（或低点）按价格聚类——相互距离 ≤ `merge_threshold`（默认 0.5%，可配置）的点合并为一个水平区域，区域中心=均值，出现次数越多权重越高（权重可用于排序）。
4. **关键位是区域**：每个关键位有 `zone_low / zone_high`（中心价 ± `zone_tolerance`，默认 0.5%，可配置），价格进入区域即算"到位"。
5. **角色互换**：前高被收盘价跌破后，转为支撑位（反之亦然）——按最近一次被突破的方向决定当前角色。
6. **有效期**：只取最近 `kline_window` 根 K 线内的摆动点（现有窗口 240 根）。

### 2.3 输出结构（示例）

```python
{
    "levels": [
        {"kind": "resistance", "price": 0.3910, "zone_low": 0.3890, "zone_high": 0.3930, "touches": 3, "role": "resistance"},
        {"kind": "resistance", "price": 0.3782, "zone_low": 0.3763, "zone_high": 0.3801, "touches": 1, "role": "resistance"},
        {"kind": "support",    "price": 0.3528, "zone_low": 0.3510, "zone_high": 0.3546, "touches": 2, "role": "support"},
        {"kind": "support",    "price": 0.3440, "zone_low": 0.3423, "zone_high": 0.3457, "touches": 2, "role": "support"},
    ]
}
```

> `kind == role`（2026-09-12 两类化）；同角色多位按价格区分，距现价最近的一档是主参考。
> 斐波那契位本期不做（见待确认问题 2）。

## 4. 信号类型：按高低点结构分类（新增 `structure.py`）

### 4.1 分类规则（基于摆动点序列，收盘价计算）

对最近 2~3 个摆动高点和低点：

| 信号类型 | 代码标识 | 判定规则 |
|---------|---------|---------|
| **上涨趋势** | uptrend | 高点递增（HH）**或**低点递增（HL），且未触发反转条件 |
| **下跌趋势** | downtrend | 高点递减（LH）**或**低点递减（LL），且未触发反转条件 |
| **趋势反转** | trend_reversal | 下跌结构（LH+LL）中**收盘价突破最近前高**；或上涨结构（HH+HL）中**收盘价跌破最近前低**（即 123 法则第②步信号） |
| **震荡区间** | range_bound | 高点水平/收敛 + 低点水平/收敛（复用现有斜率判定）；或高低点方向冲突（如 LH+HL） |
| **未分类** | unknown | 摆动点不足或结构无法识别（是否允许命中见待确认问题 3） |

**分类优先级**：趋势反转 > 趋势 > 震荡 > unknown。
**说明**：分类只做"打标签"，不构成过滤门槛（与旧逻辑的本质区别）。

## 5. 位置字段（新增 `position`）

### 5.1 取值定义

> **2026-09-12 两类化**：`position` 收敛为 `support / resistance` 两个新值；
> 历史行的 `prev_high / prev_low / range_top / range_bottom` 保留兼容展示。

12 金K 所在 K 线（最新已收盘 K 线）**触及的关键位**，取距现价最近（收盘价距中心最近）的一档：

| 位置 | 代码标识 | 触发条件 |
|------|---------|---------|
| 支撑位 | support | 最新已收盘 K 线影线触及支撑位区域，且收盘在持住侧（≥ zone_low） |
| 压力位 | resistance | 最新已收盘 K 线影线触及压力位区域，且收盘在持住侧（≤ zone_high） |
| 放量突破 | breakout（signal_type） | 收盘越过整个关键位区域 + 量能 ≥1.2×均量 + EMA 同向（见 §5.4） |

**判定口径**：触及 = 影线与区域重叠且收盘在持住侧（support-like 位要求收盘 ≥ zone_low，
resistance-like 位要求收盘 ≤ zone_high）——收盘越过远侧的破位方向不属于触及，
归放量突破分支管。同分取距区域中心最近者作主位置。

### 5.2 命中判定流程（新 `detect_all_signals`）

```
输入 K 线（已含未收盘最后一根）
   │
   ▼
1. 摆动点（收盘价）→ 结构分类 → signal_type
   │
   ▼
2. 计算关键位列表（含区域上下沿）
   │
   ▼
3. 最新已收盘 K 线是否**放量突破**了某个关键位区域？
   │ 是 + 量能 ≥1.2×均量 + EMA 同向 → 输出 breakout 信号（不要求形态）
   │ 门控不过 → 落到触位路径
   ▼
4. 最新已收盘 K 线是否触及关键位区域（持住侧规则）？
   │ 否 → 返回空（未命中）
   │ 是 → 记录 position + 命中的关键位明细
   ▼
5. 该 K 线是否出现 12 金K？（方向须与关键位角色匹配）
   │ 否 → 返回空
   │ 是 → pattern + pattern_direction
   ▼
6. EMA 严格门控（仅 4 种趋势态 + 方向一致）
   │
   ▼
输出信号：{signal_type, position, pattern, pattern_direction,
          key_levels, signal_reason, strength, ...}
```

### 5.3 signal_reason 组装

格式统一为：`{位置中文}({关键位价格}) + {形态中文}`，例如：
- `支撑位(0.3528) + 锤形线`
- `压力位(0.3782) + 看跌吞没`
- `放量突破压力区域(0.3930)·1.6×均量`（breakout 信号）

### 5.4 方向铁律与放量突破（2026-09-12）

**方向铁律**：只在支撑位做多、只在压力位做空——
AI 入场价必须落在信号方向对应角色（多=support、空=resistance）的关键位区域内
（risk_guard 强校验，容差 ±0.25×ATR；违规直接打回）。
例外：`breakout`（放量突破顺势追，入场贴近现价）/ `manual_search`（用户手动指定）。

**放量突破信号（signal_type=breakout）**，三条同时满足才触发：
1. **收盘越过整个区域**：前收盘在位的另一侧（区分"突破"与"常态居位"——价格本来就高于支撑位不算突破），
   收盘价越过 zone_high（向上突破压力）/ zone_low（向下破位支撑）；
2. **量能**：最新已收盘 K 线成交量 ≥ 1.2× 近 20 根已收盘均量（`BREAKOUT_VOL_RATIO`，与 classify_volume 同口径）；
3. **EMA 同向**：EMA 形态为 4 种趋势态之一且偏向与突破方向一致（多突破需多头态，空突破需空头态）。

不要求 K 线形态（pattern=None）；信号强度 = 倍量 0.8 / 放量 0.7 + 触及≥2 次加 0.1 + EMA 同向加 0.1（封顶 1.0）。
突破后角色按价格侧翻转自洽：向上突破压力位后该位变支撑位（position=support），
向下突破支撑位后变压力位（position=resistance）。

## 6. 数据模型与接口变更

### 6.1 `scan_results` 表

| 字段 | 变更 | 说明 |
|------|------|------|
| signal_type | 取值变化 | 新值：uptrend / downtrend / trend_reversal / range_bound / unknown；历史行保留旧值（downtrend_breakout 等）不动 |
| position | 🆕 新增 VARCHAR(32) NULL | 12 金K 出现的位置（见 §5.1） |
| key_levels | 🆕 新增 JSON NULL | 命中的关键位明细（含全部邻近关键位、距离），供 AI 分析和前端展示 |
| breakout_pct | 含义调整 | 复用为"收盘价相对命中关键位中心的偏离百分比"（带符号），前端列名改为"距关键位" |

迁移方式：沿用 `database.py` 的幂等 ALTER TABLE（`ADD COLUMN IF NOT EXISTS`），无需数据回填。

### 6.2 配置项（system_config 新增）

| 配置 | 默认值 | 说明 |
|------|--------|------|
| key_level_tolerance | 0.005 | 关键位区域半宽（±0.5%） |
| level_merge_threshold | 0.005 | 支撑/压力聚类合并阈值 |
| fib_enabled | false | 斐波那契位开关（二期启用） |

### 6.3 前端变更

1. **信号类型列**：新增标签映射——上涨趋势(绿)/下跌趋势(红)/趋势反转(紫)/震荡区间(橙)/未分类(灰)；旧值（下跌突破等）保留映射以兼容历史记录。
2. **新增"位置"列**：显示 position 中文标签（支撑位/压力位/前高/前低/区间顶/区间底），与信号类型列同宽风格。
3. **突破幅度列** → 改名"距关键位"，展示新口径的偏离百分比。
4. **K线图**：AI 标注之外，增加关键位水平线绘制（支撑绿/压力红虚线 + 价格标签）——**可选**，工作量允许时做。
5. 搜索币种 AI 分析：自动继承新字段（后端统一输出，前端无需额外改动）。

### 6.4 对 AI 分析的影响

- `signal` 入参新增 `position`、`key_levels` 字段，AI 提示词中注明："请结合关键位位置与形态判断"；
- **关键位在分析时刻重算（2026-09-12）**：手动搜索分析与定时/重分析两条链路在调用 AI 前
  用最新 K 线重算关键位（`strategy.compute_signal_key_levels`，与 `_detect` 同源、
  含 ATR 自适应区域与时间加权），扫描落库的 `key_levels` 仅作信号指纹与回退；
- `signal_type` 新取值在提示词中给出中文对照；
- 其余流程（六问、策略提示词注入）不变。
