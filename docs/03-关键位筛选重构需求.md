# 03 - 关键位筛选重构需求

> **状态**：待确认（确认后开发）
>
> **一句话需求**：筛选逻辑不再以"是否突破"为核心条件，改为 **价格处于关键位 + 出现 12 金K 即命中**；信号类型按高低点结构分类（上涨/下跌/反转/震荡），新增"位置"字段记录 12 金K 出现的位置。

---

## 1. 背景与现状问题

### 1.1 当前逻辑（三个独立策略，任一命中即可）

| 策略 | 核心条件 | 问题 |
|------|---------|------|
| 下跌突破 downtrend_breakout | LH+LL 结构 + 收盘价**刚突破**下跌趋势线（前一根还没突破） | 条件苛刻：只捕捉"突破后第一根K线"，错过突破后回踩关键位的入场点 |
| 上涨回调 uptrend_pullback | HH+HL 结构 + 回调至趋势线/HL 附近 + 看涨形态 + **前面不能有连续阳线** | 只认上涨中的回调，且形态只看 4 种看涨形态 |
| 区间震荡 range_bound | 水平/收敛结构 + 区间上下沿 30% 区域 + 指定形态 | 只覆盖震荡场景 |

**共性问题**：
1. 三个策略各自为政，过滤条件互不兼容，逻辑分散在 3 个文件里；
2. 形态识别只有 6 种（且实际过滤只用其中 4-5 种看涨形态），远少于交易系统的 12 金K；
3. **没有"关键位"概念**——前高前低、支撑压力、斐波那契位都没有计算，与《03-交易系统.md》的关键位体系脱节；
4. 缺少统一的"市场结构"分类，无法直接回答"这个币现在是什么状态"。

### 1.2 新逻辑核心思想

```
旧：结构判定 → 突破/回调/区间条件 → 形态加分
新：结构分类（打标签）→ 计算关键位 → 价格在关键位？→ 出现12金K？→ 命中
```

**过滤条件只有两个**（与《03-交易系统.md》§6.1 一致）：
1. **位置**：最新已收盘 K 线触及某个关键位（区域）；
2. **形态**：该 K 线出现 12 金K 之一。

信号类型与位置不再作为"门槛"，而是作为**分类标签**输出，供排序、展示和 AI 分析使用。

## 2. 关键位模块（`key_levels.py`）

> **⚠️ 2026-09-14 线口径重构**：本节及 §2.1/§2.2 描述的「区域 + 权重」算法已被
> **§2.0.1 摆动点聚合线**取代（用户决策：彻底去掉区域概念，支撑/压力位为单价格线）。
> 旧文保留作决策记录，现状以 §2.0.1 为准。

### 2.0 统一口径（2026-09-14 回退定版：原 AI 分析口径，已被 §2.0.1 取代）

**全站唯一关键位函数 `compute_key_levels(klines, config)`**（`strategy/key_levels.py`）——
图表端点、信号检测、AI 事实包、风控锚定共用，图上看到的位即 AI 锚定的位。
算法即**原 AI 分析（数据层）逻辑**，内部完成 摆动点 → 结构分类 → 聚类 → 回归边界 → 区域合并：

1. **摆动点**：`find_swing_points(收盘价, order=swing_order)` + `merge_swings`，
   两侧各 order 根确认（防重绘；滞后为刻意保留）；
2. **最近摆动点**：最近高/低点各一档，天然最新、无聚类权重（touches=1）；
3. **历史聚类**：其余摆动点按价距 ≤ `level_merge_threshold` 聚类，簇权重 =
   Σ `2^(−bars_ago/60)`（半衰期 60 根）× 形态加成（触及点当根及后 2 根内出现方向匹配
   12 金K → ×1.5），**权重 ≥1.2 才保留**（≈近期 2 次触及）——久远孤点自然衰减淘汰；
   `touches`=簇内触及数、`pattern_hits`=簇内形态确认触及数；
4. **震荡回归边界**：结构分类为 RANGE_BOUND 时，取每侧最近 5 个摆动点线性回归出区间
   上下轨（上/下轨间距 ≥0.5% 才收），按角色归入压力/支撑位；
5. **区域半宽**（交易层口径，**不减半**）：`clamp(0.5×ATR(14)/价格, 0.5×tol, 2×tol)`，
   基准 `key_level_tolerance=0.003` → 实际 ±0.15%~±0.6%；
6. **同角色区域合并**：区域重叠或间隔 ≤ `level_merge_threshold` → 合并（zone 取并集、
   中心取并集中点、touches/weight/pattern_hits 累加）；
7. **两类化**：support / resistance，`kind` 按当前价动态推导，输出按价格升序。

**口径沿革（2026-09-14 一日内两变，最终回退）**：
- 初始：两套口径并存（数据层聚类 vs 图表 Pine 阶梯减半），三次理解偏差
  （SCRUSDT 止盈扎堆、FLOCKUSDT 锚位、TREEUSDT 粘合）后决定统一；
- 当日曾统一为 Pine 摆动点阶梯口径（quick(50,5)+full(50,25) 阶梯、触及池=quick 全集、
  无权重门控）；经权衡按用户决定**回退为原 AI 分析口径**（即本节所述）——统一的意义
  （图上即 AI 锚定）保留，算法回归数据层，图表端点改调统一入口；
- 回退的行为变化：档位回到「聚类 ≥2 次触及/形态确认」的更实口径（Pine 阶梯档位更多更碎）；
  RANGE_BOUND 回归边界回归 key_levels；图表区域宽度不变（同为交易层 clamp 口径）；
  指纹缓存部署后一轮全量 miss（指纹含最近关键位 price），当轮 AI 重新分析量瞬时抬升；
- 窗口残留差异：扫描快照 300 根 vs AI/图表 500 根（AI 分析时重算新鲜位，非缺陷）。

**历史回测记录（2026-09-12，12 币 × 1h × ~1000 根，事件 n≈8400，针对本聚类口径）**：
加权淘汰的旧位反应率 58.4% vs 保留位 65.8%（−7.4pp，p<0.001）；整体反应率 63.4%→64.9%。
该结论支持"久远旧位应衰减"——聚类的 ≥1.2 权重门控延续这一设计。

### 2.0.1 线口径重构（2026-09-14 下午定版：摆动点聚合线，现行）

用户决策：**彻底去掉区域概念**（zone_low/zone_high、weight、时间加权/门控全部删除），
支撑位/压力位为**单价格线**。完整方案见 `docs/08-关键位支撑压力线重构方案.md`。

**算法**（`compute_key_levels`，全站唯一入口，图上看到的线即 AI 锚定的线）：

1. **摆动点**：`find_swing_points(order=swing_order)` + `merge_swings`（不变）；
   摆动点（高/低点合并）全部参与聚合，**角色按现价位置划分**：现价上方=压力线、
   下方=支撑线（2026-09-14 修订：支撑跌破即变压力、压力突破即变支撑，不再由来源固定）；
2. **聚合（含最新点，2026-09-14 收敛）**：全部摆动点按**链式**价距 ≤
   `level_merge_threshold`(0.005) 合并成线（候选点与组内最后一点比价距，可多点链式合一）
   ——价格相近的线一律融合为一条，无"最新点单独成线"例外（取消后图上不再出现贴脸双线），
   线价 = 组内均值，`touches`=组内点数、`pattern_hits`=组内触及点当根及后 2 根内
   出现方向匹配 12 金K 的个数；
3. **每侧截断**：按摆动点时间新→旧保留前 `LEVELS_PER_SIDE=3` 条（无权重门控，全图 ≤6 条）；
4. **输出字段**：`{kind, role, price, touches, pattern_hits}`，`kind == role` 由现价位置定（上方=resistance、下方=support），
   全列表按 price 升序。**删除**：zone_low/zone_high、weight、RANGE_BOUND 回归边界、
   ATR 自适应半宽、`_merge_overlapping_levels`。

**判定口径**（`find_touching_level` / `find_broken_level`，容差 `key_level_tolerance`=±0.3%）：
- **触及** = 影线与 `[price×(1−tol), price×(1+tol)]` 相交 **且** 收盘在持住侧
  （按前收盘定侧，同分取距线价最近者）；
- **突破** = 收盘越过 `price×(1±tol)`，幅度（breakout_pct）从**线价**起算；
  破位距离最大者为主位置。翻侧自洽：收盘站上旧支撑线上方，按压力位语义判向上突破。

**风控适配**（risk_guard）：方向铁律带 = 线 ±0.3% ±0.25×ATR（`DEFAULT_TOL` 镜像，
不跟随 DB config）；止损/止盈锚定点 = **线价本身**（原 zone 近轨），止盈挂线外 0.2%、
止损锚线外 0.3% 缓冲，"两锚取更远者"、最近优先强制等机制不变。

**行为变化**：触位带从自适应 ±0.15%~0.6% 收敛为固定 ±0.3%；角色固定化后单边趋势市
贴现价可入场位变少（方向铁律打回增多）；SL/TP 锚内移 → 开仓量增大、RR<1.5 打回上升；
指纹含最近位 price，部署后一轮缓存全量 miss（AI 分析量一次性抬升）。
历史 scan_results 行带 zone/weight 字段：消费面一律只读 price（"price 恒存在"），
前端 K 线图对历史行不再画区域矩形（改为每位一条水平虚线）。

### 2.1 关键位的构成

> **2026-09-12 两类化**：关键位标签收敛为两类——**支撑位（support）/ 压力位（resistance）**，
> `kind` 由角色动态推导（位在当前价上方=压力位、下方=支撑位，`kind == role`）。
> 前高/前低/区间顶/区间底不再作为新值产生，历史数据保留兼容展示。

| 关键位 | 来源 | 类型 |
|--------|------|------|
| **支撑位** | 下方摆动低点（最近档 + 历史聚类档，权重 ≥1.2） | 支撑 |
| **压力位** | 上方摆动高点（同上）+ 震荡回归上轨 | 压力 |
| 震荡回归下轨 | RANGE_BOUND 结构每侧最近 5 点回归 | 支撑 |
| 斐波那契 50/61.8/80%（二期） | 最近一段趋势段回撤 | 支撑/压力 |

### 2.2 输出结构（示例）

```python
{
    "levels": [
        {"kind": "support",    "price": 76643.60, "zone_low": 76464.73, "zone_high": 76822.47,
         "touches": 6, "role": "support", "pattern_hits": 3, "weight": 1.61},
        {"kind": "resistance", "price": 77936.50, "zone_low": 77754.61, "zone_high": 78118.39,
         "touches": 4, "role": "resistance", "pattern_hits": 1, "weight": 0.69},
    ]
}
```

> `kind == role`；同角色多位按价格区分，距现价最近的一档是主参考。
> `weight` 为时间加权触及强度（含形态加成）；聚类档受 ≥1.2 权重门控（不达标不产出），
> 最近摆动点档无 `weight` 字段（天然保留，不参与门控）。
> 斐波那契位本期不做（见待确认问题 2）。

## 4. 信号类型：按高低点结构分类（新增 `structure.py`）

### 4.1 分类规则（基于摆动点序列，收盘价计算）

对最近 2~3 个摆动高点和低点：

| 信号类型 | 代码标识 | 判定规则 |
|---------|---------|---------|
| **上涨趋势** | uptrend | 高点递增（HH）**或**低点递增（HL），且未触发反转条件 |
| **下跌趋势** | downtrend | 高点递减（LH）**或**低点递减（LL），且未触发反转条件 |
| **趋势反转** | trend_reversal | 下跌结构（LH+LL）中**收盘价突破最近前高**；或上涨结构（HH+HL）中**收盘价跌破最近前低**（即 123 法则第②步信号） |
| **震荡区间** | range_bound | 高点水平/收敛 + 低点水平/收敛（复用现有斜率判定）；或高低点方向冲突（如 LH+HL） |
| **未分类** | unknown | 摆动点不足或结构无法识别（是否允许命中见待确认问题 3） |

**分类优先级**：趋势反转 > 趋势 > 震荡 > unknown。
**说明**：分类只做"打标签"，不构成过滤门槛（与旧逻辑的本质区别）。

## 5. 位置字段（新增 `position`）

### 5.1 取值定义

> **2026-09-12 两类化**：`position` 收敛为 `support / resistance` 两个新值；
> 历史行的 `prev_high / prev_low / range_top / range_bottom` 保留兼容展示。

12 金K 所在 K 线（最新已收盘 K 线）**触及的关键位**，取距现价最近（收盘价距中心最近）的一档：

| 位置 | 代码标识 | 触发条件 |
|------|---------|---------|
| 支撑位 | support | 最新已收盘 K 线影线触及支撑线 ±容差带，且收盘在持住侧 |
| 压力位 | resistance | 最新已收盘 K 线影线触及压力线 ±容差带，且收盘在持住侧 |
| 放量突破 | breakout（signal_type） | 收盘越过关键位线 ±容差带 + 量能 ≥1.2×均量 + EMA 同向（见 §5.4） |

**判定口径（2026-09-14 线口径）**：触及 = 影线与 `[price×(1±tol)]` 相交且收盘在持住侧
（support-like 位要求收盘 ≥ 带下沿，resistance-like 位要求收盘 ≤ 带上沿）——收盘越过
远侧的破位方向不属于触及，归放量突破分支管。同分取距线价最近者作主位置。
容差 `key_level_tolerance` = ±0.3%。

### 5.2 命中判定流程（新 `detect_all_signals`）

```
输入 K 线（已含未收盘最后一根）
   │
   ▼
1. 摆动点（收盘价）→ 结构分类 → signal_type
   │
   ▼
2. 计算关键位列表（支撑/压力价格线）
   │
   ▼
3. 最新已收盘 K 线是否**放量突破**了某条关键位线（±容差带）？
   │ 是 + 量能 ≥1.2×均量 + EMA 同向 → 输出 breakout 信号（不要求形态）
   │ 门控不过 → 落到触位路径
   ▼
4. 最新已收盘 K 线是否触及关键位线 ±容差带（持住侧规则）？
   │ 否 → 返回空（未命中）
   │ 是 → 记录 position + 命中的关键位明细
   ▼
5. 该 K 线是否出现 12 金K？（方向须与关键位角色匹配）
   │ 否 → 返回空
   │ 是 → pattern + pattern_direction
   ▼
6. EMA 严格门控（仅 4 种趋势态 + 方向一致）
   │
   ▼
输出信号：{signal_type, position, pattern, pattern_direction,
          key_levels, signal_reason, strength, ...}
```

### 5.3 signal_reason 组装

格式统一为：`{位置中文}({关键位价格}) + {形态中文}`，例如：
- `支撑位(0.3528) + 锤形线`
- `压力位(0.3782) + 看跌吞没`
- `放量突破压力位(0.3930)·1.6×均量`（breakout 信号）

### 5.4 方向铁律与放量突破（2026-09-12）

**方向铁律**：只在支撑位做多、只在压力位做空——
AI 入场价必须落在信号方向对应角色（多=support、空=resistance）的关键位价格线 ±0.3% 容差带
（risk_guard 强校验，再 ±0.25×ATR 容差；违规直接打回）。
例外：`breakout`（放量突破顺势追，入场贴近现价）/ `manual_search`（用户手动指定）。

**放量突破信号（signal_type=breakout）**，三条同时满足才触发：
1. **收盘越过线 ±容差带**：前收盘在位的另一侧（区分"突破"与"常态居位"——价格本来就高于支撑位不算突破），
   收盘价越过 price×(1+tol)（向上突破压力）/ price×(1−tol)（向下破位支撑），
   突破幅度从线价起算；
2. **量能**：最新已收盘 K 线成交量 ≥ 1.2× 近 20 根已收盘均量（`BREAKOUT_VOL_RATIO`，与 classify_volume 同口径）；
3. **EMA 同向**：EMA 形态为 4 种趋势态之一且偏向与突破方向一致（多突破需多头态，空突破需空头态）。

不要求 K 线形态（pattern=None）；信号强度 = 倍量 0.8 / 放量 0.7 + 触及≥2 次加 0.1 + EMA 同向加 0.1（封顶 1.0）。
突破后角色按价格侧翻转自洽：向上突破压力位后该位变支撑位（position=support），
向下突破支撑位后变压力位（position=resistance）。

## 6. 数据模型与接口变更

### 6.1 `scan_results` 表

| 字段 | 变更 | 说明 |
|------|------|------|
| signal_type | 取值变化 | 新值：uptrend / downtrend / trend_reversal / range_bound / unknown；历史行保留旧值（downtrend_breakout 等）不动 |
| position | 🆕 新增 VARCHAR(32) NULL | 12 金K 出现的位置（见 §5.1） |
| key_levels | 🆕 新增 JSON NULL | 命中的关键位明细（含全部邻近关键位、距离），供 AI 分析和前端展示 |
| breakout_pct | 含义调整 | 复用为"收盘价相对命中关键位中心的偏离百分比"（带符号），前端列名改为"距关键位" |

迁移方式：沿用 `database.py` 的幂等 ALTER TABLE（`ADD COLUMN IF NOT EXISTS`），无需数据回填。

### 6.2 配置项（system_config 新增）

| 配置 | 默认值 | 说明 |
|------|--------|------|
| key_level_tolerance | 0.003 | 关键位触及/突破容差带 ±0.3%（线口径，影线入带=触及、收盘越带=突破） |
| level_merge_threshold | 0.005 | 摆动点聚合为一条线的价距阈值（链式合并，线价取均值） |
| fib_enabled | false | 斐波那契位开关（二期启用） |

### 6.3 前端变更

1. **信号类型列**：新增标签映射——上涨趋势(绿)/下跌趋势(红)/趋势反转(紫)/震荡区间(橙)/未分类(灰)；旧值（下跌突破等）保留映射以兼容历史记录。
2. **新增"位置"列**：显示 position 中文标签（支撑位/压力位/前高/前低/区间顶/区间底），与信号类型列同宽风格。
3. **突破幅度列** → 改名"距关键位"，展示新口径的偏离百分比。
4. **K线图**：AI 标注之外，增加关键位水平线绘制（支撑绿/压力红虚线 + 价格标签）——**可选**，工作量允许时做。
5. 搜索币种 AI 分析：自动继承新字段（后端统一输出，前端无需额外改动）。

### 6.4 对 AI 分析的影响

- `signal` 入参新增 `position`、`key_levels` 字段，AI 提示词中注明："请结合关键位位置与形态判断"；
- **关键位在分析时刻重算（2026-09-12）**：手动搜索分析与定时/重分析两条链路在调用 AI 前
  用最新 K 线重算关键位（`strategy.compute_signal_key_levels`，与 `_detect` 同源、
  含 ATR 自适应区域与时间加权），扫描落库的 `key_levels` 仅作信号指纹与回退；
- `signal_type` 新取值在提示词中给出中文对照；
- 其余流程（六问、策略提示词注入）不变。
