# 15. 系统性风险防护：普跌行情预案

> 2026-09-20 | 状态：设计已确认，待实现 | 前置文档：06（自动交易）、11（现行规则总览）
> 决策拍板：L3 分级收紧+深亏（>0.5R）提前离场 / L2·L3 暂停全部新开仓（空单不豁免）/ 全自动逐级恢复 / **5 分钟快检分频（升级）**

## 1. 背景与问题

- 现有防线全部是**单笔维度**：止损宽度闸门、余额风控、逐仓+止损。普跌行情下多单集中触发止损，高杠杆（默认 20×）下还存在插针强平风险，组合层面无任何防御
- 普跌特征：BTC 领跌 + 全市场广度下跌 + 波动放大。此时顺势策略的多头信号大概率是「接刀」，继续开仓 = 放大亏损
- 目标：增加**市场/组合维度**的系统性风险闸门（Market Guard），普跌时少开仓、管好存量仓位，企稳后自动恢复

**明确不在本期范围**：自动对冲（同时开空锁仓）、分钟级监控、跨市场信号（美股/资金费率）、空投类山寨独立阈值。

## 2. 决策记录

| 决策点 | 结论 | 理由 |
|---|---|---|
| L3 仓位处置 | 分级收紧止损 + 浮亏 >0.5R 的多单提前离场 | 只收紧止损在雪崩行情会逐笔吃满止损；全平则 V 型反弹没有仓位 |
| 空单豁免 | 不豁免，L2/L3 暂停**全部**新开仓 | 普跌时波动剧烈，空单同样面临插针反弹止损；保守优先 |
| 恢复方式 | 全自动逐级恢复（信号消失连续 2 轮确认降一级） | 免人工盯盘；逐级 + 双重确认防 V 型震荡反复切换 |

## 3. 市场风险检测（5 分钟快检，与结算分频）

**检测与结算分频（2026-09-20 补）**：每小时一次来不及——最坏延迟 ~65 分钟（:15 开新单、:20 开始崩、下轮巡检 :10 才发现），20× 杠杆下 4.5% 即强平。因此新增独立的 `market-risk-check` 任务**每 5 分钟**跑一次（beat `crontab(minute='*/5')`）：

- **成本极低**：只调币安公开行情（24hr ticker + BTC 1h/15m K线，共 3 个请求，权重 ~44），无 LLM、无重 DB 操作
- **升级即时**：快检测到等级上升 → 立即生效并立即执行仓位动作（抢 Redis 巡检锁；锁被占用则跳过本轮，5 分钟后重试，单笔即时保护始终由交易所侧止损单承担）
- **结算复用**：每小时 :10 结算巡检不再计算等级，只读当前等级执行常规结算；开仓闸门在开仓瞬间读实时等级

信号（快检任务计算，零新增外部依赖）：

| # | 信号 | 判定 | 默认阈值 |
|---|---|---|---|
| S1 | BTC 领跌 | BTC 24h 跌幅（24 根 1h 收盘 vs 现价） | ≤ −5% |
| S2 | 市场广度 | Top20 成交额币种中 24h 跌幅 ≤ −3% 的占比 | ≥ 70% |
| S3 | 波动放大 | BTC 1h ATR(14) 现值 / 24h 前均值 | ≥ 1.8× |
| S4 | 急跌（抓尖刺） | BTC 最近 3×15m 累计跌幅 | ≤ −3.5% 直达 L2；≤ −6% 直达 L3 |

## 4. 风险等级与动作矩阵

| 等级 | 触发条件 | 新开仓 | 在跑仓位 |
|---|---|---|---|
| **L0 正常** | 0 项命中且无 S4 直达 | 正常（原有闸门） | 正常跟踪止损 |
| **L1 警戒** | 1 项命中（S4 不参与计数） | recommendation 阈值 +10；单笔风险额减半 | 正常（仅提醒） |
| **L2 限制** | 2 项命中，或 S4 ≤ −3.5% 直达 | **暂停全部新开仓** | 多单止损收紧至 max(成本价, 最近摆动点)（SL_MOVE 通道） |
| **L3 防御** | 3 项命中，BTC 24h ≤ −8% 直达，或 S4 ≤ −6% 直达 | 暂停全部新开仓 | 多单：浮亏 >0.5R 市价离场（exit_reason=`market_guard`）；其余收紧止损。空单：只收紧止损（反弹止损保护利润），不动盈利空单 |

- 0.5R = 浮亏绝对值 > 0.5 × risk_amount（与盈亏比口径同源）
- L3 的空单处理：跟踪止损再收紧一档锁定利润，不主动平盈利空单（让利润奔跑）

## 5. 防抖与恢复

- **升级即时**：快检（5 分钟级）命中更高等级，立即生效并立即执行仓位动作（宁可保守）
- **降级防抖**：信号消失需**连续 24 轮快检**（约 2 小时）才降一级，L3→L2→L1→L0 逐级（轮数可配 `MARKET_GUARD_DOWNGRADE_ROUNDS`）
- **S4 单条衰减**：S4 是尖刺信号，价格回到 3×15m 跌幅 < −1.5% 即视为消失（不适用 24 轮防抖）；由 S4 直达的等级回落按命中项数重新计算
- **数据失败保守**：行情获取失败时，等级**维持原值**不升不降（避免数据故障误杀）
- 等级与最近信号快照存 `market_risk_state`（新表，一行最新状态 + 历史迁移记录）

## 6. 触达与展示

- **飞书通知**（复用 `notify.py`）：等级**升级**即时推送卡片（等级、命中信号、涉及仓位数）；降级不推（免打扰）
- **前端横幅**：扫描页/交易记录页顶部显示当前等级条（L1 黄 / L2 橙 / L3 红），悬停看命中信号明细；`GET /api/trades/market-risk`
- **交易记录标注**：`market_guard` 出场的单子在出场原因列显示「防护平仓」，操作历史记录触发时的市场快照（BTC 跌幅/广度/ATR 倍数）

## 8. 边界与空态

- `MARKET_GUARD_ENABLED=false` 时全链路跳过（AI 实验功能同款开关惯例）
- 扫描池币种不足 10 个时 S2 按「数据不足」处理，不计入命中数
- L3 提前离场与结算巡检互斥锁复用（Redis 开仓锁同款机制），快检任务抢不到锁则跳过本轮动作，下轮重试
- 快检任务的仓位动作只做两类：收紧止损（改单）、L3 深亏市价离场；不做部分平仓等复杂操作（控制与交易所交互面）
- 等级由快检任务独占更新；结算巡检/开仓闸门只读，避免双写竞态
