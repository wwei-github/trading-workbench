# 17 正式网多账号支持设计

> 2026-09-23 立项。目标：正式网支持多个独立主账号**同信号跟单**——一次 AI 分析产出信号，每个启用账号独立计算仓位并开单。
> 已拍板：① 账号形态 = 多个独立主账号 ② 交易关系 = 同信号多账号跟单（扇出）③ 节奏 = P0（账号注册表，行为不变）→ P1（并行扇出）分步交付。
> 2026-09-23 修订：**账号配置全走 .env（纯配置驱动，无新表、无密钥落库）**——弃用原 trading_account 表方案。

## 1. 现状与差距

当前「账号」概念 = `testnet` 布尔值 + .env 固定两组 key：

| 维度 | 现状 | 多账号需求 |
|---|---|---|
| 账号标识 | `testnet: bool`（记录级 + system_config 运行时级） | 稳定账号 key（`live-1` / `live-2` / `testnet-1`） |
| API key | .env 两组：`BINANCE_API_KEY/SECRET`（live）、`BINANCE_TESTNET_API_KEY/SECRET` | .env 按编号扩展 N 组 live key，**改配置不改代码** |
| 钱包/风险基数 | 按环境取钱包 → 首位数取整（100~5000）→ 1R = 基数 × 3% | **按账号取钱包**，各自算风险基数 |
| 在跑上限 | 全局 `max_open_trades` | 每账号限额 + 全局总闸 |
| 划转/资金分析/交易记录 | `scope=live/testnet` Segmented | 账号维度筛选 + 全部账号聚合视图 |
| 扫描+AI | 一次扫描 → 当前环境开单 | **信号层共享一次分析，执行层按账号扇出** |

关键事实：`BinanceTrader` 无状态，全项目 11 处 `BinanceTrader(testnet_bool)` 实例化（trade_tasks ×2、trade_engine ×3、scanner、review_tasks、feishu_bot、api/trades、api/scan ×2）。把构造参数换成账号 key，业务代码近乎不动。

## 2. 账号配置：.env 注册表（无新表）

### 2.1 环境变量格式

```bash
# ── 测试网（单账号，沿用现有变量名，零改动）──
BINANCE_TESTNET_API_KEY=xxx
BINANCE_TESTNET_SECRET_KEY=xxx

# ── 正式网 1 号账号（沿用现有变量名，完全向后兼容）──
BINANCE_API_KEY=xxx
BINANCE_SECRET_KEY=xxx

# ── 正式网附加账号：编号递增，数量不限 ──
BINANCE_LIVE_2_API_KEY=xxx
BINANCE_LIVE_2_SECRET_KEY=xxx
BINANCE_LIVE_2_NAME=仓位B          # 可选显示名，缺省「正式网-2」，纯展示不参与逻辑

BINANCE_LIVE_3_API_KEY=xxx
BINANCE_LIVE_3_SECRET_KEY=xxx
# BINANCE_LIVE_3_NAME 不配 → 默认「正式网-3」
```

### 2.2 注册表构建（`account_registry`）

| 规则 | 说明 |
|---|---|
| 稳定账号 key | `testnet-1` / `live-1` / `live-2`…；`trade_records` 加 `account_key` 列记录归属 |
| 动态发现 | 启动时（`init_db` 后 + celery worker 启动钩子）扫环境变量正则 `BINANCE_LIVE_(\d+)_API_KEY` 收集，内存注册表，不改代码 |
| 启动校验 | 配了 `_API_KEY` 缺 `_SECRET_KEY` → 启动报错并明确提示变量名；NAME 缺省用「正式网-N」 |
| 兼容性 | 只配 `BINANCE_API_KEY/SECRET` 一组时，行为与现状完全一致 |
| 密钥安全 | key/secret 始终只在服务器 .env，不落库、页面不回显（key 状态徽标沿用现有 binance_key_live 判定） |

### 2.3 system_config 演进

- `trading_testnet` 保留（选中测试网 = true，语义不变）
- 新增 `current_account_key`（String nullable）：**正式网模式下**记录当前用的 live 账号（`live-1`/`live-2`…）；NULL 或 testnet 模式回落 `live-1`
- 兼容：`current_account_key` 未配置时全按 `trading_testnet` 走，行为不变

### 2.4 存量表回填（幂等迁移，`_run_migrations`）

- `trade_records` / `transfers` 加 `account_key VARCHAR(20) NULL`
- 回填规则：`testnet=true → 'testnet-1'`，`false → 'live-1'`（存量只有这两个来源）
- 读路径回落：`account_key` 为 NULL 的行按 `testnet` 布尔映射（双保险）

## 3. 信号共享 + 扇出执行（P1 核心）

```
定时扫描（:02）
  → 指标筛选触发币种（信号层，一次）
  → 重复命中抑制 / 黑名单判定（信号层，一次）
  → AI 分析（一次，产出建议）
  → 开单扇出 for account in registry.live_accounts():
      ├─ trader = BinanceTrader(account.key)
      ├─ wallet = trader.wallet_balance()          # 各账号各自取
      ├─ 风险基数 = 首位数取整(wallet)              # 每账号独立，上限 5000 不变
      ├─ 闸门：余额风控 min_free_pct / 账号在跑上限 / 全局总闸 / 滑点实测
      └─ 开单 → trade_records(account_key=…)
  → 单账号失败不影响其他账号；结果汇总进扫描记录
```

- 结算巡检（:00）/ 复盘 / 日报：按 `rec.account_key` 分组遍历，各账号用各自 key 结算
- 飞书平仓回调（feishu_bot）：`BinanceTrader(bool(rec.testnet))` → `BinanceTrader(rec.account_key)`，NULL 回落 testnet 布尔
- 限频：币安权重按 IP 计，多账号共享 IP → 扇出**串行下单**（K 线缓存共享，AI 分析只一次，压力点仅在开单 REST，串行足够）

## 4. UI 改动

| 页面 | 改动 |
|---|---|
| 系统配置 | 「交易环境」互斥双开关演进：**测试网**一个开关（不变）；**正式网**侧 N 个开关（每个 live 账号一个，显示 NAME），仍是互斥单选。只配一组 live key 时与现有双开关完全一致 |
| 交易记录 / 资金分析 / 划转 | live/testnet Segmented → **账号下拉**（含「全部账号」聚合）；单账号时退化原样式 |
| 顶部状态栏 | 当前账号名（EnvironmentTag 文案扩展） |
| 概览指标 | 聚合视图：余额类求和；胜率/盈亏比按全量已闭单重算；「在跑单子」跨账号合计 |

页面**不提供**账号增删（.env 是唯一配置源），系统配置里只展示账号清单 + key 配置状态 + 当前账号选择。

## 5. 分阶段交付

### P0 账号注册表（行为与现在完全一致）
1. `account_registry` 模块：env 解析 + 启动校验 + 账号枚举 API
2. `BinanceTrader` 改造：构造参数 `(account_key: str | None)`（None=按 system_config 解析当前账号，兼容全部既有调用点）；11 处调用点语义不变
3. 存量 `trade_records`/`transfers` 回填 account_key
4. 系统配置 UI：正式网账号开关组 + 当前账号选择；环境徽标显示账号名
5. 交易记录/划转/资金分析筛选器改为账号下拉（此阶段通常 1 testnet + 1~N live）
6. 验收：全部现有流程（扫描→开单→巡检→复盘→日报→飞书卡片）行为不变

### P1 并行扇出
1. 扫描任务扇出：信号层共享，按账号独立风控+开单
2. 每账号限额 + 全局总闸双生效
3. 结算/复盘/日报按账号分组
4. 聚合视图指标口径
5. 验收：≥2 账号同时跟单，余额不同仓位不同，单账号异常隔离

### P2（可选，暂不排期）
- 账号↔策略/黑名单绑定（每账号跑不同币池）
- 账号级日报/飞书推送分流

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 密钥泄露 | key/secret 只在服务器 .env（现状不变，不新增落库面）；DB 备份天然无密钥 |
| 总敞口放大 | 全局 `max_open_trades` 总闸 + 每账号上限（P1）；风险基数上限 5000/账号不变 |
| 限频（共享 IP） | 扇出串行开单；K 线/行情缓存共享 |
| 迁移破坏存量结算 | account_key 回填幂等 + 读路径按 testnet 布尔回落；巡检按回落链兜底 |
| 配错 key | 启动校验缺 SECRET 报错；账号↔key 映射只依赖变量名编号，重启即生效 |

## 7. 明确不做

- 不做币安主子账号体系（已拍板独立主账号）
- 不做页面账号管理（.env 唯一配置源，页面只读展示）
- 不做单信号按账号差异化杠杆/参数（同信号同参数，仅仓位随余额自然不同；差异化留 P2）
- 不做账号间资金调拨（划转仍只在单账号内记录）
