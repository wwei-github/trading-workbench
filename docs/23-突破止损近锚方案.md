# 突破止损近锚方案：RR 不达标时的宽锚降级 + 现有移动止损接管

> 2026-09-29 设计提案（v2，按评审意见收窄触发条件；v3 前提收窄为"唯一 skip 原因
> 是 RR 不达标"；v4 近锚定稿为突破K线极值口径）。状态：**已实施（2026-09-29）**。
> 动机：趋势突破/结构突破信号的止损锚（摆动前低/轨价下方）在波动大的币上离入场常 4-6%，
> 或导致 RR 铁律无法达标（AI 被迫 skip），或触发开仓宽度闸门弃单——突破类信号"看得见吃不到"。
> **前提：仅针对突破单；仅当 AI 的 skip 唯一原因是结构锚下盈亏比不达标、
> 其余全部开单条件均已满足时，才允许降级近锚。任何其他条件不满足 → 照常 skip。**

## 1. 背景与问题

### 1.1 突破单止损锚现状

AI 分析（P0/Agent 两管线）按提示词方法论锚定止损：

- 结构锚 vs 影线极值**取更远者** + 0.3% 缓冲（docs/09 锚定设计，2026-09-15 起降级为提示词纪律，程序不打回）
- 止损宽度不设固定百分比上限，RR 铁律 ≥1.5 由 AI 自行满足

对突破类信号（`trigger_breakout` / `trigger_trend_breakout`），"取更远者"意味着：

- 结构突破：锚在**摆动前低/前低**下方——距离入场常 3-6%
- 趋势突破：锚在**Donchian 轨价**下方——强趋势连续新高时轨价离现价更远

### 1.2 开仓闸门拦截点（trade_engine.\_attempt_open）

| 闸门                | 位置                     | 行为                                                                                     |
| ------------------- | ------------------------ | ---------------------------------------------------------------------------------------- |
| `max_stop_pct` 补丁 | trade_engine.py L247-262 | 止损距离 ≥ 补丁上限 → 弃单（NULL=默认不限制）                                            |
| 动态杠杆下限        | trade_engine.py L263-299 | 止损过宽 → `_adaptive_leverage` 反推安全杠杆，低于 `min_adapt_leverage`（默认 3×）→ 弃单 |

典型案例（代码注释在案）：BATUSDT 止损 6.4% 被强平 → 20× 下加闸门。止损 5%+ 的突破单在
3× 下限闸门下**必然弃单**——固定亏损法无解，但这恰恰把"趋势最顺的一批信号"全部挡在门外。

### 1.3 现有移动止损基建（方案第二半零开发）

`_trailing_stop`（trade_engine.py L704-727）：**最近 3 根已收盘K线最低（多）/最高（空），
只收紧不放松**；TP2_HIT 状态额外以 TP1 夹紧保本。配套 `_replace_sl` 撤旧挂新
（-4130 残留 closePosition 兜底）、"新 SL 会立即触发则跳过本轮"防抖（-2021 拒单保护）。

**启用时机：仅 TP1 成交后**（TP2_HIT / TP1_HIT-without-TP2）。TP1 前止损固定。

## 2. 方案

### 2.1 核心思路

突破入场的失效条件是"跌回突破结构"——**突破K线（信号K线）最低价（多）失守即突破K
全损、失败突破的经典定义**。近锚的定位是"万事俱备、只差 RR"的拯救档：AI 决策链上
RR 有两个可调自由度（入场价、止损锚），现行提示词只允许调入场价，调不动就 skip。
本方案在两者之间插入第三档，且**适用前提是除 RR 外其余开单条件全部满足**（信号方向、
4h 背景、趋势状态、量能特征、质量分门槛等）——skip 原因若含任何其他条件不满足，
禁止使用近锚：

```
① 结构锚 + 优先调整入场价（现行规则，不变）
② 其余条件全部达标、仅 RR 不达标 → 降级近锚（突破K最低价下方 0.3% 缓冲）复算 RR
③ 近锚仍不达标，或存在任何其他条件不满足 → skip（铁律不放松）
```

近锚选突破K极值而非"最近 N 根"的理由：语义最纯粹（N 无依据）、AI 事实包现成无歧义、
且突破K从盘整区上沿起爆其低点通常高于前 2 根盘整K低点 → 止损更窄、RR 更好、
更多单可开。近锚达标后，开仓后既有链路自然接管：TP1 成交 → 止损移保本 →
3 根极值 trailing（只收紧不放松，切换不会把止损移远，衔接无损）。

### 2.2 提示词方案（推荐，程序不硬覆盖）

**改动点：`ai_analyzer.py` 门槛块 + `ai_agent.py` 提示词锚点**，仅对突破类 signal_type 生效：

```
- 止损锚（突破类专用）：结构锚（前低/轨价下方 +0.3% 缓冲）优先；按结构锚
  复算盈亏比 <1.5 且调整入场价仍无法达标（本应 skip）时，才降级近锚——
  突破K线（本信号K线）最低价（做多）下方 0.3% 缓冲（做空=最高价上方），
  TP 与盈亏比按新锚复算；近锚达标才可 suggest，并在输出 stop_anchor
  字段标注 "near"（结构锚达标时输出 "structure"）；近锚仍不达标 → skip
- 近锚适用前提（硬约束）：仅当 skip 的唯一原因是盈亏比不达标——信号方向、
  4h 背景、趋势状态、量能特征、质量分等其余开单条件必须全部满足；
  任何其他条件不满足时禁止使用近锚，照常 skip
- 近锚资格附加线：量比 <1 的缩量突破单无近锚资格（缩量假突破 + 止损贴脸
  是最危险组合）；近锚后盈亏比 >4 时重新评估或 skip（止损过近说明失效位
  无意义，插针一扫就死）；近锚止损宽度仍受方法论区间下限 0.3×ATR 约束
```

设计取舍：

- **降级条件与 RR 铁律直接挂钩**（而非固定距离线）：结构锚下 RR 本来就达标的
  突破单一律不动——结构锚是更高质量的失效定义，没有理由换
- **近锚只救"万事俱备、只差 RR 的单"**：其余条件任一不满足 → 无近锚资格，
  与"优先调整入场价"衔接成三档降级链（§2.1）
- **近锚不得架空 RR 铁律**：RR 按止损计算，锚放宽后 RR 几乎总能凑出——若不加
  附加线，AI 有系统性动机"宣称其余条件满足"走近锚出单（胡乱开单主通道）。
  量比 ≥1 资格线 + RR≤4 上限 + 0.3×ATR 最小宽度把近锚窗口压到真正的
  "结构合理窄止损"场景
- **近锚仍受 RR 铁律与全部既有闸门约束**，不是无条件放宽
- **stop_anchor 字段随 AI 输出落 `ai_snapshot` → `trade_records`**，复盘可按
  锚类型精确分组对比（§5 验证口径依赖此字段）
- 程序侧仅**一处**小改动：risk_guard 对 `stop_anchor=near` 的标注一致性硬校验
  （止损必须贴近突破K线极值 ±0.5% 容差，否则视作滥用打回 skip）；
  其余开单闸门（动态杠杆、强平、风险预算）零改动

### 2.3 近锚单风险折价 ×0.7（评审补充，2026-09-29 已实施）

近锚单在开仓引擎侧风险预算 ×`NEAR_ANCHOR_RISK_FACTOR`（默认 0.7，可配）：

- **依据**：① 止损窄使名义仓位放大（止损 1% vs 4% → 名义 4 倍），手续费/滑点磨损
  绝对额相应放大（30 USDT 预算例：4.5 vs 1.1 USDT）；② 被扫率是同一枚硬币的
  另一面（止损贴脸既提高 RR 也降低胜率），净效应未知——未知胜率策略的敞口折价
- **明确边界**：折价不改变 EV/R 符号（磨损占比 0.15%/止损距离与预算无关），
  只把试错成本从 30 USDT/笔降到 21 USDT/笔；复盘胜率验证后（如实测 ≥40%）
  可把系数调回 1.0 放开
- **口径自洽**：`risk_amount` 随 qty 同步变小，复盘 R 倍数统计不受污染；
  仅 AI 显式声明 near（risk_guard 已硬校验止损贴突破K极值）时生效

### 2.4 明确不做的事

| 事项                                | 理由                                                                        |
| ----------------------------------- | --------------------------------------------------------------------------- |
| trade_engine 按信号类型强制覆盖止损 | 剥夺 AI 结构判断；AI 的 TP/RR 按原锚计算，程序改锚后建议与仓位口径不一致    |
| TP1 前提前启用 trailing             | 开仓即跟 3 根极值移损，横盘期被贴脸扫掉，变相零容错；近锚本身已窄，无需再跟 |
| 回踩金K确认类同步放宽               | 触碰位下方锚本来就近（通常 <1.5%），无宽锚问题，不扩大改动面                |
| 近锚后再叠加更紧的初始跟踪          | 同"TP1 前启用 trailing"，双窄叠加胜率崩塌                                   |

### 2.4 参数与范围

| 参数         | 取值                                                                  | 说明                                                             |
| ------------ | --------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 适用信号     | `trigger_breakout`、`trigger_trend_breakout`                          | 仅突破类；白名单内其他类型不注入该指令                           |

## 3. 风险与对策

| 风险                                 | 评估                                                                                                                              | 对策                                                                                                                                                                |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 假突破一扫就死（近锚被插针扫掉）     | 突破K口径较"近N根"更窄 → 被扫率更高，是**已知代价**：RR 自动放大（同 TP 下 1.5 → 3+），单笔风险金额固定，期望值正负只能靠数据裁决 | 复盘分组按 stop_anchor 直接对比 structure/near 两批单的胜率与 EV（trade_reviews + 实盘归因），2-3 周样本后再定去留                                                  |
| 止损被扫后重复开单磨损               | 突破信号未消失时可能反复进场                                                                                                      | `REPEAT_WINDOW_HOURS=3` 去重 + 连续止损黑名单冷却（现有机制兜底），不动                                                                                             |
| AI 滥用近锚（结构锚达标也走近锚）    | 降级仅允许发生在 RR 铁律失败场景，但 AI 可能有动机在灰色地带偏近锚（止损窄 → 名义仓位大）                                         | 输出 `stop_anchor` 必填标注（structure/near）；复盘归因按锚类型分组，structure 占比异常即收紧措辞；程序侧硬校验（near 标注时止损必须贴近突破K极值 ±容差）           |
| **AI"宣称其余条件满足"绕过近锚前提** | 近锚前提是提示词纪律，无程序硬校验；量比/背景/质量分全凭 AI 自报，RR 又因近锚几乎总能凑出 → 胡乱开单主通道                        | ① 量比 <1 无近锚资格（写进指令）；② RR>4 强制重估；③ 0.3×ATR 最小宽度；④ stop_anchor=near 硬校验（止损必须贴近突破K极值 ±容差，否则程序打回）；⑤ structure 占比监控 |
| **政策叠加：突破链路三连放宽**       | 触点全开 + 放量改加分 + 近锚，同一链路连续放宽，叠加产量效应无单一环节评估                                                        | 上线后 2 周冻结突破类其他放宽改动，先积累分组数据（§5）再决定后续                                                                                                   |
| 近锚 + 高杠杆放大插针爆仓            | 固定亏损法 qty 随止损变窄放大，但强平距离同步变远                                                                                 | 强平闸门与动态杠杆逻辑不变，天然自洽                                                                                                                                |

## 4. 实施清单（已按此落地，2026-09-29）

实施时的一处优化：`stop_anchor` **不加 trade_records 新列**——随 `_ai_snapshot`
JSON 快照透传（与 trade_type 同款仓库惯例），复盘归因从 `trade_records.ai_snapshot.stop_anchor`
取；仅 `ai_analyses` 加一列（SQLite `ADD COLUMN IF NOT EXISTS` 迁移）。

1. `ai_analyzer.py`：`render_signal_gate_block` 突破两类公共段追加降级链指令
   （降级链 + 前提硬约束 + 附加线）；SYSTEM_PROMPT 字段区加 stop_anchor 定义
2. `ai_agent.py`：LEVEL_REFS 加 `signal_low`/`signal_high`（突破K极值锚，
   `_resolve_price` 解析 klines[-2]）；AGENT_SYSTEM 加 `{near_stop_rule}` 槽位
   （仅突破类注入）；**stop_anchor 由程序从 stop_ref 推导**（signal_low/signal_high
   → near，比 AI 自报更难滥用）；submit_decision schema 描述同步
3. `risk_guard.py`：TradeDecision 加 stop_anchor 字段（非法值归一化回退）；
   validate_decision 加近锚一致性硬校验（突破类 + near + 突破K极值 ±0.5%，
   数据不足放行仅 warning）；fixed dict 落库 near 仅突破类有效
4. 落库链：models/scan.py AIAnalysis 加 stop_anchor 列 + database.py 迁移；
   ai_tasks upsert / trade_engine `_ai_snapshot` / actual_review 归因事实行透传
5. 测试：test_near_stop_anchor.py（13 用例：near 正反、空单对称、structure 不校验、
   数据不足放行、回踩类回退、非法值回退、Agent 推导正反）+ test_ai_agent_anchors.py
   （极值锚解析）+ test_signal_gate_block.py（门槛块注入面）
6. 文档：docs/11 §4.1a 补行；本方案状态改"已实施"

173 后端测试全过。**无**新表/新任务/交易所接口改动。

## 5. 验证与回滚

- **验证口径**（依赖 `stop_anchor` 分组，而非仅 signal_type）：上线 2-3 周后对比：
  ① 突破类总产量与前 2 周基线对比（政策叠加效应监控）；
  ② 突破类 skip → suggest 转化量（近锚应拯救一批原 skip 单）；
  ③ `structure` vs `near` 两批突破单的胜率 / EV / MAE 分布；
  ④ 近锚单被扫后"扫后趋势继续"比例（归因事实）；
  ⑤ `structure` 占比与 near 硬校验拦截量（防 AI 偏近锚偷懒）
- **回滚**：提示词删行 + risk_guard 校验删行即停用近锚（AI 不再输出 near）；
  `stop_anchor` 列保留无害

## 6. 结论

方案可行且成本低：移动止损基建（3 根极值 trailing、改单防抖）全部现成，需要做的
只有突破类提示词的"RR 不达标 → 近锚"降级链、`stop_anchor` 标注链路，以及一处
near 一致性硬校验。触发条件与盈亏比铁律直接挂钩，结构锚达标的突破单一律不动——
近锚只救"万事俱备、只差 RR 的单"。防胡乱开单靠三道附加线（量比 ≥1、RR ≤4、
0.3×ATR 最小宽度）+ near 硬校验 + 政策冻结期，把近锚窗口压到"结构合理窄止损"
场景。核心风险（近锚胜率下降）是突破打法的固有属性而非方案缺陷，且有完整复盘
闭环（按锚类型分组）兜底验证。建议实施。
