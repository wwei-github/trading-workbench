# docs/19 - 均线策略融合方案（EMA 21/55/144 趋势跟踪 × 现有系统）

> **实施状态（2026-10-10 融合拍板）**：不走插件影子路线——4H EMA144 闸门（三重否决）+ 1H 三线发散结构并入原生触发层，新触发类型 `trigger_trend_pullback`（T3 确认信号两道门全过时升级标注，任一门不过回落普通回踩确认，升级不拦截）。判定函数 `strategy/ema_gate.py`，链路见 docs/02 §5.6；影子层（docs/20/21）整体退役。P2 出场变体保留在回测引擎（`backtest_engine.py` 的 tp_qty_override/sig_exit）。

> 来源：外部 EMA 21/55/144 趋势跟踪系统设计稿（4H 闸门 → 1H 结构 → 震荡评分卡 → 回踩/金叉信号 → 纯跟踪出场）。
> 本文不照搬，逐模块对照现有系统，只吸收增量价值，全部按「先观测、后约束」的影子模式方法论落地。

## 一、外部策略一句话拆解

用 **4H EMA144 当趋势闸门**（价格位置 + 斜率 + 走平/缠绕/ADX 三重否决），**1H 三线排列 + ATR 归一发散度**确认结构，**8 项震荡评分卡**（≥3 分拒入场）过滤震荡市，**回踩优先、金叉补充**两类入场，止损贴均线（±0.5×ATR），出场**不设固定止盈**——保本（1×ATR 武装）+ ATR 跟进 + 信号出场（破 EMA55 / 死叉）。

### 2.3 冲突域（不拍板，用实验说话）

**出场哲学冲突**：外部纯跟踪（不设固定止盈，让利润奔跑）vs 我们 TP1/TP2 分批（60/20/80，锁定落袋）。

这是流派之争，无先验正确答案：

- 纯跟踪在强趋势行情盈亏比上限高，但在加密 7×24 高波动市场，浮盈回吐严重（我们 docs/15 的早期保护路线正是针对这个痛点）；
- 分批落袋胜率高、回撤平滑，但砍掉了大盈利尾部。

**处置**：不改现有出场。利用 `backtest_engine.replay_exit` 的 overrides 机制跑**配对对照实验**（同一批信号，两种出场），用我们自己的历史数据回答。见 §四 P2。

### 2.4 已有但需核实用法

- **ADX**：`analyze_adx` 已实现且进 AI 快照。核实其是否已进 votes/约束；若仅作 AI 输入，则纳入评分卡素材（1h ADX<18 扣分）。
- **布林带宽**：`analyze_bollinger` 已实现。BBW 分位（收口检测）为评分卡素材，回看窗口需 ≥120 根（外部默认分位窗口未指明，我们自己定）。
- **成交量**：breakout 过滤器已有 `vol_ratio`；回踩「缩量确认」可直接复用同一口径。

## 三、融合设计（四层递进，逐层解锁）

```text
L1 观测层 ──→ L2 闸门层 ──→ L3 实验层 ──→ L4 出场增强层
（不动行为）    （约束行为）    （回测对照）    （视实验结果）
```

### 3.1 L1 观测层（P0：只记录，不改任何开仓/出场行为）

新增 5 个量化字段，全部进 `_votes_snapshot` 与 AIAnalysis 快照，复盘表新增「震荡分」维度（复用 docs/17 的 htf_phase 分桶模式）：

| 字段                  | 计算                                  | 周期  |
| --------------------- | ------------------------------------- | ----- |
| `ema144_slope_pct`    | abs(EMA144[-1] − EMA144[-20]) / close | 4h    |
| `wrap_count_144`      | 近 10 根收盘价穿越 EMA144 的次数      | 4h    |
| `divergence_fast_mid` | abs(EMA21 − EMA55) / ATR14            | 1h    |
| `cross_ema21_count`   | 近 20 根收盘价穿越 EMA21 的次数       | 1h    |
| `range_score`         | 震荡评分卡合计（见 3.2，先只算不拦）  | 1h+4h |

**验收**：扫描正常出结果，新字段落库可见；复盘报告可按 range_score 分桶统计胜率/期望 R。

### 3.2 L2 闸门层（P1：观测数据出来后，预注册阈值再启用）

**震荡评分卡（扣分制）**，候选 8 项：

| 项  | 条件                                                    | 分值 |
| --- | ------------------------------------------------------- | ---- |
| 1   | 4h `ema144_slope_pct` < 阈值（观测期定，外部默认 0.5%） | 1    |
| 2   | 4h `wrap_count_144` ≥ 3                                 | 1    |
| 3   | 1h 三线不排列（多空都不满足）                           | 1    |
| 4   | 1h `divergence_fast_mid` < 0.5                          | 1    |
| 5   | 1h ADX < 18                                             | 1    |
| 6   | 1h BBW 处于近 120 根低分位（< 30%）                     | 1    |
| 7   | 1h `cross_ema21_count` ≥ 4                              | 1    |
| 8   | 1h 近 20 根量能变异系数 < 0.3（成交量低迷）             | 1    |

**启用条件（预注册，缺一不可）**：

1. L1 观测期 ≥ 4 周且样本 ≥ 200 条 AI 建议单；
2. 用真实复盘数据重估每项阈值（**不采用外部默认值**——分位数按我们自己的样本定）；
3. 验证区分度：range_score ≥ N 组的期望 R 显著低于 < N 组（配对 t 或 bootstrap）；
4. 起步只做**软闸门**：≥ 阈值分的候选不进 AI 分析（省 token + 算力），并在扫描结果标注「震荡过滤」，前端可展开被滤原因；
5. 软闸门稳定 2 周无申诉性误杀，才考虑把其中区分度最高的 2-3 项升为 enforce 硬约束（进 `enforce_htf_constraint` 或新 enforce 函数）。

**反过拟合条款**：任何一项升硬约束前，必须在 docs/16 的改判记录里预注册其「降级条件」（类比 REC70），例如「升级后 4 周内被滤候选的机会成本（被滤但市场走出的 R）> 保留收益，则回退软闸门」。

### 3.3 回踩信号质量增强（P1 同期，独立于评分卡）

对现有金K触点 trigger 追加三道**企稳确认**（外部策略的可取细节，纯增益不改变触发面）：

1. **企稳 K 线形态**：触点当根需满足看涨企稳形态之一（多头；空头镜像）。引用 docs/11 金K形态库的看涨形态枚举（锤子线/长下影阳线/看涨吞没等按库内口径），库内缺的形态先补库再引用，不另写一套；
2. **量能语义**：回踩当根不放巨量（vol > 1.5×MA20 视为放量下跌而非健康回踩，多头方向不确认）；
3. **MACD 零轴状态确认**（源自策略 A）：入场周期 DIF/DEA 在零轴上方（多头），或「回踩零轴不破」——DIF 曾下探零轴但未深穿即回升。这是独立于均线排列的动量维度证据，`analyze_macd` 已有 DIF/DEA 全序列，计算零成本。作为触发前提还是质量分调整项，由 L1 观测数据定。

新增发散度作为**金K质量分调整项**（不拦截）：`divergence_fast_mid` < 0.5 时质量分 −2，进 votes 快照。是否升级为触点前置条件，由 L2 同批数据决定。

### 3.4 L3 实验层（P1.5：出场哲学对照，纯回测，不碰生产）

扩展 `replay_exit` overrides（OVERRIDE_KEYS 白名单内新增，API 层同步）：

| 变体        | overrides                                                                                                                                                                                                           | 回答的问题                                  |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| V1 纯跟踪   | 新键 `tp_mode="trail_only"`：TP1/TP2 不挂档，全部仓位进「1×ATR 武装保本 + ATR/摆动跟进」                                                                                                                            | 分批 vs 纯跟踪，谁净期望 R 高、回撤谁深     |
| V2 信号出场 | 新键 `sig_exit=True` + `sig_exit_rule` 菜单逐一测试：`ema55_break`（收盘破 EMA55）/ `macd_death_cross`（零轴上方 DIF 死叉 DEA）/ `ma20_break_2bar`（连续 2 根收盘破 MA20 未收回——策略 A「无法快速收回」的量化口径） | 三种「结构/动量失效出场」谁最能减少浮盈回吐 |
| V3 组合     | tp_mode=trail_only + 最优 sig_exit                                                                                                                                                                                  | 完整跟踪出场语义 vs 我们的                  |
| V4 止损变体 | 新键 `stop_mode="swing_low"`：回调摆动低点 − 0.5×ATR（策略 A「回调低点下方」）vs 基线均线锚定                                                                                                                       | 结构止损 vs 均线止损，打损率与盈亏比权衡    |

**实验协议**：

- 信号源：`build_signals_from_history`（真实 AI 建议单）为主，`build_signals_by_scan_replay` 补样本量；
- 配对 delta（同信号不同 overrides），逐变体输出期望 R / 胜率 / 最大回撤 / 平均持仓时长；
- 样本窗口 ≥ 6 个月，覆盖至少一次趋势转震荡切换；
- 结论落 docs/16 改判记录：**只有当纯跟踪组期望 R 显著更高且回撤可接受时，才把 TP 分批比例默认值向「少止盈」方向调**（我们刚做了分批配置化，调整只是改配置，无需改代码——这正是配置化的红利）。

### 3.5 L4 出场增强层（P2：视 L3 结果决定）

若 V2 实验支持，生产出场引擎加一条**可选腿**（默认关，配置化，沿用本次 TP 比例配置化的模式）：

- `sig_exit_enabled: bool = False`：TP1 成交后，收盘破 EMA55（1h）→ 剩余仓市价清出（先于跟进腿判定，保守序与现有一致）；
- 该腿只收紧不放松，与摆动/ATR 腿取「先触发者」。

## 六、明确不做的事

1. **不推翻现有架构**：外部「纯规则信号系统」不替代「规则筛候选 + AI 三价 + veto」——AI 层是我们相对外部方案的核心优势（结构位识别、假突破识别），外部精华只进规则层。
2. **不引入外部默认参数**。
3. **不因外部方案取消 TP 分批**——出场哲学之争交给配对实验（§3.4）。
4. **不加频率限制**（最小间隔/日上限）——现有在跑上限 + 候选去重已够，等出现真实过度交易证据再说。

## 七、一句话总结

外部方案与我们系统约七成重叠，且重叠部分我们普遍做得更细；真正值得拿的是**震荡检测的组织方式**（扣分制评分卡 + 缠绕/穿越计数/发散度三个我们缺失的量化证据）和**出场哲学的对照组**。落地纪律只有一条：先观测、后约束、参数自己估、结论实验给。

## 八、可插拔策略架构（最终形态）

> 设计目标：EMA 策略与现有「金K + AI」逻辑**彼此隔离、互不可见**，共用底座能力；未来新策略以插件形式接入，不动存量代码。

### 8.1 核心原则

1. **策略 = 信号生产者，系统 = 信号消费者**。策略只回答「何时开、开哪个方向、三价、理由」；风控、仓位、执行、出场骨架、复盘全部由系统统一承载。
2. **存量管线降级为一个内置插件**：现有「金K候选 → AI 三价」重构为 `golden_k_ai` 策略；EMA 策略为第二个插件 `ema_trend`。重构铁律：**golden_k_ai 的输出与现状逐字段一致**，基线等价性测试锁死，存量行为零变化。
3. **协议从两个具体策略归纳**（rule of two）：不做通用「策略市场」式过度抽象，接口只长出两个策略真正共需的字段。

### 8.2 StrategyPlugin 协议

```python
@dataclass
class StrategySignal:
    # 与现有 AIAnalysis 三价对齐——trade_engine 消费的唯一形态
    strategy_id: str            # "golden_k_ai" / "ema_trend"
    symbol: str
    direction: str              # long / short
    entry: float
    stop: float
    tp1: float
    tp2: float                  # 0 = 无
    reason: str                 # 入场理由（触发器文案 / 信号描述）
    confidence: float           # 策略自评 0~1（AI 置信度 / 规则强度）
    raw: dict                   # 策略私有快照（votes / 震荡分 / 结构位…，落库归因用）

class StrategyPlugin(Protocol):
    id: str
    display_name: str
    def scan_candidates(self, universe: list[str]) -> list[Candidate]: ...
        # 筛币 + 预筛（策略私有过滤：评分卡 / 波动率闸门…）
    def build_signal(self, candidate: Candidate) -> Optional[StrategySignal]: ...
        # golden_k_ai：此步调 AI 分析；ema_trend：纯规则产出
    def exit_spec(self) -> dict: ...
        # 出场语义声明（见 8.4），给 trade_engine 与 backtest_engine 共用
```

关键解耦点：**trade_engine / 风控 / 复盘只认 `StrategySignal` 与 `strategy_id`，策略之间完全不可见**。AI 分析是 golden_k_ai 的内部实现细节，对系统其余部分透明。

### 8.3 调度、预算与冲突（隔离规则）

| 机制                         | 设计                                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 注册与开关                   | system_config 新增 `strategy_registry` JSON：`[{id, enabled, max_positions, risk_weight}]`；扫描任务遍历 enabled 策略，各自独立产候选/信号 |
| 全局风控（共享，不放宽）     | 周/月熔断、保证金、账户级在跑上限、同向上限——**账户维度铁律对所有策略生效**，策略级预算是全局预算的**子集划分**，不是额外额度              |
| 策略级预算（隔离）           | 每策略独立 `max_positions`（ema_trend 起步 1-2 个）；`risk_weight` 乘进单笔风险额                                                          |
| 同标的冲突（第一版最简规则） | 同一 symbol 全系统只允许一个在跑仓位（跨策略互斥）：后到信号拒绝，拒绝原因记 `strategy_conflict` 落库可查。双向持仓/对锁不在第一版范围     |
| 黑名单/新币冷却              | 共享（账户级禁入清单对所有策略生效）                                                                                                       |

### 8.4 出场语义跟策略走（ExitSpec）

出场引擎骨架（同根 K 线保守序铁律：逆侧整根优先 / 顺侧近者先成 / 滞后一根生效）全局唯一，**参数按持仓的 `strategy_id` 解析**：

| 策略                    | ExitSpec                                                                                      |
| ----------------------- | --------------------------------------------------------------------------------------------- |
| golden_k_ai（现状不变） | `{tp_ladder: 配置化 60/20/80, be: TP1 成交武装, trail: swing3+ATR_k}`                         |
| ema_trend               | `{tp_ladder: 无（或按 §3.4 实验结论）, be: 1×ATR 武装, trail: ATR×2, sig_exit: 收盘破 EMA55}` |

- `backtest_engine.replay_exit` 增加 `exit_spec` override 键——策略出场语义直接可回测，§3.4 的对照实验天然纳入；
- 现有 TP 分批比例等配置归属 golden_k_ai 策略名下，不是全局配置。

| S0 重构动摇存量链路                      | 基线等价性测试（终局逐例）+ 快照逐字段对比双保险；重构 PR 不夹带任何语义改动           |

| 出场语义分流破坏保守序铁律               | ExitSpec 只许改参数不许改骨架；保守序判定在引擎骨架内硬编码，策略不可触碰              |

### 8.9 多策略并发 vs 单策略：全面设计

> 回答三个问题：能否多策略同时跑？信号/仓位重叠怎么办？止盈止损与配置参数不同怎么办？

#### 8.9.1 决策框架：架构支持并发，运营分阶段解锁

**不存在「单策略版」和「多策略版」两套代码**。registry 配置即并发度：enabled 列表长度 = 并发数，只启用一个就是单策略模式。分阶段解锁的是**开单权限**，不是架构能力：

| 阶段    | 开单并发             | 说明                                     |
| ------- | -------------------- | ---------------------------------------- |
| S0      | 1（仅 golden_k_ai）  | 归因地基，行为零变化                     |
| S1 影子 | 1 开单 + N 产信号    | ema_trend 影子跑，**天然收集重叠率数据** |
| S2      | ≤2（影子期数据放行） | ema_trend 独立预算 1-2 仓                |
| S3+     | 数据说话             | 相关性达标再放开更多策略                 |

**并发准入的量化铁律（预注册）**：影子期统计两策略的**信号重叠率**（同标的同方向同周窗口内都出信号的频率）与**盈亏相关性**（逐周 R 序列相关系数）。重叠率 >50% 或相关系数 >0.7 → 判定为「同一策略的两种参数化」，并发 = 放大回撤而无分散收益，**只跑其一**（选期望 R 高者）。两个策略若连回撤都同涨同跌，分开跑只是自欺。

#### 8.9.2 重叠三层，逐层给规则

| 层       | 场景                         | 第一版规则                                                                                                       | 进阶（预注册后启用）                                                                      |
| -------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 信号重叠 | 同标的同方向，两策略都出信号 | **跨策略同标的互斥**：同 symbol 全系统仅一仓，后到信号拒绝并落库（reason=strategy_conflict）。先到先得，简单可靠 | 高置信度可置换：新信号 confidence 显著高于在跑仓（差值阈值预注册）且在跑仓浮亏 → 平旧开新 |
| 方向重叠 | 同标的多空对锁               | 禁止（单仓模型天然排除；对锁是净持仓为零的伪对冲，费用双份）                                                     | 不做                                                                                      |
| 风险重叠 | 不同标的同时回撤             | 全局风控兜底：周/月熔断、账户在跑上限、同向上限**对所有策略生效**；策略级 max_positions 只是全局预算的子集划分   | 组合层面回撤归因（分策略 R 序列进复盘）                                                   |

**重叠率是资产不是麻烦**：S1 影子期把重叠率当核心观测指标落库——它回答「这两个策略是否值得同时存在」。数据判断，不拍脑袋。

#### 8.9.3 止盈止损不同 → ExitSpec per strategy（§8.4 落地细节）

出场引擎是**每根 K 线轮询所有在跑仓位的 per-position 状态机**——每个仓位按自己的 `strategy_id` 解析 ExitSpec，天然互不干扰，改造点仅在「参数解析处」：

```text
Trade.strategy_id ──→ ExitSpec(strategy) ──→ 出场骨架（全局唯一）
                                            ├─ tp_ladder: golden_k=60/20/80 可配 | ema_trend=无/实验结论
                                            ├─ be_arm:    golden_k=TP1 成交武装 | ema_trend=1×ATR 武装
                                            ├─ trail:     golden_k=swing3+ATR_k  | ema_trend=ATR×2
                                            └─ sig_exit:  golden_k=无           | ema_trend=破EMA55 等
```

关键约束：**骨架不可变**（同根 K 线保守序、滞后一根生效、只收紧不放松），策略只能声明参数。golden_k 的全部既有出场行为经基线等价性测试锁死。

#### 8.9.4 配置参数不同 → 策略配置命名空间

配置从「全局平面」重构为「**全局层 + 策略层**」两级：

| 层                     | 内容                                                                                            | 变更方式                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 全局层（账户级，共享） | 风险额基数、周/月熔断阈值、在跑/同向上限、黑名单、TP 分批比例（刚做的配置化）                   | 现有 system_config 页面，不动               |
| 策略层（私有，隔离）   | 各策略自有参数：ema_trend 的评分卡阈值/发散度/ADX 下限；golden_k 的触发器开关/触点引用/新币冷却 | `strategy_registry` JSON 内嵌 `config` 字段 |

```json
"strategy_registry": [
  {"id": "golden_k_ai", "enabled": true, "max_positions": 3, "risk_weight": 1.0, "config": {}},
  {"id": "ema_trend", "enabled": true, "max_positions": 1, "risk_weight": 0.5,
   "config": {"adx_min": 20, "divergence_min": 0.5, "range_score_max": 2}}
]
```

- 策略私有参数**只进自己 namespace**，golden_k 感知不到 ema_trend 的参数，反之亦然（代码层：每插件一个 config dataclass，registry 反序列化注入）；
- `risk_weight` 乘进单笔风险额：新策略上线先半风险运行（0.5），表现达标升 1.0——这是新策略的**风险驯化通道**；
- 现有全局配置（TP 比例等）S0 阶段名义上归入 golden_k_ai 名下，实际存储位置不变（避免迁移风险），文档口径归属即可。

#### 8.9.5 明确不做

1. **不做策略间信号仲裁市场**（如「两策略都出多信号则加仓」）——第一版同标的互斥已够，叠加规则等数据；
2. **不做策略对冲/对锁**——伪对冲；
3. **不做每策略独立账户**——账户扇出已存在（trader 多账号），策略维度再分账户会爆炸；单账户内子预算即可归因；
4. **不做动态权重分配**（按近期表现自动调 risk_weight）——过拟合温床，人工季度评估改。

### 9.3 结论

策略 A 与外部 EMA 方案是同一流派（趋势 + 回调）的两个表述，重叠条件不重复吸收；**真实增量只有 4 个**：MACD 零轴状态确认（规则层）、KDJ/Stochastic 指标（观测候选）、摆动低点止损变体（V4）、信号出场菜单扩充（MACD 零上死叉 + MA20 双根破位）。全部以「观测/变体」身份进既有 L1/L3 流程，不改 §八 架构，不改阶段节奏。
